## 一、知识点

### 1. 前端技术选型回顾

| 需求 | 选型 | 理由 |
|------|------|------|
| 脚手架 | Vite + React 18 + TS | 秒级热更新、类型安全 |
| 样式 | Tailwind CSS | 原子化 CSS，团队协作不扯皮命名 |
| 组件 | shadcn/ui（Radix） | 代码进仓库可定制，非黑盒组件库 |
| 路由 | react-router-dom v6 | 嵌套路由 + 布局路由 |
| 状态 | Zustand | 聊天消息等全局状态，API 极简 |
| 请求 | Axios | 拦截器统一错误处理 |

### 2. 前后端联调的两个关键配置

- **API 基址可配置**：`import.meta.env.VITE_API_BASE_URL`，开发指 `http://localhost:8000`，生产容器内走 Nginx 反代 `/`；
- **FormData 请求头陷阱**：手动设 `Content-Type: multipart/form-data` 会丢失 boundary，必须在拦截器里**删除**该头让浏览器自动生成。

### 步骤 4：配置路径别名与开发端口

`vite.config.ts`：

```ts
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react-swc";
import path from "path";

export default defineConfig(({ mode }) => ({
  server: {
    port: 8080,
  },
  plugins: [react()],
  resolve: {
    alias: {
      "@": path.resolve(__dirname, "./src"),
    },
  },
}));
```

`tsconfig.app.json` 的 `compilerOptions` 中同步：

```json
"baseUrl": ".",
"paths": { "@/*": ["./src/*"] }
```

> 之后所有导入写 `@/components/...`，告别 `../../../`。

### 步骤 6：实现 API 客户端 `src/api/client.ts`

```ts
import axios, { AxiosError } from "axios";

const API_BASE_URL =
  import.meta.env.VITE_API_BASE_URL?.trim() || "http://localhost:8000";

export const apiClient = axios.create({
  baseURL: API_BASE_URL,
  timeout: 60000, // LLM responses can take long
});

apiClient.interceptors.request.use(
  (config) => {
    if (config.data instanceof FormData) {
      delete config.headers["Content-Type"]; // let browser set multipart boundary
    }
    return config;
  },
  (error) => Promise.reject(error)
);

apiClient.interceptors.response.use(
  (response) => response,
  (error: AxiosError) => {
    const rawDetail = (error.response?.data as any)?.detail;
    let message: string;
    if (Array.isArray(rawDetail) && rawDetail.length > 0) {
      message = rawDetail.map((e: any) => e.msg || JSON.stringify(e)).join("; ");
    } else if (typeof rawDetail === "string") {
      message = rawDetail;
    } else {
      message = error.message || "Unknown API error";
    }
    const normalizedError = { status: error.response?.status || 500, message };
    return Promise.reject(normalizedError);
  }
);
```

**设计要点**：

1. **60s 超时**：多 Agent + 视觉模型串行场景可能超过常规 10s；
2. **错误归一化**：FastAPI 的 `detail` 可能是字符串或数组，统一成 `{status, message}`，页面层无需关心协议细节。

### 步骤 7：路由骨架 `src/App.tsx`

```tsx
import { QueryClient, QueryClientProvider } from "@tanstack/react-query";
import { BrowserRouter, Routes, Route } from "react-router-dom";

import { Toaster } from "sonner";

import Layout from "./pages/Layout";
import Chat from "./pages/Chat";
import ImageDiagnosis from "./pages/ImageDiagnosis";
import History from "./pages/History";
import NotFound from "./pages/NotFound";

const queryClient = new QueryClient();

const App = () => (
  <QueryClientProvider client={queryClient}>
    <Toaster position="top-center" />
    <BrowserRouter>
      <Routes>
        <Route path="/" element={<Layout />}>
          <Route index element={<Chat />} />
          <Route path="image" element={<ImageDiagnosis />} />
          <Route path="history" element={<History />} />
        </Route>
        <Route path="*" element={<NotFound />} />
      </Routes>
    </BrowserRouter>
  </QueryClientProvider>
);

export default App;
```

配套创建（本次用占位实现，实训 11 充实）：

- `src/pages/Layout.tsx`：顶部导航 + `<Outlet />`；
- `src/components/Navbar.tsx`：三个导航项（聊天 / 图片诊断 / 历史），用 `NavLink` 高亮当前页；
- `src/pages/Chat.tsx`、`ImageDiagnosis.tsx`、`History.tsx`：先各返回一个标题占位；
- `src/pages/NotFound.tsx`：404 页面。

## 四、常见问题排查

| 现象 | 原因与解决 |
|------|-----------|
| `@/` 导入报红 | `tsconfig` 的 `paths` 与 vite `alias` 要**同时**配置；重启 TS Server |
| 跨域失败 | 后端未启动或 CORS 未开；确认后端 `allow_origins=["*"]` |
| FormData 请求 422 | 检查是否漏了拦截器里 `delete Content-Type`（boundary 丢失） |
| Tailwind 样式不生效 | `content` 通配路径没覆盖到你的文件；确认 `@tailwind` 三行在 index.css |
