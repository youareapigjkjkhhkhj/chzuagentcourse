## 一、知识点

### 1. 测试策略：测什么、怎么测

| 层 | 测试方式 | 外部依赖 |
|----|----------|----------|
| 纯逻辑（护栏、Token、路由规则） | 单元测试，直接调函数 | 无 |
| HTTP 接口 | `TestClient`（进程内，不起真服务） | mock 或降级 |
| 真实模型调用 | **不进自动化测试**（慢、费钱、不稳定） | 手工验收 |

> **关键技巧**：`conftest.py` 注入假 Key + 模块级降级设计（所有 LLM 失败都返回文案），使测试**零外部依赖**即可跑通。

### 2. Docker 交付架构

```
docker-compose
├── redis      redis:7-alpine            6379
├── backend    python:3.11-slim          8000   (PYTHONPATH=/app)
└── frontend   node:20 构建 → nginx 托管   3000→80
                  └ nginx 反代 /ask /weather /health /metrics /docs → backend:8000
```

前端构建时 `VITE_API_BASE_URL=/`（同源），生产环境由 Nginx 把 API 路径反代给后端——**浏览器零跨域**。

## 二、操作步骤：自动化测试

### 步骤 1：测试基础设施

```ini
[pytest]
testpaths = backend/tests
python_files = test_*.py
addopts = -v
```

`backend/conftest.py`（pytest 自动加载）：

```python
"""Pytest configuration. Run before any tests to ensure resume-worthy state."""
import os
import sys
from pathlib import Path

# Add project root so "backend" package is importable
root = Path(__file__).resolve().parent.parent
if str(root) not in sys.path:
    sys.path.insert(0, str(root))

# Set minimal env so app can import without real keys
os.environ.setdefault("GROQ_API_KEY", "test-key-for-unit-tests")
```

    assert "llama-3.2-vision-preview" not in vision


def test_metrics_usage(client):

## 三、操作步骤：容器化部署

### 步骤 5：后端镜像 `Dockerfile`（项目根）

```dockerfile
FROM python:3.11-slim

WORKDIR /app

# Install system deps for sentence-transformers
RUN apt-get update && apt-get install -y --no-install-recommends \
    build-essential \
    cmake \
    && rm -rf /var/lib/apt/lists/*

COPY backend/requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY backend/ ./backend/
ENV PYTHONPATH=/app

EXPOSE 8000

CMD ["sh", "-c", "uvicorn backend.main:app --host 0.0.0.0 --port ${PORT:-8000}"]
```

> 构建上下文是项目根（`COPY backend/...`），与 `uvicorn backend.main:app` 的包路径保持一致。

### 步骤 6：前端镜像 `frontend/Dockerfile`（多阶段构建）

```dockerfile
FROM node:20-alpine AS builder

WORKDIR /app

COPY package*.json ./
RUN npm ci

COPY . .
# Use same origin so nginx can proxy /ask, /weather, /health to backend
ARG VITE_API_BASE_URL=/
ENV VITE_API_BASE_URL=$VITE_API_BASE_URL
RUN npm run build

FROM nginx:alpine
COPY --from=builder /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

`frontend/nginx.conf`：

```nginx
server {
    listen 80;
    root /usr/share/nginx/html;
    index index.html;
    location / {
        try_files $uri $uri/ /index.html;   # SPA 路由回退
    }
    location ~ ^/(ask|weather|health|metrics|docs|openapi.json) {
        proxy_pass http://backend:8000;     # compose 服务名即主机名
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

### 步骤 7：编排 `docker-compose.yml`（项目根）

```yaml
services:
  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"
    volumes:
      - redis_data:/data
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 5s
      timeout: 3s
      retries: 3

  backend:
    build:
      context: .
      dockerfile: Dockerfile
    ports:
      - "8000:8000"
    environment:
      - GROQ_API_KEY=${GROQ_API_KEY}
      - OPENWEATHER_API_KEY=${OPENWEATHER_API_KEY}
      - LANGCHAIN_TRACING_V2=${LANGCHAIN_TRACING_V2:-false}
      - LANGCHAIN_API_KEY=${LANGCHAIN_API_KEY}
      - LANGSMITH_API_KEY=${LANGSMITH_API_KEY}
      - PINECONE_API_KEY=${PINECONE_API_KEY}
      - PINECONE_INDEX_NAME=${PINECONE_INDEX_NAME:-agrigpt-subsidies}
      - REDIS_URL=redis://redis:6379/0
    volumes:
      - ./backend/data:/app/backend/data
    depends_on:
      redis:
        condition: service_healthy

  frontend:
    build:
      context: ./frontend
      dockerfile: Dockerfile
      args:
        VITE_API_BASE_URL: /
    ports:
      - "3000:80"
    depends_on:
      - backend

volumes:
  redis_data:
```

**设计要点**：

1. `REDIS_URL` 从 `localhost` 变成 **`redis://redis:6379/0`**——容器网络内用服务名通信；
2. `backend/data` 挂载卷：日志与向量库持久化，不随容器销毁；
3. `depends_on + healthcheck`：Redis 真正就绪后才启动后端；
4. 密钥从宿主 `.env` 注入（compose 自动读取同级 `.env`），**镜像里不含任何密钥**。

### 步骤 8：一键启动与部署验收

在项目根准备 `.env`（至少 `GROQ_API_KEY`），然后：

```powershell
docker-compose up --build
```

| # | 验收项 | 预期 |
|---|--------|------|
| 1 | 三容器状态 | `docker ps` 全部 healthy/running |
| 2 | `http://localhost:8000/health` | 依赖显示 `redis_memory: connected` |
| 3 | `http://localhost:3000` | 前端可访问（Nginx） |
| 4 | 前端发起提问 | 经 Nginx 反代成功（无跨域报错） |
| 5 | `docker-compose restart backend` 后再提问 | 同会话记忆仍在（Redis 持久化） |
| 6 | `docker-compose down; docker-compose up -d` | 数据卷保留，历史日志仍在 |

## 四、（选做）云部署

### 方式 A：Render（Native Python）

仓库根目录 `render.yaml`：

```yaml
services:
  - type: web
    name: agrigpt-api
    runtime: python
    plan: free
    buildCommand: pip install -r backend/requirements.txt
    startCommand: PYTHONPATH=. uvicorn backend.main:app --host 0.0.0.0 --port $PORT
    envVars:
      - key: GROQ_API_KEY
        sync: false
      - key: PYTHONUNBUFFERED
        value: "1"
```

步骤：推送仓库 → Render New → Blueprint → 在面板填入 `GROQ_API_KEY`。注意调整 `buildCommand`/`startCommand` 中的路径以匹配你的仓库结构。

### 方式 B：任意支持 Docker 的平台

直接用根 `Dockerfile` 构建，注入 `PORT=8000` 与 `GROQ_API_KEY` 即可。
