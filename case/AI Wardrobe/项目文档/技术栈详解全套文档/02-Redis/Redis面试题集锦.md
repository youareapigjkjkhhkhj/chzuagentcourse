# Redis 面试题集锦（附参考答案）

---

## 🥉 基础题

### Q1. Redis 为什么这么快？

**参考答案：**
1. **纯内存操作**：内存读写比磁盘快 5 个数量级。
2. **单线程执行命令**：无锁竞争、无线程上下文切换；Redis 瓶颈在内存和带宽而非 CPU。
3. **IO 多路复用（epoll）**：单线程监听上万连接，内核事件通知，不轮询。
4. 加分项：6.0 后网络 IO 多线程化，但命令执行仍单线程；高效的数据结构（SDS、跳表、listpack）。

---

### Q2. Redis 常见数据类型及使用场景？

**参考答案：**

| 类型 | 场景 |
|------|------|
| String | 缓存对象、计数器（INCR）、分布式锁（SET NX EX） |
| Hash | 存对象（购物车：userId → {商品Id: 数量}） |
| List | 简单消息队列（LPUSH+BRPOP）、最新动态 |
| Set | 去重、共同好友（SINTER）、抽奖（SRANDMEMBER） |
| ZSet | 排行榜（ZADD/ZREVRANGE）、延迟队列（score=时间戳）、滑动窗口限流 |

加分项：Bitmap（签到统计）、HyperLogLog（UV 统计，误差 0.81%）、GEO（附近的人）、Stream（消息队列）。

---

### Q3. Redis 的持久化方式？怎么选？

**参考答案：**
- **RDB**：定时全量快照，文件紧凑恢复快，但可能丢失最近几分钟数据，bgsave 靠 fork + COW 写时复制。
- **AOF**：追加写命令日志，`appendfsync everysec` 最多丢 1 秒；AOF 重写压缩日志体积。
- **生产推荐**：RDB + AOF 混合持久化（4.0+），AOF 重写时前半段为 RDB 二进制 + 后半段增量命令，恢复速度和数据完整性兼得。恢复时优先加载 AOF。

---

### Q4. Redis key 过期了为什么不马上删？过期策略是什么？

**参考答案：**
- **惰性删除**：访问时检查，过期才删——不访问就占着内存。
- **定期删除**：每 100ms 随机抽查一批设了过期时间的 key，删过期的——占 CPU。
- 两者结合平衡 CPU 与内存。所以可能出现"key 已过期但还能读到内存占用"的情况。

---

### Q5. 内存满了怎么办？淘汰策略有哪些？

**参考答案：**
达到 `maxmemory` 后按策略淘汰，常用：
- `allkeys-lru`：所有 key 中淘汰最久未使用（通用缓存首选）；
- `volatile-lru`：只在设了 TTL 的 key 中淘汰；
- `volatile-ttl`：淘汰剩余寿命最短的；
- `noeviction`（默认）：不淘汰，写入报错。
注意 Redis 是**近似 LRU**——随机采样 N 个 key 淘汰最久未用的，避免维护全量链表的开销。

## 🥈 进阶题

### Q6. 缓存穿透、击穿、雪崩的区别和解决方案？

**参考答案：**

| 问题 | 定义 | 解决方案 |
|------|------|---------|
| **穿透** | 查询**根本不存在**的数据，每次都打到 DB | ① 缓存空值（短 TTL）；② **布隆过滤器**前置拦截；③ 接口层参数校验 |
| **击穿** | **单个热点 key** 过期瞬间，高并发同时打到 DB | ① 互斥锁：只放一个线程去 DB 重建，其他等待；② 逻辑过期：不设置物理 TTL，异步线程刷新 |
| **雪崩** | **大量 key 同时**过期 | ① 过期时间加随机抖动（如 24h±1h）；② 热点数据不过期；③ 多级缓存（Caffeine + Redis）；④ 熔断降级兜底 |

布隆过滤器原理：bit 数组 + 多个 hash 函数，"说没有一定没有，说有不一定有"，用来挡恶意 id。

### Q7. 如何保证缓存与数据库双写一致？

**参考答案：**
经典方案：**Cache Aside Pattern（旁路缓存）**
- 读：先读缓存， miss 则读 DB 并回填缓存。
- 写：**先更新 DB，再删除缓存**（不是更新缓存！更新缓存在并发下会产生脏数据，且更新成本高）。

为什么"先 DB 后删缓存"还会不一致？—— 极端时序：读线程查 DB 旧值正要回填时，写线程完成了"更新 DB + 删缓存"，随后读线程把旧值写进缓存 → 脏数据。缓解：**延迟双删**（写完后延迟几百 ms 再删一次缓存）或 **binlog 订阅**（Canal 监听 MySQL binlog 异步删缓存，最常用生产方案）。

强一致要求场景：加分布式锁或用消息队列串行化，但要权衡性能。

### Q8. Redis 分布式锁怎么实现？有哪些坑？

**参考答案：**
1. 基础：`SET key uuid NX EX 30`——一条命令原子完成"不存在才设置 + 过期时间"，value 存 UUID 标识持有者。
2. 删锁：Lua 脚本保证"判断是否自己的锁 + 删除"原子执行，防止误删。
3. 坑 1：业务超时锁过期 → **Redisson 看门狗**每 10s 自动续期到 30s。
4. 坑 2：主从切换丢锁（master 未同步就宕机）→ RedLock（多独立节点过半加锁），但业界有争议，实践中多用单实例 + 数据库唯一约束/乐观锁兜底。

---

### Q9. Redisson 看门狗机制？

**参考答案：**
`lock()` 不显式指定时间时，默认锁 30 秒；后台看门狗线程每 **10 秒（锁时间的 1/3）**检查一次：若锁仍被当前线程持有且业务未完，则重置过期时间为 30s，如此循环直到 unlock 或进程宕机（宕机则锁自然超时释放，不会死锁）。
底层锁结构是 Hash：field 存线程标识实现**可重入**，加锁/续期/解锁都是 Lua 脚本保证原子性。

### Q10. ZSet 底层为什么用跳表不用红黑树？

**参考答案：**
1. **实现简单**：跳表靠随机层高，红黑树旋转平衡极其复杂；
2. **范围查询高效**：跳表定位起点后顺序遍历即可，红黑树需中序遍历回溯；
3. **并发友好**：跳表插入只影响局部节点，红黑树调整可能波及整树。
另外 ZSet 是 skiplist + hashtable 双结构：跳表负责分数排序和范围查询 O(logN)，哈希表负责按 member 查分 O(1)。

## 🥇 架构题

### Q11. 主从复制的原理？全量同步和部分同步？

**参考答案：**
- **全量同步**（首次或偏移量丢失时）：master 执行 bgsave 生成 RDB → 发给 slave → slave 加载 RDB → master 把 RDB 期间缓冲的写命令补发给 slave。
- **增量同步**：正常情况 master 把写命令流实时发给 slave。
- **部分重同步**（2.8+ psync）：master 维护**复制积压缓冲区**（环形 buffer）+ 复制偏移量，slave 断线重连后带上自己的 offset，如果数据还在缓冲区里就只补发缺失部分，否则触发全量。
- 注意：主从是**异步复制**，master 宕机可能丢少量数据——这也是分布式锁丢锁的根源。

---

### Q12. 哨兵和 Cluster 集群的区别？Cluster 怎么分片？

**参考答案：**
- **哨兵**：不解决容量问题，只解决**自动故障转移**——监控主从、主观下线→客观下线（过半哨兵同意）、选举 leader 哨兵执行 failover、通知客户端新 master。
- **Cluster**：解决**数据分片与水平扩展**——16384 个槽位，`CRC16(key) mod 16384` 定位槽，槽分配给各节点；节点间 gossip 协议交换状态；支持在线扩缩容（槽迁移，MOVED/ASK 重定向）；每个分片可带从节点做高可用。
- 选型：数据量 < 10G 且 QPS 不高 → 哨兵够用；数据量大/写入高 → Cluster。

### Q13. Redis 大 Key、热 Key 问题怎么发现和解决？

**参考答案：**
**大 Key**（如 10MB 的 String、百万成员的 Hash）：
- 发现：`--bigkeys` 扫描、memory usage 命令、监控工具。
- 危害：网络阻塞、删除阻塞（DEL 是 O(N)，用 **UNLINK** 异步删）、主从同步慢、Cluster 数据倾斜。
- 解决：拆分（大 Hash 拆成多个小 Hash）、压缩、换数据结构。

**热 Key**（如明星八卦被百万 QPS 访问）：
- 发现：monitor 采样、proxy 层统计、hotkeys 参数。
- 解决：本地缓存（Caffeine 前置）、热 Key 拆分成多副本（key_1~key_N 随机读）、读写分离。

---

### Q14. Redis 6.0 多线程是怎么回事？为什么之前单线程？

**参考答案：**
- 之前单线程：因为瓶颈不在 CPU 而在内存/网络，单线程无锁反而高效，且避免并发 bug。
- 6.0 多线程：把**网络 IO 的读和写**（耗时的 socket read/write、协议解析）分给多个 IO 线程，**命令执行仍是主线程单线程**——所以不用担心并发安全，也没有锁。
- 效果：大流量下 QPS 提升一倍以上，主要优化了"读请求、解析、写回"这些纯 IO 开销。

### Q15. Redis 除了缓存还能干什么？（开放性题）

**参考答案：**
1. **分布式锁**（Redisson）；
2. **计数器/限流**：INCR + 过期时间做固定窗口；ZSet 滑动窗口；Lua 令牌桶；
3. **消息队列**：List（简单）、**Stream**（支持消费者组、ACK、消息回溯）；
4. **延迟队列**：ZSet score 存到期时间戳，轮询到期任务；
5. **排行榜**（ZSet）、**共同关注**（Set 交集）、**签到统计**（Bitmap）、**UV 统计**（HyperLogLog）、**附近的人**（GEO）；
6. **Session 共享**、**分布式 ID**（INCR）。
