### 2.3 核心改动

| 智能体 | 当前逻辑 | LLM 增强后 |
|--------|----------|------------|
| 库存监控 | 规则判断阈值 | LLM 分析库存趋势，预测风险演化 |
| 需求预测 | 统计计算 | LLM 结合市场因素、季节性、促销活动预测 |
| 采购规划 | 公式计算 | LLM 综合考虑供应商产能、账期、战略关系 |
| 供应商谈判 | 模板对话 | LLM 自由对话，策略谈判，多轮博弈 |
| 物流规划 | 规则匹配 | LLM 分析路线、天气、时效，生成最优方案 |
| **新增：决策解释** | 无 | LLM 为每个决策生成人类可读的解释 |

### 3.3 数据模型

```sql
-- 用户表
CREATE TABLE users (
    id UUID PRIMARY KEY,
    email VARCHAR(255) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    tenant_id UUID REFERENCES tenants(id),
    role VARCHAR(50) NOT NULL,
    created_at TIMESTAMP DEFAULT NOW()

-- 租户表
CREATE TABLE tenants (
    id UUID PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    plan VARCHAR(50) DEFAULT 'free',

    id UUID PRIMARY KEY,

);
```

### 6.3 工作流定义格式

```yaml
# 标准采购工作流模板
name: standard_procurement
version: "1.0"
nodes:
  - id: inventory_check
    type: inventory_monitor
    config:
      threshold: 0.8

  - id: demand_forecast
    type: demand_forecast
    config:
      horizon_days: 30

  - id: approval_gate
    type: approval
    config:
      approver_role: procurement_manager
      timeout_hours: 24

  - id: procurement
    type: procurement
    config:
      strategy: cost_optimized

  - id: negotiation
    type: vendor_negotiation
    config:
      max_rounds: 5
      target_discount: 0.15

  - id: logistics
    type: logistics
    config:
      priority: standard

edges:
  - from: inventory_check
    to: demand_forecast
  - from: demand_forecast
    to: approval_gate
    condition: "demand_forecast.confidence > 0.7"
  - from: approval_gate
    to: procurement
  - from: procurement
    to: negotiation
  - from: negotiation
    to: logistics
```

## 八、总结

本项目已具备完整的多智能体供应链决策能力，后续通过五个方向的持续增强，可逐步从**技术演示**升级为**企业级产品**：

1. **LLM 深度集成** — 让智能体真正"智能"
2. **权限多租户** — 具备企业级安全
3. **实时数据流** — 支撑高并发场景
4. **智能分析引擎** — 从执行到决策
5. **低代码工作流** — 从工具到平台

建议优先完成方向一（LLM 集成），这是项目的核心差异化所在，也是比赛评审的重点关注方向。
