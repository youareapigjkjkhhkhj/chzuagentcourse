# AgentBuddy 可拓展创新方向

> 项目定位：**个人本地 Agentic Coding 工作台**，Electron + Vue3 + TS 桌面端，用户自带 API Key（OpenAI 兼容，已支持 deepseek/openai/qwen/glm/ollama/vllm），本地优先、可学可改。
>
> 源码摸底确认 P0~P7 已全部落地：流式聊天与多会话 JSON 落盘（sessionStore）；Agent Loop（orchestrator）+ 内置工具 read/glob/grep/write/edit/bash/webfetch/websearch/todo_write/skillTool；三栏工作台与 Diff 审阅（checkpoint ChangeSet 建模 modified/created/deleted/renamed + accept/revert 状态机）；权限矩阵 Plan/Ask/Auto × READ/WRITE/EXEC/NETWORK/DANGEROUS + 危险命令识别 + bash 白名单 + 路径 jail；两级 Skills（zip 导入，解析器零依赖）；MCP 客户端（stdio/http/SSE 三传输 + JSON 导入）；用量成本核算（usage/store 按模型/工具/日聚合，pricing 内置单价表）；专家团（persona + 工具/技能绑定）；密钥 safeStorage、Renderer 白名单 IPC + Zod 校验。
>
> 已有《优化精华版》面向修复既有短板（权限记忆绕过、token 估算、tool search、compaction 等）。本文档在其基础上**再跳一步**：10 个拓展方向全部挂在现有模块上，不引入付费外部服务。

## 一、桌面工作台功能增强

### 方向 1：会话成本仪表与预算护栏【易 · 1 周】

**背景与痛点**：用户自带 Key，用量统计页只做"事后总账"，长任务跑完才知道烧了多少。数据已齐：llm/usage 逐请求归一化（含 cacheRead 缓存命中）、usage/store 已按模型/工具/日聚合、pricing 内置多模型单价。缺的是过程可视化。

**创新点**：成本从"事后账单"变"实时仪表 + 预算护栏"——每轮回复后展示本次花费与缓存节省，设置会话/日预算，触线提醒而非等 API 超限报错。

**方案设计**：ask 完成后把 NormalizedUsage 经 chatService 现有 emit 下推；ChatView 每条 assistant 消息尾部渲染微型花费气泡（模型/入出 token/缓存节省/金额）；预算阈值存 configStore，ask 入口按 sessionId 过滤 UsageEntry 累计，超 80% 黄条提示、超 100% 二次确认。

**落地步骤**：W1 打通"ask 结束 → emit → 气泡"，成本复用 costOf；W2 预算触线确认，顺带采用精华版 CJK 加权 token 估算，否则金额失真。

**实用价值**：学生用小额充值 Key 跑整晚 Agent 敢放手试错；缓存命中用户看到"缓存节省 ¥x"形成省钱正反馈。

**风险与备选方案**：价格表会过时——做成可编辑 JSON，未知模型兜底价估算；护栏只提醒 + 二次确认，绝不硬性中止。

### 方向 2：变更交付助手——一键 Commit【易 · 1~2 周】

**背景与痛点**：Agent 改完、Diff 全 accept 后工作流断在"切终端敲 git"。checkpoint 的 ChangeSet 已结构化保存这次改动（modified/created/deleted/renamed），workspace:git 通道与 git 只读白名单已就位，只差收尾动作。

**创新点**：Diff 全绿时浮现"准备提交"交付条：基于 ChangeSet + diff.ts 补丁内容走一次 LLM，产出 Conventional Commits 风格 message，同时列出变更文件树。

**方案设计**：chatService 监听会话全部 ChangeSet 已 accept 事件，用当前模型生成建议文案；新 CommitCard 组件展示可编辑 message + 文件清单（created/renamed 高亮）；"复制到剪贴板"按钮零权限成本；"执行 git commit"必须过 Permission Gate（bash 白名单外走 Ask），命令由主进程拼接（git add 指定文件 + git commit -F 临时消息文件），绝不信任模型字符串拼接。

**落地步骤**：W1 摘要生成 + CommitCard 静态 UI + 复制；W2 权限门内执行 commit，临时文件放工作区内受 resolveWithinWorkspace 约束，端到端冒烟。

**实用价值**：作业/比赛每个提交点都省掉"比对文件 + 憋 message"，且文件清单由 ChangeSet 生成，不会漏提交 Agent 新建的文件。

**风险与备选方案**：模型 message 可能夸大——永远可编辑，提供"仅文件清单"纯本地模式；git 属写操作必须确认，不做自动 push。

### 方向 3：诊断自修复闭环（tsc/eslint 回灌）【中 · 2~3 周】

**背景与痛点**：Agent 修完一个编译错误是否修对，只能靠跑 npm test（慢且贵）；更常见是"改 A 引入 B"无人察觉。项目无 LSP 依赖（AGENTS.md 明令禁止过早引入重依赖），但工作区几乎都有 tsc/eslint。

**创新点**：零依赖"体检仪"：每次 write/edit 后自动跑 `tsc --noEmit`（或探测到的 eslint），结构化报错回灌下一轮上下文，CodeViewer 同步高亮行列——模型"改了立刻知道对不对"，形成 改码→体检→自修 闭环。

**方案设计**：① 新 tools/lintTool.ts：探测 package.json 判定栈，调用 CLI（tsc --pretty false / eslint -f json），复用 process/run.ts 的超时与截断，解析为 {file,line,col,severity,message,code}[]，结果走标准 ToolResult；② 拦截点不动 Agent Loop：tools/bus.ts 对 write/edit 注册包装器，执行成功后追加一次 lint 并把结果合并进该轮 tool result——Orchestrator 与 Permission 语义零改动；③ CodeViewer 接收行号高亮。

**落地步骤**：W1 lintTool（tsc 路径）+ 单测（构造含错小工程验证解析）；W2 bus 包装 + 自修冒烟（3 个错误的文件一轮内修完）；W3 eslint 探测 + UI 高亮 + 设置开关。

**实用价值**：把"报错→修复"反馈从分钟级降到秒级；对 TS 课设/前端作业最痛场景直击，且该范式可换接任意 CLI 检查器，是给 Loop 加"质量传感器"的通用方案。

**风险与备选方案**：全量 tsc 大项目超 20s——超时降级为 edit 唯一性校验；warning 默认只展示 UI 不进上下文，防噪音误导。

## 二、Agent 能力升级

### 方向 4：提交前专家评审工作流【中 · 2~3 周】

**背景与痛点**：专家团（P7）目前是"换人设单聊"，与主对话产出无协作。真实组队场景最想要的是：写完了，让"架构专家""质量专家"**只读审一遍改动再提交**。experts.ts 的 persona + 工具绑定、chatService 的 persona 注入与 bus 过滤（buildSessionBus allow 参数）都已就绪，缺"评审编排"层。

**创新点**：专家从"单聊角色"升级为"评审协作者"：一个入口让多位只读专家基于同一份 ChangeSet 并行评审，产出结构化问题清单，主对话按清单逐条派单修复。

**方案设计**：① Expert 增加可选 `focus` 字段，持久化沿用 experts.ts；② 新 reviewWorkflow：输入 ChangeSet → 过滤含只读工具的专家 → 每人独立 turn（人设 + 改动摘要 + 文件内容，不继承主对话历史），Zod 校验产出 {file,line,severity,title,suggestion}[]；③ DiffPanel 顶栏"评审"按钮，结果按文件聚合为 ReviewCard，每条可"指派修复"（生成指令追加进主对话）；④ 强制只读工具 + Ask 模式，Permission 边界不放松，先并发 2 位。

**落地步骤**：W1 单专家同步版编排器 + 清单 Schema；W2 双专家并行 + 超时兜底 + 聚合 UI；W3 指派修复回流主对话。

**实用价值**：组队开发的"提交前互审"第一次有了 Agent 版；交作业前跑一遍等于免费请两位不同视角的学伴把关，答辩可展示"自审过程"。

**风险与备选方案**：评审易空泛——prompt 注入 readProjectInstructions 读到的 AGENTS.md 规则，并要求每条问题必须带行号与修改建议；成本顾虑则默认 1 位专家、用户手动加人。

### 方向 5：任务复盘报告【易 · 1~2 周】

**背景与痛点**：会话散落几十条消息与工具轨迹，任务做完用户很难向第三方（老师/队友/客户）说清"解决了什么、改了什么、花了多少"。数据全在：SessionData 全量落盘、usage 有成本、checkpoint 有变更集、execWhitelist 之外的命令都有记录。

**创新点**：会话"复盘收尾"：onDone 后用轻量 LLM 摘要生成一页 Markdown 报告——任务目标、改动文件清单、执行命令、关键决策、token 与费用，一键导出或复制。

**方案设计**：chatService 增加 finish 钩子：输入 = todo 完成清单 + ChangeSet 文件清单 + usage 汇总 + 消息序列（只到工具名级，不复述全文），按固定模板产出；报告写入工作区 `.agentbuddy/reports/{sessionId}.md`（走 resolveWithinWorkspace），侧栏加"复盘"入口；提供"人话版"开关（不带命令细节，给老师/客户看）。

**落地步骤**：W1 报告服务 + 模板 + 落盘；W2 复盘入口 UI + 导出/复制 + 失败静默不阻断主流程。

**实用价值**：答辩/竞赛/外包交付最缺"过程性证据"，自动复盘把 Agent 的隐形劳动变可展示成果；个人可累积"AI 使用周报"。

**风险与备选方案**：模型可能编造——文件/命令清单由代码生成不经模型，模型只写叙述段落且约束"不得超出给定事实"；另提供纯模板模式零成本。

### 方向 6：任务流配方 .taskflow【高 · 3~4 周】

**背景与痛点**：一批重复性多步活（新项目摸底、作业提交前自检、换依赖后回归）每次都要重新指挥。Skills 只能注入静态提示，表达不了"先 A 验证通过再做 B，失败重试/中止"。

**创新点**：工作区 `.agentbuddy/flows/*.taskflow.json` 声明带验证门的线性步骤，Agent 按配方执行、每步跑验证命令、失败自动重试或停在断点——把零散对话变成可复现可交接的流水线。

**方案设计**：① FlowDef {name, steps:[{prompt, verify:{cmd, expect:"exit0"|"grep"}}], retryLimit, budget}，放 shared/types 并 Zod 校验，扫描/加载仿 skills.ts（全局 + 项目两级）；② FlowRunner 串行把每步 prompt 交给现有 chatService.ask（同会话追加，继承上下文），步后跑 verify（走 bash 与 Permission Gate），失败重试时附上次输出；③ 入口 `/flow 名称`（并列注册进 skills 的 `/` 解析）+ 首页快捷区；参数 `{{var}}` 占位，杜绝代码执行。

**落地步骤**：W1 Schema + Zod + 扫描 + /flow list；W2 线性执行器（内置"新项目摸底"配方验证）；W3 重试 + 参数占位 + 断点续跑；W4 表单编辑器（可选）。

**实用价值**：一次调通终身复用——接外包翻新同类项目、统一团队作业流程；答辩演示"同一条流水线跑两个项目"说服力强，是本地 Agent 少有（区别于纯 Skills）的能力。

**风险与备选方案**：MVP 只做线性 + 单验证门，条件/并行/嵌套明确不做；降级方案：不做 JSON 引擎，用"Markdown 配方顺序注入"两周交付，验证门后补。

### 方向 7：会话录制回放台【高 · 3~4 周】

**背景与痛点**：排查"为什么上次没修对、换个 prompt 或便宜模型行不行"只能重跑碰运气。会话本已全量录制（SessionData + 工具 + usage），context.ts 的 trimToBudget/dropOldMessages 决定模型当时看到什么——这些都没被利用。

**创新点**：会话"录像带"：导出可离线回放文件，按时间轴步进展示每轮上下文窗口与工具调用；进阶"分叉对比"——同一份录制换 prompt 模板/模型配置重放，逐轮对比输出与成本。

**方案设计**：① 导出 .agentbuddy-replay.json（含 usage 与 drop 断点标注，过 redact 脱敏）；② 回放器先 CLI 后 UI：纯离线按序回放（工具结果用录制值不真执行），复算 context.ts budget 曲线（当时上下文多少 token、丢过哪些消息）；③ 对比模式把各轮输入原样喂 llm/client（换 modelId/prompt 片段）产出并排 diff + 成本对比，全程只读不写盘；④ UI 一期只做只读步进视图。

**落地步骤**：W1 导出/导入通道 + 回放 CLI；W2 上下文占用曲线（drop 点标记）；W3 双配置对比 + 结果 diff；W4 UI 只读回放视图。

**实用价值**：自研 Agent 最缺"可复现实验环境"——"同任务新旧配置对比"是答辩最硬证据；普通用户可复盘"翻车现场"（回放到出错轮看模型当时看到了什么）。

**风险与备选方案**：对比耗 token——默认只跑前 N 轮或指定段；导出含密钥痕迹必须过 redact.ts（已有）；MVP 严格限定导出 + CLI 回放，UI 二期。

## 三、架构工程化

### 方向 8：数据保险——导出/导入与自动备份【易 · 1~2 周】

**背景与痛点**：承诺"数据全在本机"，但磁盘损坏/误删/重装都会清零。sessionStore 已有完整 JSON 落盘与防护，zip.ts 已有安全解包（防炸弹与 zip-slip），导出侧空白。

**创新点**：一键导出会话（json 或打包）、一键导入（校验合并）、工作区定时自动备份轮转——本地工具的信任底线与工程成熟度证明。

**方案设计**：① session:export 新 IPC：sessionStore.get → redact 脱敏 → 主进程弹保存框（Renderer 不碰文件系统，守现有分层）；② session:import：Zod 校验版本 → id 冲突生成新 id 标"导入副本" → 刷新 sessionStore 缓存；③ 主进程定时（默认每小时）把 sessions 与配置增量拷贝至 `.agentbuddy/backup/{ts}/`，保留最近 7 份轮转，纯 fs.copyFile 零依赖；④ 打包导出后续用 Node zlib deflateRawSync 补 minimal zip writer（与现有解析对称）。

**落地步骤**：W1 单会话导出/导入 + IPC + UI（侧栏会话菜单与设置页）；W2 自动备份轮转 + 启动自检；W3 zip 批量打包（选做）。

**实用价值**：覆盖"换机器/重装"与"把会话发给同学复盘"高频场景；长期使用者等于给整学期工作留底稿。

**风险与备选方案**：脏数据导入破坏会话列表——Zod 校验 + 导入前完整备份；备份体积控制靠 N 份轮转；zip writer 来不及则 MVP 用单文件 json。

### 方向 9：自更新发布流水线【中 · 2 周】

**背景与痛点**：electron-packager 已能出免安装 exe（DELOPY.md 有发布清单雏形），但分发靠人肉传文件，使用者不知道有没有新版、改了什么。

**创新点**：极简自更新：publish 脚本生成 `latest.json`（版本/日期/变更摘要/下载 URL/sha256），应用内"关于"页检查更新，全走免费静态托管（GitHub/Gitee Releases），不引 electron-updater，绕开其代码签名硬要求。

**方案设计**：① publish.bat：打包 → 算 sha256 → 生成 latest.json（变更摘要从 CHANGELOG.md 摘本版段落），上传动作留给用户选渠道；② main 进程 updater 模块：手动"检查更新"GET latest.json（10s 超时静默失败），版本高于本地则弹窗展示摘要与下载（shell.openExternal）；启动自检默认关，个人工具不打扰；③ 版本号单一来源 package.json，构建期注入确保一致。

**落地步骤**：W1 publish 脚本 + latest.json + 本地 http 冒烟；W2 检查更新 UI + 全流程手工验证；W3 启动自动检查（可选）。

**实用价值**：训练营/组队分发 exe 是最真实路径，更新检查让使用者拿到的永远是新版；为开源/上架的产品化路线备好发布基建。

**风险与备选方案**：无签名 exe 触发 SmartScreen——文档注明"更多信息→仍要运行"或自签证书；托管不可用则局域网共享盘也能跑（协议不变）；只提示下载不自动替换，避免半自动更新毁掉信任。

## 四、落地商业化预演

> 商业化前提是"有人愿意持续用"。第一步不是收费，而是进入"愿意让 AI 替自己干活并为此付钱"的真实场景。方向 10 是这条路上最小的切口：不改变产品形态，只新增一种"以交付物为单位"的用法。增值点留档（本期不做）：复盘报告加密导出、多机配置同步、团队配方库（方向 6 的 .taskflow 天然可作交换品）。

### 方向 10：工单交付模式与任务账单【中 · 2~4 周】

**背景与痛点**：学生接小外包（改 Bug/做页面）的流程是"QQ 聊需求 → 闷头改 → 打包发送"：说不清工作量、不好报价，客户也不放心"AI 改的东西"。AgentBuddy 正是这类活的主力工具，缺"以工单为单位"的框架。

**创新点**：一次接单包装成"工单"：任务契约（需求 + 验收清单 + 预算上限）→ 独立会话执行 → 按验收清单逐项核对收尾（接方向 5 复盘报告做交付说明）→ 产出账单（耗时/改动/成本/报价区间参考），用过程透明换客户信任。

**方案设计**：① 契约：工单表单生成 {brief, acceptCriteria[], budgetLimit} 存入会话 meta（SessionData 扩展可选字段）；② 验收清单注入首轮上下文并同步成 todoTool 初始清单（打勾有现成持久化）；③ 超预算走方向 1 预留提醒接口；④ onDone 强制"验收核对"：Agent 逐条对照标准检查产物并如实标达成/未达成（未达成必须给理由），核对轮只读工具且每条结论引用证据（文件路径/命令输出），随后接方向 5 出交付报告；账单聚合 usage cost 与时长，报价区间用本地模板参考，不代做决策。

**落地步骤**：W1 工单创建 + 验收清单注入 todo + meta 落盘；W2 收尾核对流程 + 对接复盘报告；W3 账单导出（MD/CSV）+ "我的工单"历史列表。

**实用价值**：接单学生有可出示的过程证据，客户疑虑消解；工具从"个人效率"走向"微型交付服务"，是"用户愿意为好交付付费"的最小商业验证。

**风险与备选方案**：模型自评可能糊弄——结论必须引用证据，拿不出证据视为未达成；报价仅本地参考，无线上交易，规避合规；场景若太窄可降级为"验收模式"——老师按验收清单批作业，同一套逻辑不改。

## 落地组合建议

- **2 周档（答辩够用）**：方向 1 + 2 + 5——全"易"、互不依赖、UI 可见度高，演示"实时成本 + 一键提交 + 自动复盘"。
- **4 周档（进阶）**：加方向 3 + 4——挂在工具链与专家模块上，演示"改完自检自修、提交前自动评审"。
- **挑战档**：方向 6 或 7 二选一做差异化——6 偏产品、7 偏工程实验；先做 MVP 子集（线性配方 / CLI 回放），UI 放最后。
- **验证底线**：沿用项目惯例 mock LLM 单测 + 真模型冒烟；涉及权限的改动（方向 2 的 git 执行、方向 6 的 verify）必须补 Permission Gate 单测。
