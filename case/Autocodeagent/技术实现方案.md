# AgentBuddy MVP 技术实现方案

> 版本：v1.0 ｜ 定位：个人本地 Agentic Coding 工作台的 **MVP 落地技术方案**
> 配套文档：《设计方案》（产品与架构设计）、《AgentBuddy_原型_v2.1_优化版.html》（交互基线）

## 1. 技术选型

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 应用壳 | Electron 31+（contextIsolation 开启、nodeIntegration 关闭） | 原型布局即最终布局 |
| 前端 | Vue 3 + TypeScript + Vite + Tailwind CSS | 原型样式直接迁移为组件基线 |
| Agent 运行时 | 纯 TypeScript 模块 `agent-core`，**无编排框架** | 单 Agent Loop 直连 OpenAI 兼容 API |
| 模型接入 | OpenAI 兼容 Chat Completions（`tools` / `tool_calls`、流式） | 一套代码接 DeepSeek / OpenAI / Ollama |
| MCP | `@modelcontextprotocol/sdk`（官方 TS SDK，stdio 传输） | 不自实现协议层 |
| 校验 | `zod`（IPC payload、工具入参、配置文件统一 schema） | 置于 `shared` 包 |
| Token 计数 | `js-tiktoken` | 上下文预算与用量预估 |
| 密钥 | Electron `safeStorage` | Renderer 零接触明文 |
| 存储 | 文件系统（JSON / JSONL），不引入数据库 | 符合本地轻量定位 |

┌──────────────────▼────────────────────────────┐

- MVP 阶段 `agent-core` 内嵌 Main 进程；接口按「可拆 `utilityProcess`」设计，不做提前拆分。

## 3. agent-core 模块职责

| 模块 | 职责 | 关键接口 |
| --- | --- | --- |
| `orchestrator` | Agent Loop、Turn 计数、超时、Abort、事件发射 | `runTurn(ctx, text, emit)` |
| `context` | 上下文六层注入、token 预算、截断与 Compaction | `assembleContext(ctx): Message[]` |
| `permission` | 模式 × 风险决策、确认挂起、会话内授权记忆 | `check(mode, risk, call): Decision` |
| `toolbus` | 内置 + MCP 工具注册、schema 导出、分发执行 | `schemas()` / `get(name)` |
| `workspace` | 工作区生命周期、路径解析与 jail、git/项目信息 | `open()` / `resolvePath()` / `isInside()` / `gitInfo()` |
| `process` | bash 子进程管理：spawn、超时、输出限流、**进程树清理** | `run()` / `killTree(pid)` |
| `tools/builtin` | read / glob / grep / write / edit / bash | 统一 `Tool` 接口 |
| `skills` | 全局/项目两级扫描、frontmatter 解析、目录注入、`/` 命令 | `scan()` / `inject()` |
| `checkpoint` | WRITE/EXEC 前自动打 git 快照，支持按 changeId 撤销 | `snapshot()` / `restore(changeId)` |
| `mcp` | 配置读写、连接池、tools 发现、JSON 导入、生命周期 | `connect()` / `importJson(text)` |
| `llm` | 兼容 API 流式调用、重试、usage 采集 | `chatStream(req)` |
| `usage` | token/费用/缓存命中/执行记录落盘与聚合 | `record()` / `stats(range)` |
| `store` | 会话与配置的读写；**关键事件即时落盘 + 普通消息防抖 flush，流式 token 不落盘** | `sessions/{id}.json` |

统一工具接口：

```ts
type RiskLevel = 'READ' | 'WRITE' | 'EXEC' | 'NETWORK' | 'DANGEROUS'

interface Tool {
  name: string
  description: string
  inputSchema: JSONSchema
  risk: RiskLevel
  assessRisk?(input: unknown): RiskLevel   // bash 危险命令动态升级
  execute(ctx: ToolContext, input: unknown): Promise<ToolResult>
}
```

## 4. 核心实现

### 4.1 Agent Loop（orchestrator）

```ts
export async function runTurn(ctx: SessionContext, userText: string, emit: Emitter) {
  ctx.messages.push({ role: 'user', content: userText })
  let turns = 0

  while (turns++ < ctx.config.maxTurns) {
    if (ctx.signal.aborted) return markInterrupted(ctx)

    const messages = assembleContext(ctx)                    // §4.3
    const res = await llm.chatStream({
      model: ctx.model, messages,
      tools: ctx.toolBus.schemas(), signal: ctx.signal,
      onDelta: d => emit('streamToken', d),
    })
    ctx.messages.push(res.message)
    ctx.usage.record(res.usage)                              // §4.7
    if (!res.message.tool_calls?.length) return              // 无工具调用 = 回合结束

    for (const call of res.message.tool_calls) {
      const tool = ctx.toolBus.get(call.name)
      const risk = tool.assessRisk?.(call.arguments) ?? tool.risk
      const decision = await ctx.permission.check(ctx.mode, risk, call)   // §4.2
      if (decision === 'deny') {
        ctx.messages.push(toolMsg(call.id, '用户拒绝了该操作，请换一种方式或向用户说明。'))
        continue
      }
      emit('toolStart', { call, risk })
      try {
        const out = await withTimeout(tool.execute(ctx, call.arguments), TOOL_TIMEOUT)
        ctx.messages.push(toolMsg(call.id, out.text))
        emit('toolResult', { call, ok: true, out })
      } catch (e) {
        ctx.messages.push(toolMsg(call.id, `工具执行失败: ${e.message}。请调整参数或改用其他工具。`))
        emit('toolResult', { call, ok: false, error: e.message })
        if (repeatFailure(ctx, call, 2)) return emit('error', '同一工具连续失败，已终止')
      }
    }
  }
  emit('error', '达到 maxTurns，任务未完成')
}
```

实现约束：

1. **权限拦截位于循环内、执行前**；`awaiting_permission` 即挂起于 `permission.check`。
2. **工具失败不崩溃**：结构化错误回灌模型自行换路；同一工具同一入参连续失败 2 次熔断。
3. **流式 `tool_calls` 增量按 `index` 累积 `arguments` 字符串，完整后一次性 `JSON.parse`**，禁止按分片解析。
4. `abort` 时保留已完成工具结果；当前半截 assistant 消息标记 `interrupted` 后落盘，不带入下轮请求。
5. `maxTurns` 默认 20；单工具超时默认 60s（bash 120s）。
6. **同一 assistant 消息内的独立 `tool_calls` 并发执行**（如同时 read 多个文件），有依赖则顺序；主流实现均已采用，显著降低多轮损耗。
7. WRITE/EXEC 执行前经 `checkpoint.snapshot()` 打快照，`diff.revert` 基于快照恢复（见 §4.8）。

### 4.2 Permission Gate

决策矩阵直接落为查表：

```ts
const MATRIX = {
  Plan: { READ: 'auto', WRITE: 'deny', EXEC: 'deny', NETWORK: 'deny', DANGEROUS: 'deny' },
  Ask:  { READ: 'auto', WRITE: 'ask',  EXEC: 'ask',  NETWORK: 'ask',  DANGEROUS: 'ask' },
  Auto: { READ: 'auto', WRITE: 'auto', EXEC: 'ask',  NETWORK: 'ask',  DANGEROUS: 'ask' },
}
// Auto.EXEC 先查低风险白名单（ls / git status / npm test …），命中则 'auto'
// DANGEROUS 不提供 allow_always_session，仅「允许一次」
```

- `bash.assessRisk`：正则命中 `rm -rf`、`sudo`、`git push --force`、`git reset --hard`、`npm publish`、`DROP TABLE` 等 → `DANGEROUS`。
  **定位：命令风险启发式检测，不是安全边界**（`x=$(cat cmd.txt); bash $x)` 类绕过无法用正则拦截）。真正的安全边界由三层承担：Permission Gate 决策 + workspace jail + bash 执行策略：
  - cwd 强制工作区、环境变量受控（不透出钥匙串内容）
  - 超时 + stdout/stderr 限流，不得绕过 Permission Gate 直达执行层
- **确认粒度采用模式匹配**：同一 `bash` 命令模式、同一文件路径的授权可在会话内复用，避免同类操作重复弹窗；MCP 首次调用确认后按 server 记忆。
- 授权记忆仅存活于会话内（`allow_always_session`），随会话结束清空。
- 所有文件路径经 `resolveWithinWorkspace()`，逃出工作区直接拒绝。

### 4.3 上下文管理

注入顺序（固定六层）：

```
① 系统角色与安全约束
② 工作区路径与技术栈信息
③ 项目指令：AGENTS.md（兼容 CLAUDE.md / .cursor/rules，只取其一）
④ 已启用 Skills 的 name + description 摘要（正文按需 read）
⑤ 历史消息与工具结果
⑥ 当前用户消息
```

预算控制：

```
预算 = 模型上下文上限 − 输出预留（默认 8k）
超限时依序降级：
  1) 旧消息中工具结果正文 → 替换为占位摘要（保留首 10 行）
  2) 仍超 → Compaction：最早 N 轮收成一条摘要消息（调便宜模型生成）
  3) ①–④ 系统区永不裁剪
```

Compaction 细则：

| 事项 | 规则 |
| --- | --- |
| 触发 | 自动：历史占用超预算 80%（每轮请求前检查）；手动：`/compact` 命令 |
| 范围 | 保留最近 K 轮（默认 3）原文，更早全部进摘要 |
| 摘要内容 | **结构化四项（Claude Code 同款，防丢失执行状态）**：① 原始任务与目标 ② 已完成事项及关键结论 ③ 涉及的关键文件路径与修改状态 ④ 下一步计划与未完成项 |
| 生成模型 | 便宜小模型；失败降级为规则式摘要（取每轮首条用户消息 + 工具名清单），不阻塞主流程 |
| 落盘 | 摘要替换仅作用于请求组装；`sessions/{id}.json` 始终存完整历史，回放不受影响 |
| UI | 时间线插入「已压缩上下文」分隔条；`/compact` 支持追加指令（如「重点保留测试结论」） |

源头限流：`read` 单次 ≤ 2000 行；`bash` / 工具输出 ≤ 20KB，超出截断并附提示。
**文件新鲜度校验（主流标配）**：记录每个文件的 `read 时刻 mtime`；`edit`/`write` 时若文件在 read 之后被外部修改，拒绝执行并要求重新 `read`，防止基于陈旧内容的盲改。

### 4.4 LLM Adapter

- 单一实现：`POST {baseUrl}/chat/completions`，`stream: true`，SSE 逐块解析。
- 能力：流式回调、`AbortController` 中断、指数退避重试（仅网络错误与 5xx，最多 3 次）。
- **厂商差异归一**：对外统一 `NormalizedLLMResponse { message, toolCalls, usage, finishReason, providerMetadata }`。已知差异：缓存字段各家不同（§4.7）、DeepSeek 思考内容在 `reasoning_content`、Ollama 仅在末块返回 usage——差异集中在适配层处理，Loop 层零感知。
- 每次响应结束采集 `usage` 并归一（见 §4.7）；工具失败不触发重试。

### 4.5 MCP 子系统

```ts
import { Client } from '@modelcontextprotocol/sdk/client/index.js'
import { StdioClientTransport } from '@modelcontextprotocol/sdk/client/stdio.js'

const transport = new StdioClientTransport({
  command: cfg.command, args: cfg.args, env: resolveEnv(cfg.env),
})
await client.connect(transport)
const { tools } = await client.listTools()
// 注册进 Tool Bus：name = `mcp__${server}__${tool.name}`，risk = 'NETWORK'
```

**工具数量上限**：tools schema 全量随请求下发，连接过多会持续消耗 token。单会话挂载工具数设上限（默认 40，超出提示用户在 MCP 页禁用），这是 MCP 接入的必备护栏。

| 事项 | 规则 |
| --- | --- |
| 配置三通道 | `mcp.json` 文件、UI 表单、JSON 粘贴导入，统一走 `McpConfig.upsert`（同名覆盖） |
| JSON 导入 | zod 校验 `{ mcpServers: {...} }` 或内层对象；`command+args`→stdio、`url`→sse；解析失败整体拒绝 |
| 环境变量 | `${VAR}` 占位符从钥匙串 / 系统环境变量解析注入，不落盘、不进日志 |
| `enabled` | 决定启动时是否自动连接 |
| 生命周期 | 启用即连接 + `listTools` 入总线；禁用/退出 `close()`；进程崩溃标记离线，不影响内置工具 |
| 传输 | MVP 仅 stdio；SSE/HTTP 后置 |

### 4.6 Skills 子系统

- 两级目录：`~/.agent/skills/`（全局）+ `<workspace>/.agent/skills/`（项目，同名覆盖全局）。
- 解析 `SKILL.md` frontmatter（name / description），zod 校验。
- 两种使用方式：**目录注入**（摘要进系统提示，正文按需 `read`）+ **斜杠命令**（`/name` 将正文追加为高优先级指令）。
- Skills 仅为文本指令，不提供脚本执行能力。
- **`todo` 内置工具（计划可见性）**：模型通过 `todo_write` 维护任务清单，UI 的 Plan Checklist 由该工具事件驱动而非提示词约定；长任务下显著减少模型跑偏，实现成本仅一个内存列表工具。

### 4.7 用量采集

```
~/.agent/usage.jsonl   { ts, sessionId, model, in, out, cached, cost }
~/.agent/records.jsonl { ts, sessionId, tool, target, risk, ok, ms }
```

- 缓存命中字段归一：OpenAI `usage.prompt_tokens_details.cached_tokens`、DeepSeek `prompt_cache_hit_tokens`、Anthropic `cache_read_input_tokens` → 统一为 `cached`。
- 命中率 = Σcached / Σin；费用按各模型单价累加。
- `usage.stats({ range })` / `usage.records({ sessionId?, tool? })` 读 JSONL 内存聚合（个人量级无需数据库）。

### 4.8 Checkpoint（写操作安全网）

```
edit / write / bash(EXEC+) 执行前：
  git 仓库   → git stash create --include-untracked 拿快照 hash（不动工作区、无提交噪音）
  非 git 目录 → 复制受影响文件到 ~/.agent/snapshots/{changeId}/
diff.revert(changeId) → 按快照恢复
```

撤销语义显式建模为 **ChangeSet**，避免「UI 显示可撤销但恢复不完整」：

```
ChangeSet { modified[], created[], deleted[], renamed[] }
revert = modified 还原内容 · created 删除 · deleted 恢复 · renamed 反向还原
```

- 快照与 changeId 绑定，随会话消息落盘；会话删除时一并清理。
- 与右栏 `[撤销]` 按钮同源：UI 层撤销 = 调用 `restore(changeId)`。

### 4.9 进程管理（bash 专用）

`AbortController` 无法保证杀死 OS 进程树（`npm` → `node` → 子进程），`bash` 工具统一走 `process` 模块：

```
run(command, { cwd: workspace, timeout, outputLimit })
abort → 平台化杀树：
  Windows: taskkill /PID {pid} /T /F
  POSIX:   进程组 kill（spawn detached + kill(-pgid)）
超时与手动停止共用同一杀树路径；残留进程记录告警。
```

## 6. IPC 契约

```ts
// Renderer → Main
agent.startSession({ workspace, model })

onStreamToken / onPlanStep / onToolStart / onToolResult
onPermissionRequest / onDiffReady / onDone / onError
```

## 7. 前端实现要点

- Vue 3 Composition API；视图状态对齐原型：`assistant / skills / mcp / models / usage`。
- 对话流由事件驱动渲染：`onStreamToken` 增量拼接、`onToolStart/Result` 生成 Tool Trace 卡片、`onPermissionRequest` 内联权限卡、`onDiffReady` 打开右栏 Diff。
- 输入栏：工作区选择、Chat/Agent 模式、工作区默认权限（Plan/Ask/Auto）、`@文件 #MCP /技能` 提及。
- MCP 页：卡片列表 + 连接开关 + Tools 展开 + JSON 导入弹窗。
- 用量统计页：总览（统计卡 / 7 日柱状图 / 工具分布）、模型消耗、执行记录三 Tab。
- Key 仅显示掩码；所有危险操作无本地绕过入口。

## 8. 里程碑与验收标准

| 阶段 | 交付 | 验收标准 |
| --- | --- | --- |
| P0 | Electron 壳 + Vue 路由 + LLM 流式聊天 | 流式对话、可中断、会话落盘 |
| P1 | 6 内置工具 + Agent Loop + Ask 权限 | 完成「读代码 → 改动 → 跑测试」闭环 |
| P2 | 三栏工作台 + Diff 审阅 | 接受/撤销后文件与消息状态一致 |
| P3 | 权限矩阵全覆盖（**含 Plan 模式**）+ 危险命令识别 | 矩阵 15 格单测全过；Auto 下 `rm -rf` 仍弹确认 |
| P4 | Skills 两级扫描 + `/` 命令 | 项目级覆盖全局同名；`/review` 可触发 |
| P5 | MCP stdio + Tools 发现 + JSON 导入 | 接官方 filesystem server 实测 list/call；粘贴 `mcpServers` JSON 批量导入 |
| P6 | safeStorage + 用量统计 | Key 仅掩码；用量页含缓存命中率；记录可按会话/工具筛选 |

P1 + P2 结束即为可用 MVP（含 Compaction 截断版，长会话必需且成本极低）；P4–P6 为扩展能力收口。
**后置候选（不进 MVP）**：LSP 诊断回灌（edit 后自动取诊断喂回模型）、子 Agent（task 工具）、SSE 传输。架构均已预留接口，不阻塞当前实现。

## 10. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 流式 `tool_calls` 分片解析错误 | 按 `index` 累积后统一 parse；分片单测覆盖 |
