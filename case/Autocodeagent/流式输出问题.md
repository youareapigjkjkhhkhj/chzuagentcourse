对，你这个现象其实很典型。**从你描述的代码结构看，问题大概率不在 SSE，而在“流式事件”和“Agent Turn 生命周期”耦合得太紧了。**

你现在实际上是：

```text
LLM stream
  ↓
onDelta
  ↓
emit(token)
  ↓
IPC
  ↓
Renderer
```

但是一旦模型产生 Tool Call：

```text
LLM stream
  ↓
等待整个 stream 结束
  ↓
解析 tool_calls
  ↓
执行 Tool        ← 这里可能持续几秒
  ↓
再次请求 LLM
  ↓
最终文本
  ↓
Renderer
```

所以用户看到的就是：

> **界面像卡住了 → 工具偷偷执行 → 工具完成 → 突然蹦出一大段结果**

这不是一个好的 Agent UX。

主流 Agent 的思路是把 **“模型输出”“工具调用”“工具执行”“下一轮模型输出”全部当成独立事件流**。例如 Anthropic 的 streaming tool use 会把 tool-use block 的开始、参数 JSON 增量、工具结果等作为独立事件；工具执行期间本身就是一个明确的状态阶段。([Claude 文档][1])

# 我建议你把整个流式架构改成 Event Stream

不要再把核心概念定义成：

```text
token
```

而应该定义成：

```text
AgentEvent
```

例如：

```ts
type AgentEvent =
  | {
      type: "turn.started"
      turnId: string
    }

  | {
      type: "message.delta"
      messageId: string
      delta: string
    }

  | {
      type: "tool.call.started"
      callId: string
      toolName: string
    }

  | {
      type: "tool.call.arguments.delta"
      callId: string
      delta: string
    }

  | {
      type: "tool.call.ready"
      callId: string
      arguments: unknown
    }

  | {
      type: "tool.execution.started"
      callId: string
      toolName: string
    }

  | {
      type: "tool.execution.progress"
      callId: string
      message?: string
    }

  | {
      type: "tool.execution.completed"
      callId: string
      result: unknown
    }

  | {
      type: "turn.completed"
      turnId: string
    }

  | {
      type: "turn.failed"
      turnId: string
      error: unknown
    }
```

这样 Renderer 根本不需要知道：

> “现在是不是 LLM stream？”

它只需要知道：

> **Agent 当前发生了什么。**

# 关键变化：Tool Call 不能等 Turn 结束才暴露

你现在有一句非常值得改：

> **流结束后一次性解析 tool_calls**

这个设计就是问题核心之一。

应该变成：

```text
SSE chunk
   │
   ├── text delta
   │      ↓
   │   message.delta
   │
   └── tool_call delta
          ↓
      tool.call.started
          ↓
      tool.call.arguments.delta
          ↓
      tool.call.ready
```

例如模型开始调用：

```json
{
  "tool": "blender.render_scene"
}
```

你马上给 Renderer：

```text
tool.call.started
```

UI 立刻显示：

```text
🤖 正在调用 Blender
   render_scene
```

参数继续流：

```text
tool.call.arguments.delta
```

最后：

```text
tool.call.ready
```

然后：

```text
tool.execution.started
```

UI：

```text
🤖 正在调用 Blender
   render_scene
   ● 执行中...
```

# 然后最重要的一点

**Tool execution 和 UI event stream 必须彻底解耦。**

应该是：

```text
                    ┌───────────────┐
                    │    LLM SSE    │
                    └───────┬───────┘
                            ↓
                    ┌───────────────┐
                    │ Event Mapper  │
                    └───────┬───────┘
                            ↓
                    ┌──────────────────────┐
                    │   Agent Event Bus    │
                    └───────┬──────────────┘
                            │
               ┌────────────┴────────────┐
               ↓                         ↓
        Renderer / IPC              Orchestrator
                                         ↓
                                   Tool Executor
                                         ↓
                                   Event Bus
```

也就是说：

```text
Tool Executor
```

执行 10 秒：

**不能阻塞 Event Bus。**

# 你的 Orchestrator 应该变成这种感觉

现在可能接近：

```ts
const response = await client.chat(...)

for await (const chunk of response) {
  ...
}

const toolCalls = parseToolCalls()

for (const call of toolCalls) {
  await executeTool(call)
}
```

建议变成：

```ts
for await (const chunk of client.chat(...)) {
  const events = parser.push(chunk)

  for (const event of events) {
    eventBus.emit(event)

    if (event.type === "tool.call.ready") {
      toolExecutor.execute(event)
    }
  }
}
```

但这里还有一个重要细节：

**不要让 `toolExecutor.execute()` 阻塞 SSE 消费。**

应该：

```ts
if (event.type === "tool.call.ready") {
  void executeTool(event)
}
```

然后：

```ts
async function executeTool(call) {
  bus.emit({
    type: "tool.execution.started"
  })

  try {
    const result = await toolBus.call(call)

    bus.emit({
      type: "tool.execution.completed",
      result
    })
  } catch (error) {
    bus.emit({
      type: "tool.execution.failed",
      error
    })
  }
}
```

```text
                 │  STREAMING   │

                                 │
```

这才是 Agent Harness 应该真正管理的东西。

# 还有一个你现在特别应该检查的地方

你说：

> **工具其实时执行的，等工具执行完了会显示完整输出。**

我会首先排查两个地方。

### ① Main process 有没有同步阻塞

如果：

```ts
await toolBus.call()
```

背后实际上是：

```ts
spawnSync()
execSync()
JSON.parse(巨大数据)
CPU 密集计算
```

那 Electron Main Thread 会真的卡住。

这种情况下：

```text
Tool 执行
     ↓
Main Thread blocked
     ↓
webContents.send()
     ↓
Renderer 收不到
```

**这和 Agent streaming 是两回事。**

如果 MCP 是 stdio，尤其要检查你的 MCP transport 实现是不是错误地用了同步 subprocess / buffer-all 模式。

---

### ② 你的 IPC event 是否实际上被“Turn 完成”包住了

比如这种：

```ts
const events = []

await runTurn({
  onDelta: e => events.push(e)
})

for (const event of events) {
  emit(event)
}
```

这会直接造成你现在看到的现象。

正确的是：

```ts
await runTurn({
  onEvent: event => {
    emit(event) // 立即发送
  }
})
```

**不要在 Orchestrator / ChatService 中把 event 收集成数组后再统一 emit。**

```text
                 ┌─────────────┐
                 │     LLM     │
                 └──────┬──────┘
                        SSE
                         ↓
                 ┌─────────────┐
                 │ SSE Parser  │
                 └──────┬──────┘
                        ↓
                ┌────────────────┐
                │ Agent Event Bus│
                └───────┬────────┘
                        │
          ┌─────────────┼─────────────┐
          ↓             ↓             ↓
       Renderer     Orchestrator   Logger
          ↑             │
          │             ↓
          │        Tool Executor
          │             │
          │       ┌─────┴─────┐
          │       ↓           ↓
          │    MCP Tool    Progress
          │       │           │
          └───────┴───────────┘
```

核心原则只有一句：

> **所有“正在发生的事情”都先变成 Event，再由不同消费者处理；不要让 Tool Execution 成为 Stream Output 的阻塞点。**

## 和主流设计对齐的话，你应该重点学这三个东西

**第一是 Event-based streaming。**
不要只有 `token`，而是 text / tool / status / error / lifecycle 都是事件。

**第二是 interleaved tool streaming。**
Tool call 自己也是 streaming block，而不是等完整 LLM response 后才突然出现。Anthropic 的 API 就是把 `content_block_start`、`content_block_delta`、tool result 等作为流事件暴露出来。([Claude 文档][1])

**第三是 Agent state 和 UI state 分离。**

```text
Agent State
    ↓
Event Stream
    ↓
UI Projection
```

而不是：

```text
Orchestrator
    ↓
直接修改 Message
```

这样以后你再加：

```text
thinking
tool search
MCP
sub-agent
permission
checkpoint
retry
parallel tools
tool progress
background task
```

都不会把流式系统重新推翻。

**如果只改一件事，我建议你先把现在的 `token event` 升级成统一的 `AgentEvent`，并确保 `tool.execution.*` 事件在工具执行期间实时经过 IPC 发给 Renderer。**这很可能就能直接解决你现在“工具在跑，但 UI 卡住”的核心问题。
