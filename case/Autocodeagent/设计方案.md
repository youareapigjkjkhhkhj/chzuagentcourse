# 本地轻量编程代理 — 专业设计方案（v2）

**定位**：个人本地使用的 Agentic Coding 工作台  
**技术栈**：Electron + Node.js + Vue3 + TypeScript  
**能力对标**：Claude Code / OpenCode / Pi 的核心子集，并纳入 **MCP** 与 **Skills**  
**原则**：结构专业、实现可落地、复杂度可控

> **v2 修订说明**：依据评审建议整体打磨产品信息架构与 Agent 执行体验——
> ① 概念模型收敛为 **Workspace → Session**（取消"任务"实体）；
> ② 权限模型升级为 **模式（Plan/Ask/Auto）× 风险等级（READ/WRITE/EXEC/NETWORK/DANGEROUS）**；
> ③ 主界面从"聊天 + Tool Trace"升级为 **三栏 Coding 工作台（会话 / 对话 / 代码与 Diff）**；
> ④ "执行审计日志"降级为设置内的 **执行记录**；
> ⑤ MCP 增加 Tools 发现能力，Skills 区分全局/项目来源；
> ⑥ API Key 进入 **OS Keychain / safeStorage**，Renderer 层永不接触明文密钥。
>
> **v2.2 增补**：⑦ MCP 支持 **JSON 粘贴导入**（兼容 Claude Desktop `mcp.json` 的 `mcpServers` 格式）；
> ⑧ 「设置」一级入口移除，改为 **用量统计**（模型 Token 消耗 / 工具调用分布 / 执行记录回放）。

---

## 1. 产品定义

### 1.1 一句话

在本地项目目录上，用自然语言驱动 **读码 → 改码 → 跑命令 → 调外部工具（MCP）→ 复用技能（Skills）** 的闭环编程代理。

### 1.2 设计目标

| 目标     | 说明                                            |
| -------- | ----------------------------------------------- |
| 本地优先 | 会话、配置、工作区全在本机；模型 API 由用户自备 |
| 可自治   | Agent Loop 多轮工具调用，直到任务完成或用户中断 |
| 可扩展   | Skills（提示/流程资产）+ MCP（外部工具协议）    |
| 可控     | 权限 = 模式 × 风险等级；危险操作任何模式下都确认 |
| 可学可改 | 模块边界清晰，单人可在数周内做出可用 MVP        |

### 1.3 范围

**包含**

- Agent Loop + 内置工具（read / write / edit / bash / glob / grep）
- Skills 加载与按需注入（全局 + 项目两级）
- MCP Client（stdio / 可选 SSE）与 Tools 发现
- 会话持久化、模式×风险权限、Diff 审阅工作台
- Vue3 桌面 UI（三栏工作台）

**不包含**

- 企业 SSO / 策略中心 / 审计上送
- 多 Agent 编排平台、自动 worktree 集群
- 向量库强依赖、云端同步

## 2. 产品信息架构（核心概念模型）

### 2.1 三层概念：Workspace → Session → 执行痕迹

> 不设独立的"任务"实体。Coding Agent 的核心是 **工作区 + 会话**：用户进入一个项目后不断产生会话，
> 每个会话承载一段完整的 Agent 执行痕迹。

```
代码空间 Workspace（一个本地项目目录）
    │
    ├── 会话 Session
    │      ├── 消息（用户 / AI）
    │      ├── 执行计划（Plan Checklist）
    │      ├── Tool 调用痕迹（Tool Trace）
    │      ├── 修改记录（Diff / 已接受 / 已撤销）
    │      └── 执行结果（命令输出、测试结果）
    │
    └── 工作区级资产：AGENTS.md · .agent/skills/ · git 状态
```

左侧树因此呈现为 **代码空间 → 会话**，而不是"代码空间 → 任务"。

### 2.2 应用级导航

```
AgentBuddy
├── 编程助理        （首页 / 三栏工作台）
├── 代码空间        （侧栏树：项目 → 会话）
├── Skills          （全局 / 项目两级）
├── MCP 连接器      （含 Tools 发现）
├── 模型            （密钥托管在 OS Keychain）
└── 用量统计        （Token 消耗 / 工具分布 / 执行记录）
```

> 原「执行审计日志」一级入口移除：个人产品不需要企业级审计中心。
> 「设置」页整体降级：偏好类配置（默认权限等）前移到输入框的权限按钮，
> 执行记录与 Token 用量合并为 **用量统计** 一级入口——个人用户更关心「花了多少、调了什么」。

### 2.3 首页设计原则

首页是 **一个大输入框**，不再有"场景分类 Tab"（敏捷开发 / 代码重构 / 自动化测试 …）。

理由：用户只需「告诉 Agent 我要干什么」，属于什么场景由 Agent 自己判断——
一句"帮我看看这个项目为什么启动失败"可能同时涉及 Bug 排查、代码分析、Shell 与 MCP，
让用户先分类是反直觉的。保留的只是 **技能快捷入口（`/review` 等）与常用动作示例**。

## 4. 核心概念

### 4.1 Agent Loop

经典单线程主循环（与 Claude Code / Pi 同构）：

```
用户输入
  → 组装上下文（系统提示 + 项目指令 + Skills 摘要 + 历史）
  → 调用 LLM（带 tools schema）
  → 若有 tool_calls：权限检查 → 执行 → 结果写回 messages → 再调用
  → 直至无 tool_call 或用户 Abort 或达到 maxTurns
```

### 4.2 Agent 执行体验（UI 呈现结构）

Tool Trace 与 AI 对话 **不完全混排**，一个完整回合按以下结构呈现：

```
AI 回复（意图说明）
  ↓
执行计划（Plan Checklist：✓ 分析项目结构 / ✓ 定位认证模块 / …）
  ↓
Tool Trace（grep / read / edit / bash / mcp 卡片流）
  ↓
结果（命令输出、测试结论）
  ↓
AI 总结
```

编辑类工具卡片附带 `[查看 Diff]`，点击后右侧 **Code/Diff 工作台** 打开对应文件；
命令类工具在需要确认时卡片内直接给出 `[允许一次] [始终允许] [拒绝]` 三个动作。

### 4.3 Tools（工具）

模型可调用的原子能力，统一接口：

```ts
type RiskLevel = 'READ' | 'WRITE' | 'EXEC' | 'NETWORK' | 'DANGEROUS'

interface Tool {
  name: string
  description: string
  inputSchema: JSONSchema       // 供 function calling
  risk: RiskLevel               // 静态基线
  assessRisk?(input): RiskLevel // 动态升级（如 bash 命令含 rm → DANGEROUS）
  execute(ctx: ToolContext, input: unknown): Promise<ToolResult>
}
```

### 4.4 Skills（技能）

**面向「怎么做」的可复用知识/流程包**，主要是 Markdown + 元数据，不是任意代码（个人版保持简单、安全）。

典型用途：代码审查清单、提交规范、某框架脚手架步骤、`/review` `/test` 等斜杠指令。

### 4.5 MCP（Model Context Protocol）

**面向「能调用什么外部系统」的标准协议**。本应用作为 **MCP Host/Client**，连接用户配置的 MCP Server，把其 tools 动态挂到 Tool Bus。

> Skills = 怎么做（内部流程知识）；MCP = 能调用什么（外部系统能力）。
> 两者边界保持分离，不做"可执行脚本式 Skill"。

## 5. 模块设计

### 5.1 Orchestrator（编排器）

职责：

- 维护 `messages[]` 与当前 Turn
- 流式转发 token / tool 事件到 UI（含 Plan 步骤事件）
- `maxTurns`（如 20）、超时、AbortController
- 错误：工具失败结果回灌模型，而非直接崩溃

关键状态：`idle | running | awaiting_permission | aborted`

### 5.2 Context Assembler（上下文组装）

注入顺序建议：

1. 系统角色与安全约束  
2. 工作区路径、技术栈提示  
3. **项目指令（Project Instructions）**：统一概念，按优先级读取
   `AGENTS.md` → 兼容读取 `CLAUDE.md` / `.cursor/rules`（只取其一，不叠加）  
4. **已启用 Skills 的说明摘要**（名称 + description，完整正文按需再 read）  
5. 最近对话与工具结果（超长则截断旧轮）  
6. 当前用户消息  

个人版 Compaction：简单策略即可——超过 N 轮或 token 预算时，把更早的对话收成一段摘要消息。

### 5.3 Builtin Tools

| 工具    | 基线风险 | 说明                                      |
| ------- | -------- | ----------------------------------------- |
| `read`  | READ     | 读文件，支持 offset/limit                 |
| `glob`  | READ     | 按模式列文件                              |
| `grep`  | READ     | 内容搜索                                  |
| `write` | WRITE    | 创建或覆盖（工作区内）                    |
| `edit`  | WRITE    | 精确 `str_replace`（工作区内）            |
| `bash`  | EXEC     | 默认 EXEC；`assessRisk` 可升级为 DANGEROUS |

路径规则：所有 FS 操作经 `resolveWithinWorkspace()`，禁止逃出工作区。

`bash` 动态升级规则：命中危险模式（`rm -rf`、`sudo`、`docker rm`、`git reset --hard`、
`git push --force`、`npm publish`、`DROP TABLE/DATABASE` 等）→ 强制 `DANGEROUS`。

### 5.4 Permission Gate（模式 × 风险等级）

#### 模式语义

| 模式 | 含义 |
| ---- | ---- |
| Plan | 只分析，不修改；仅允许 READ，可产出执行计划 |
| Ask  | 每次有副作用的操作（WRITE/EXEC/NETWORK/DANGEROUS）都询问 |
| Auto | 允许工作区内**低风险操作自动执行**（READ/WRITE + 白名单低风险命令）；高风险仍询问 |

#### 模式 × 风险决策矩阵

| 风险 \ 模式 | Plan      | Ask   | Auto                |
| ----------- | --------- | ----- | ------------------- |
| READ        | ✓ 自动    | ✓ 自动 | ✓ 自动              |
| WRITE       | ✗ 禁止    | 询问  | ✓ 工作区内自动      |
| EXEC（低风险，白名单） | 只读命令可选 | 询问 | ✓ 自动（如 `npm test`、`ls`） |
| EXEC（其他） | ✗ 禁止   | 询问  | **询问**            |
| NETWORK     | ✗ 禁止    | 询问  | **询问**            |
| DANGEROUS   | ✗ 禁止    | 询问  | **询问（不可跳过，也不可"始终允许"持久化）** |

要点：

- **Auto ≠ 任意执行命令**。自动域仅限：读文件、写工作区文件、白名单低风险命令。
- `rm -rf`、`docker rm`、`git reset --hard`、`git push`、`npm publish`、`DROP DATABASE`
  之类的 DANGEROUS 操作，**任何模式下都必须显式确认**，且默认只提供「允许一次」。
- 确认动作：`允许一次` / `始终允许（本会话）` / `拒绝`。

实现：`beforeToolExecute` 钩子；UI 通过 IPC 返回
`allow_once | allow_always_session | deny`。

### 5.5 Skills 子系统

#### 目录约定（两级来源）

```
~/.my-agent/skills/           # 全局技能（所有项目可用）
<workspace>/.agent/skills/    # 项目技能（同名时优先于全局）
```

每个技能一个目录或单文件：

```
my-review/
  SKILL.md          # 必需
```

`SKILL.md` 示例：

```markdown
---
name: review
description: 对当前改动做代码审查，关注正确性、安全与可读性
---

# 代码审查技能

1. 用 git diff / grep 了解变更范围
2. 按清单检查：边界条件、错误处理、测试
3. 输出：问题列表 + 建议修改（不要直接大范围重写，除非用户要求）
```

#### 加载与使用方式（两种，建议都支持）

| 方式         | 行为                                                         |
| ------------ | ------------------------------------------------------------ |
| **目录注入** | 启动/刷新时扫描两级 Skills，把 `name + description` 放进系统提示；模型需要细节时用 `read` 读 `SKILL.md` |
| **斜杠命令** | 用户输入 `/review` → 把该技能正文追加为高优先级指令再跑 Loop |

个人版**不要**默认执行 Skills 里的任意脚本；若未来要「可执行 skill」，单独加 `trusted: true` 与确认。

#### Skills 管理 UI 要素

每个技能卡片必须呈现：**名称、描述、来源（全局 / 当前项目）、状态（已启用/已禁用）、
触发方式（`/review`）、版本、最后修改时间**，并提供「查看 SKILL.md」「编辑」入口。

#### 与 Tool Bus 的关系

- Skills 默认是 **上下文资产**，不是工具。  
- 可选：为常用 Skill 注册伪工具 `skill_review`，内部只是注入提示（仍无额外权限）。

### 5.6 MCP 子系统

#### 职责划分

| 组件             | 职责                                                        |
| ---------------- | ----------------------------------------------------------- |
| `McpConfig`      | 读配置：command、args、env、启用列表                        |
| `McpClientPool`  | 按 server 名管理连接生命周期                                |
| `McpToolAdapter` | 把 MCP `tools/list` 转成内部 `Tool`（风险默认 NETWORK）      |
| `McpPermission`  | 首次调用确认；可按 server 配置信任级别                       |

#### 配置示例（`~/.my-agent/mcp.json`）

```json
{
  "mcpServers": {
    "filesystem-extra": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/allowed/path"],
      "enabled": true
    },
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": { "GITHUB_TOKEN": "${GITHUB_TOKEN}" },
      "enabled": false
    }
  }
}
```

#### JSON 粘贴导入（MCP 管理页必备入口）

文件配置与 UI 表单两种维护方式都保留，另提供 **「JSON 导入」** 按钮：

- 用户粘贴上面这种 `{ "mcpServers": { ... } }`（或直接粘贴内层对象）→ 解析后**批量合并**进配置，同名 server 覆盖；
- 格式与 **Claude Desktop / Cursor 的 `mcp.json` 兼容**，已有配置零成本迁移；
- 字段映射：`command + args` → stdio；`url` → sse/http；`env` 中 `${VAR}` 为占位符，真实值经钥匙串或系统环境变量注入，不落盘明文；`enabled` 决定导入后是否自动连接；
- 解析失败给出行级错误提示，不做半截导入。

#### Tools 发现（MCP 管理页必备信息）

连接成功的 server 必须展示：

```
GitHub  ● 已连接   12 个 Tools
create_issue · create_pull_request · search_repositories · …
[查看 Tools]
```

点开展示每个 tool 的名称与描述，让用户知道 **MCP 到底给 Agent 增加了什么能力**。

#### 工具命名

避免冲突：`mcp__{serverName}__{toolName}`  
UI 上可显示为 `github / create_issue`。

#### 传输

个人版优先实现 **stdio**（本地进程，最常见）。  
SSE/HTTP 传输作为第二阶段。

#### 生命周期

- 应用启动或用户点「连接」时拉起 enabled servers  
- `tools/list` 合并进 Tool Bus  
- 会话结束或禁用时 `dispose` 子进程  
- 某 server 崩溃：标记离线，不影响内置工具

### 5.7 Session Store

```
~/.my-agent/
  config.json
  mcp.json
  skills/                     # 全局技能
  sessions/{sessionId}.json
```

会话文件建议内容：`id、workspace、title、messages、plan、createdAt、model、skillIds`。  
消息中保留 `tool_calls` 与 `tool` 结果，修改记录保留 diff 与「已接受/已撤销」状态，便于回放。

### 5.8 LLM Adapter

统一 OpenAI 兼容 Chat Completions（含 `tools` / `tool_calls`），这样一套代码可接：

- OpenAI / DeepSeek / 通义兼容模式  
- 本地 Ollama（兼容接口）

需要：流式、abort、基础重试。

### 5.9 密钥托管（重要）

```
Renderer（只见掩码） → IPC → Main → OS Keychain / Electron safeStorage
```

- API Key **只在 Main 进程经安全存储读写**，Renderer 永不持有明文。
- UI 只显示掩码：`sk-••••••••••••••8F2A`，操作入口为「重新设置」。
- 原型/文档中不出现任何完整 Key 字面量；日志对 Key 脱敏。

## 6. 前端信息架构（Vue3 · 三栏工作台）

### 6.1 核心工作区布局

```
┌────────────────────────────────────────────────────────────┐
│ AgentBuddy                         DeepSeek-V3   Ask       │
├──────────────┬───────────────────────────────┬─────────────┤
│              │                               │             │
│ 代码空间     │        Agent 对话             │ 代码 / Diff │
│              │                               │             │
│ 📁 TuiChat   │ 👤 修复 JWT 登录问题          │ token.ts    │
│              │                               │             │
│  💬 JWT问题  │ 🤖 我先分析认证流程...        │ ┌─────────┐ │
│  💬 API重构  │                               │ │ -旧行   │ │
│              │ 执行计划 ✓✓✓                  │ │ +新行   │ │
│              │ ✓ grep  ✓ read  ✓ edit       │ └─────────┘ │
│              │                               │ [接受][撤销]│
│              │ ⚠ npm test                    │             │
│              │ [允许一次][始终允许][拒绝]    │             │
├──────────────┴───────────────────────────────┴─────────────┤
│  📎 文件   /review   Ask ▼                 输入...   ➤    │
└────────────────────────────────────────────────────────────┘
```

- **左栏**：全局导航 + 代码空间树（项目 → 会话）
- **中栏**：Agent 对话 + 执行计划 + Tool Trace
- **右栏**：文件树 / 代码查看 / Diff 审阅（`[接受修改]` `[撤销]`）；可折叠

### 6.2 页面清单

| 页面        | 要点 |
| ----------- | ---- |
| 首页        | 大输入框 + 技能快捷入口；**无场景分类 Tab** |
| 三栏工作台  | 如上；edit 卡片 → 右栏 Diff；bash 确认卡内联 |
| Skills      | 全局/项目筛选、来源徽标、启用开关、查看/编辑 |
| MCP         | server 列表、连接状态、**Tools 数量 + 查看 Tools** |
| 模型        | Provider/Model ID/Base URL/参数；**Key 只显掩码 + 重新设置** |
| 用量统计    | 模型 Token 消耗（请求/输入/输出/**Prompt Cache 命中率**/估算费用）、工具调用分布、**执行记录**（时间、会话、工具、对象、结果、耗时） |

用量统计是**个人回放与成本可视工具**，不是企业审计中心：Token 按会话归集、执行记录支持按会话/工具筛选即可。
缓存命中率 = 命中 Prompt Cache 的输入 Token / 总输入 Token（取自 LLM 返回的 `cached_tokens` 用量字段），
命中部分多数供应商按折扣计价，是个人用户控成本的关键指标；不支持缓存的模型显示为 0%。

## 7. IPC 契约（示意）

```ts
// Renderer → Main
agent.startSession({ workspace, model })
agent.sendMessage({ sessionId, text })
agent.abort({ sessionId })
agent.respondPermission({ requestId, decision })   // allow_once | allow_always_session | deny
diff.accept({ sessionId, changeId }) / diff.revert({ sessionId, changeId })
skills.list({ scope }) / skills.setEnabled(name, bool)
mcp.listServers() / mcp.listTools(server) / mcp.setEnabled(name, bool)
mcp.importJson({ text })                          // 粘贴 mcpServers JSON 批量合并
models.setKey({ modelId })                          // 打开密钥录入，不落 Renderer
usage.stats({ range })                              // Token / 费用 / 缓存命中率 / 工具分布
usage.records({ sessionId?, tool? })

// Main → Renderer（事件）
onStreamToken / onPlanStep / onToolStart / onToolResult
onPermissionRequest / onDiffReady / onDone / onError
```

所有跨进程数据用 **zod** 校验，避免恶意或异常 payload。

## 8. 安全基线（轻量但专业）

1. Renderer 无 Node；API 仅经 preload 白名单暴露  
2. 文件路径 workspace jail（`resolveWithinWorkspace`）  
3. `bash` 使用参数数组，避免字符串拼 shell；危险命令模式强制升级风险等级  
4. MCP 子进程：显式配置才启动；env 不写进日志  
5. API Key 存 OS Keychain / safeStorage；UI 掩码；日志脱敏  
6. Skills 只当文本指令，不默认 `eval`  
7. `maxTurns` + 单工具超时，防止失控循环  
8. DANGEROUS 操作不提供"始终允许"持久化

## 10. 端到端数据流

**示例：用户输入「修复 JWT 过期导致的登录失败」**

1. UI 发送消息；Orchestrator 组装 tools = 内置 + 已连接 MCP tools  
2. 模型先产出执行计划 → `onPlanStep` 逐步推给 UI（✓ 分析项目结构 / ✓ 定位认证模块）  
3. `grep` / `read`（READ，直接执行）→ Tool Trace 卡片  
4. `edit src/auth/token.ts`（WRITE）→ Ask 模式询问 / Auto 模式自动 →
   `onDiffReady` → 右栏 Diff 打开，用户 `[接受修改]` 或 `[撤销]`  
5. `bash: npm run test:auth`（EXEC）→ 权限卡片 `[允许一次] [始终允许] [拒绝]`  
6. 用户允许 → 执行 → 输出回灌 → 模型总结 → `onDone` → 会话落盘、执行记录写入

## 13. 设计决策摘要（ADR 风格）

| 决策        | 选择                            | 理由                          |
| ----------- | ------------------------------- | ----------------------------- |
| 概念模型    | Workspace → Session（无 Task）  | 与 Session Store 同构，符合 Coding Agent 心智 |
| 主界面      | 三栏工作台（对话 + 代码/Diff）  | Coding Agent 必须可见"改了什么" |
| 权限        | 模式 × 风险等级五档             | Auto 安全可控，危险操作无法被绕过 |
| 用量统计    | 一级入口，含执行记录与 Token 消耗 | 个人用户关心成本与回放，设置类偏好前移到输入框 |
| MCP 配置    | 文件 + 表单 + JSON 粘贴导入三通道 | 兼容 Claude Desktop mcp.json，迁移零成本 |
| 项目指令    | 统一 AGENTS.md，兼容读其他格式  | 避免 AGENTS/CLAUDE/GEMINI 碎片化 |
| 扩展模型    | Skills（知识）+ MCP（工具）分离 | 与业界一致，职责清晰          |
| Skills 形态 | Markdown 为主，全局/项目两级    | 安全、易写、易分享、可覆盖    |
| MCP 传输    | 先 stdio                        | 本地场景覆盖率最高            |
| 密钥        | OS Keychain / safeStorage       | Renderer 零接触明文           |
| 图标        | 统一线性图标（Lucide 类）       | 产品 UI 不依赖 Emoji          |
| 编排        | 单 Loop，无复杂 DAG             | 易调试，符合主流 coding agent |
| 进程        | 先内嵌 Main，接口可拆           | 个人轻量与专业演进平衡        |

## 14. 成功标准（你怎么算做完）

1. 在任意 Git 项目里能完成：「读代码 → 小改动 → Diff 审阅接受 → 跑测试」  
2. 能添加一个自定义 Skill（项目级覆盖全局同名），并用 `/name` 触发  
3. 能配置一个 MCP Server，查看其 Tools 列表，模型能调用其 tool（经确认）  
4. 刷新应用后会话与配置仍在；API Key 只以掩码出现  
5. 工作区外路径无法读写；Auto 模式下 `rm -rf` 仍会弹确认  
6. 用量统计中可按模型查看 Token 消耗、按会话/工具筛选回放执行记录
7. 粘贴一段 Claude Desktop 格式 `mcpServers` JSON 能批量导入连接器

## 15. 原型说明

随附 `原型.html` 为**高保真交互原型（Demo 层）**：所有工具执行、延迟测试、
ZIP 导入、JSON 导入、用量统计数字均为前端模拟数据，用于验证信息架构与交互流。产品实现层必须走
`Vue → IPC → Agent Core → LLM → Tool Call → Permission → 实际执行 → 结果回灌`
的真实闭环（见第 7、10 节），不得以"前端添加假卡片"的方式实现。
