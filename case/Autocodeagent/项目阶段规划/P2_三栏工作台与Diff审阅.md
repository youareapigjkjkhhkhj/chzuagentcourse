# P2 · 三栏工作台与 Diff 审阅

> 周期参考：约 1 周 ｜ 前置：P1 ｜ 产出：文件与消息状态一致的审阅体验 —— 至此达成可用 MVP

## 阶段目标

把 P1 的闭环升级为专业审阅体验：每一次代码修改可见、可接受、可撤销；命令确认内联在对话流中。P2 结束即达成《设计方案》成功标准第 1 条。

## 范围

**包含**：三栏布局落地、Diff 渲染与审阅、ChangeSet 完整撤销语义、bash 内联确认卡、代码查看右栏
**不包含**：权限模式扩展（P3）、Skills / MCP

## 工作分解

| # | 任务 | 说明 |
| --- | --- | --- |
| 1 | 三栏布局 | 左栏（导航 + 代码空间树）、中栏（对话 + Tool Trace）、右栏（文件树 / 代码 / Diff，可折叠）；顶栏二级状态条（工作区路径、git 分支） |
| 2 | Diff 事件链路 | `edit` / `write` 成功 → `onDiffReady` → 右栏自动打开对应文件 Diff；工具卡片附 `[查看 Diff]` |
| 3 | Diff 渲染 | 逐行红绿对比（删除 / 新增），支持多文件切换 |
| 4 | 接受 / 撤销 | `[接受修改]` 固化变更、消息标记已接受；`[撤销]` = `checkpoint.restore(changeId)` |
| 5 | ChangeSet 语义 | 显式建模 `modified / created / deleted / renamed` 四类；revert 逐类处理（新增→删除、删除→恢复、重命名→反向还原） |
| 6 | bash 确认卡 | EXEC 确认内联在对话流：`[允许一次] [始终允许（本会话）] [拒绝]`，等待期间状态 `awaiting_permission` |
| 7 | 文件树与代码查看 | 右栏工作区文件树；点击只读查看，行号与语法着色 |
| 8 | 执行计划呈现 | Plan Checklist 区块占位（P4 由 todo 工具驱动，本期先支持静态渲染事件 `onPlanStep`） |

## 验收条件

- [ ] 一次 `edit` 产生后，右栏自动打开 Diff；接受后文件内容与 Diff 一致、消息标记已接受
- [ ] 撤销四种场景全部正确：修改已有文件还原、新增文件被删除、被删文件恢复、重命名回退
- [ ] 撤销后再发起新编辑，快照基线正确（无脏状态串扰）
- [ ] bash 确认卡三按钮行为正确；「始终允许」同模式命令本会话内不再弹窗，重启后失效
- [ ] 右栏折叠 / 展开不影响对话流与工具执行
- [ ] 会话回放：重开会话可看到完整回合结构（AI 回复 → 计划 → 工具卡 → 结果 → 总结）
- [ ] 集成测试：mock-LLM 走完「read → edit → Diff 确认 → bash」一轮，含接受与撤销两条分支

## 交付检查点

真模型冒烟 1 次：完整修 bug → 审 Diff → 接受 → 跑测试；再故意撤销一次确认恢复正确。

**🎉 本期达成后即为可用 MVP（《设计方案》成功标准 1）。**
