# P7 · 专家团

> 周期参考：3–5 天 ｜ 前置：P4 + P5（依赖 Skills 目录与 MCP 连接器清单）｜ 产出：可创建的专家角色 + 专家专属会话

## 阶段目标

让用户把「人设 + 能力标签 + 工具/Skills 绑定子集」沉淀为可复用的专家角色：卡片式管理（Logo 上传、标签、绑定明细），点击专家进入与主界面同款的对话视图；专家会话每轮自动注入人设、只下发绑定的工具与技能，实现「受限而专注」的角色化代理。

## 范围

**包含**：Expert 持久化、会话绑定 expertId、persona 系统提示注入、工具绑定过滤（内置 + `mcp:连接器名`）、技能目录限定、专家团管理页、专家会话横幅与头像
**不包含**：专家级独立模型/权限配置（沿用全局模型与权限矩阵）、专家间协作编排（子 Agent 属后置候选）、预置专家种子（清单初始为空，由用户创建）

## 工作分解

| # | 任务 | 说明 |
| --- | --- | --- |
| 1 | Expert 类型 + zod | shared 定义 `Expert`（人设/标签/绑定清单/Logo dataURL）；`ExpertUpsertPayload` 与 MCP 图标同款 `data:image/*` 校验（§23） |
| 2 | ExpertStore | `~/.AgentBuddy/experts.json` 落盘；读写同 schema 复核；损坏/非法条目跳过不击穿启动 |
| 3 | 会话绑定 | `SessionMeta.expertId`（缺省 = 普通助理会话）；`session:create` 支持携带 expertId，随 meta 落盘 |
| 4 | persona 注入 | `systemPrompt` / `assembleContext` / `TurnDeps` 增加可选 `persona`，绑定专家的会话每轮追加人设段 |
| 5 | 工具绑定过滤 | `buildSessionBus(mcpTools, max, allow)`：内置按名匹配、`mcp:名称` 命中连接器全部工具；`todo_write` 始终保留；空 = 不限定；过滤只影响 schema 下发，权限矩阵全程生效（§14） |
| 6 | 技能限定 | ④层目录只列绑定技能；`/name` 触发受绑定硬边界（Main 侧拒绝未绑定技能）；`/` 菜单同源过滤 |
| 7 | 专家团管理页 | 卡片网格（Logo/Emoji、标签、简介、绑定徽标、会话数）+ 搜索 + 创建/编辑弹窗（Logo 上传、Emoji 快选、标签回车添加 + 预设、工具/Skills 多选 chips）+ 删除二次确认 |
| 8 | 专家会话 | 复用 ChatView（不复制对话渲染）：顶部专家横幅（返回/头像/标签/绑定明细）、assistant 头像替换；侧栏「专家会话」按专家分组归档，不混入助理会话 |

## 实现要点归档（P7）

| 层 | 关键点 |
| --- | --- |
| shared | `Expert` 类型（tools 元素 = 内置工具名或 `mcp:连接器名`；空数组 = 不限定）；`SessionMeta.expertId?`；通道 expert:list / upsert / remove；`ExpertUpsertPayload`（logo ≤150KB + `data:image/*` superRefine，MCP 图标同款）；`SessionCreatePayload`（title + expertId，session:create 由裸取参改 zod 校验） |
| agent-core/experts.ts | ExpertStore（experts.json，ConfigStore 同款 JSON 落盘）；upsert 走 `ExpertUpsertPayload.parse`（与 IPC 同一 schema，单一事实来源）；load 逐条 safeParse 净化，损坏文件回退空清单 |
| agent-core/bus | `ToolBus.unregister`；`buildSessionBus` 第三参 `allow`：内置过滤时快照 `[...names()]` 再删（Map keys 活视图，边迭代边删会漏项）；`todo_write` 豁免（计划面板依赖）；dropped 只计过滤后超上限的 MCP 工具 |
| agent-core/context + orchestrator | `systemPrompt` 第 9 可选参 persona（追加「专家人设」段）；`assembleContext.opts.persona`；`TurnDeps.persona`——Loop 无专家分支（§13），只透传配置数据 |
| main | ExpertStore 装配于 index.ts（dataDir）；ChatService 构造注入 `experts?`；ask 每轮：`latest.expertId → experts.get` → 技能目录过滤 + `/name` 绑定校验 + `buildSessionBus(mcpTools, undefined, expert.tools)` + mcpCatalog 过滤 + persona 传入 runTurn；专家已删除 = 查无此人自然回退全量 |
| preload/bridge | `expert.list/upsert/remove`；`session.create(title, expertId?)` |
| 渲染端 | ExpertsView 卡片页（搜索/创建/编辑弹窗：Logo FileReader→dataURL ≤100KB、Emoji 快选、标签回车 + 预设、工具 chips 蓝/紫、Skills chips 靛）；App.vue 导航「专家团」+ 会话按 expertId 分组（assistantSessions / expertSessionGroups）+ openExpert（恢复最近会话或新建）；ChatView 复用：`expert` prop → 顶部横幅（返回/头像/标签/绑定明细）+ assistant 头像替换 + `/` 菜单按绑定过滤 |
| 耦合边界 | agent-core 只消费 Expert 数据（不知 IPC/UI）；绑定关系唯一落点是 SessionMeta.expertId（ask 零新参数）；过滤只收窄 schema 下发与目录注入，权限矩阵/路径 jail/审阅链路原样生效；删除专家不迁移会话（悬空 expertId 即回退），零破坏性 |
