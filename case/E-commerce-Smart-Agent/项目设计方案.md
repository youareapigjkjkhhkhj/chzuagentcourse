**基于 LangGraph 与 RAG 的电商智能客服系统设计方案**  

### 1. 项目概述

本系统是一个面向电商场景的**智能客服与购物助手**，采用 LangGraph 构建有状态多智能体工作流，结合 RAG 技术实现商品与政策知识的准确问答，并支持订单查询等工具调用。

**核心目标**：
- 支持多轮对话与上下文保持
- 基于 RAG 的商品知识问答（含引用）
- 订单状态查询
- 意图智能路由与多智能体协作
- 简单售后政策引导

系统以可运行原型为目标，重点突出 LangGraph 状态管理与 RAG 落地，工作量适合本科毕业设计。

### 2. 系统总体架构

系统采用分层架构，清晰解耦：

```
┌─────────────────────────────────────────────┐
│               表现层（前端）                  │
│         Streamlit / 简单 Web 对话界面         │
└─────────────────────┬───────────────────────┘
                      │ HTTP / SSE 流式
┌─────────────────────▼───────────────────────┐
│               服务层（FastAPI）               │
│     接口封装、用户鉴权、流式响应、会话管理      │
└─────────────────────┬───────────────────────┘
                      │
┌─────────────────────▼───────────────────────┐
│          智能体编排层（LangGraph）            │
│  Supervisor + Product Agent + Order Agent    │
│  + 状态管理 + 条件路由 + Checkpointer        │
└────────────┬──────────────┬─────────────────┘
             │              │
┌────────────▼────────┐ ┌───▼─────────────────┐
│   RAG 检索模块       │ │   工具调用模块        │
│ 向量检索 + 重排 + 引用│ │ 订单查询 Tool        │
└────────────┬────────┘ └───┬─────────────────┘
             │              │
┌────────────▼──────────────▼─────────────────┐
│                 数据层                       │
│  PostgreSQL（订单、会话） + 向量库（商品知识） │
│  Redis（可选缓存）                            │
└─────────────────────────────────────────────┘
```

### 3. 功能模块设计

#### 3.1 智能体编排模块（核心）

采用 **Supervisor 模式**：

- **Supervisor Agent**：接收用户输入，进行意图分类，路由到对应专业 Agent。
- **Product Agent**：处理商品相关问题（检索、问答、简单推荐）。
- **Order Agent**：处理订单查询相关请求。
- **Knowledge Agent**（可选合并到 Product）：处理退货、运费等政策问题。

**状态定义（AgentState）**：
- messages：对话历史
- user_id / session_id
- intent：当前意图
- retrieved_docs：RAG 检索结果
- order_info：订单相关信息
- final_answer：最终回复

使用 LangGraph 的 StateGraph 实现节点跳转与条件边，支持多轮状态保持。

#### 3.2 RAG 检索模块

**知识库内容**：
- 商品信息（标题、描述、规格、卖点）
- 售后政策（退货规则、运费说明等）

**处理流程**：
1. 文档加载与切分
2. 向量化并写入向量数据库
3. 用户查询时进行相似度检索
4. （可选）简单重排
5. 将检索结果作为上下文交给大模型生成回答，并返回引用来源

**设计重点**：强制 grounded generation，减少幻觉。

#### 3.3 工具调用模块

将订单查询封装为 Tool：
- 输入：订单号或用户标识
- 输出：订单状态、物流信息等

Order Agent 在需要时自动调用该工具，并将结果整合进回复。

#### 3.4 对话与记忆模块

- 使用 LangGraph Checkpointer（内存或 PostgreSQL）实现会话持久化
- 支持多轮对话上下文保持
- 简单会话级记忆即可（不做复杂长期画像）

#### 3.5 前端与接口

- 后端：FastAPI，提供对话接口，支持流式输出
- 前端：Streamlit 快速构建对话界面，方便演示

### 4. 核心流程设计

**典型对话流程**：

1. 用户输入进入 FastAPI
2. 加载历史状态（Checkpointer）
3. Supervisor 进行意图识别
4. 根据意图路由：
   - 商品/政策问题 → Product Agent → 调用 RAG → 生成回答
   - 订单问题 → Order Agent → 调用工具 → 生成回答
5. 更新状态并返回最终回复（流式）
6. 保存会话状态

**条件路由逻辑**：
- 意图为 product / knowledge → Product Agent
- 意图为 order → Order Agent
- 其他 → 通用回复或重新路由

---

### 5. 数据设计

**结构化数据（PostgreSQL）**：
- users：用户基本信息
- orders：订单主表（订单号、状态、物流信息等）
- conversations / messages：会话与消息记录（可选）

**向量数据**：
- 商品与政策文档的 embedding
- 元数据包含 product_id、doc_type 等，便于过滤

**模拟数据**：毕业设计阶段可自行构造或使用公开电商数据集。

### 6. 技术选型

| 模块       | 技术选型                           | 说明            |
| ---------- | ---------------------------------- | --------------- |
| 智能体编排 | LangGraph + LangChain              | 核心框架        |
| 大模型     | OpenAI / DeepSeek / 通义千问等     | 可替换          |
| 向量数据库 | Chroma（推荐入门）或 Qdrant        | 轻量易部署      |
| 后端服务   | FastAPI                            | 异步 + 流式支持 |
| 前端       | Streamlit/vue3/react               | 快速演示        |
| 数据库     | PostgreSQL + SQLite（开发）        | 结构化数据      |
| 嵌入模型   | bge-small / text-embedding-3-small | 性价比高        |

---

### 7. 关键实现要点

1. **LangGraph 图构建**：明确定义节点函数与条件边，保证状态正确传递。
2. **RAG 质量**：合理切分文档，控制检索 top-k，生成时明确要求基于检索内容回答。
3. **工具调用可靠性**：订单工具做好异常处理与空结果提示。
4. **流式输出**：提升用户体验，适合演示。
5. **可扩展性**：预留添加新 Agent 或新工具的接口。

### 8. 系统测试与验证建议

- **功能测试**：覆盖商品问答、订单查询、多轮对话、意图路由等用例。
- **对比实验**：
  - 纯大模型直接回答
  - 仅 RAG
  - 完整多智能体系统
- **评价指标**：回答准确性、相关性、是否产生幻觉、响应完整性（人工评估即可）。

---

### 9. 项目边界与简化说明

为控制毕业设计工作量，本方案明确简化以下内容：
- 不做完整退货执行与支付流程
- 不做复杂风控与人工审核队列
- 不做高并发与生产级部署
- 用户画像仅做会话级简单记忆

重点保证**核心链路完整可运行**，并具备清晰的设计文档与演示效果。
