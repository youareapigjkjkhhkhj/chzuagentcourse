# 部署手册

## 1. 部署概述

### 1.1 部署目标

本手册旨在指导运维人员部署LLM Wiki知识管理平台，包括开发环境、测试环境和生产环境的部署。

### 1.2 部署架构

```
┌─────────────────────────────────────────────────────────────┐
│                      负载均衡层                              │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐      │
│  │    Nginx     │  │   HAProxy    │  │   云LB       │      │
│  └──────────────┘  └──────────────┘  └──────────────┘      │
└─────────────────────────────────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────────┐
│                      应用服务层                              │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐      │
│  │   Flask      │  │   Flask      │  │   Flask      │      │
│  │   Worker 1   │  │   Worker 2   │  │   Worker 3   │      │
│  └──────────────┘  └──────────────┘  └──────────────┘      │
└─────────────────────────────────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────────┐
│                      数据存储层                              │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐      │
│  │   MySQL      │  │   Redis      │  │   Milvus     │      │
│  │   主从       │  │   哨兵       │  │   集群       │      │
│  └──────────────┘  └──────────────┘  └──────────────┘      │
└─────────────────────────────────────────────────────────────┘
```

### 1.3 环境要求

#### 服务器配置
- **CPU**: 4核心以上
- **内存**: 8GB以上
- **磁盘**: 100GB以上 SSD
- **网络**: 100Mbps以上

#### 软件依赖
- Docker 20.10+
- Docker Compose 2.0+
- Node.js 18+ (前端构建)
- Python 3.11+ (后端开发)

## 2. 开发环境部署

### 2.1 本地开发环境

#### 2.1.1 克隆项目

```bash
# 克隆项目
git clone https://github.com/your-org/llm-wiki-platform.git
cd llm-wiki-platform
```

#### 2.1.2 启动基础服务

```bash
# 启动MySQL、Redis、Milvus
docker-compose -f docker-compose.dev.yml up -d
```

#### 2.1.3 后端环境

```bash
# 进入后端目录
cd backend

# 创建虚拟环境
python -m venv .venv

# 激活虚拟环境
# Windows
.venv\Scripts\activate

# Linux/Mac
source .venv/bin/activate

# 安装依赖（Python 3.13 需 SQLAlchemy>=2.0.31，见 requirements.txt 注释）
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple

# 配置环境变量（数据库/Milvus/OpenAI）
cp .env.example .env
# Milvus 可指向远程向量数据库，如 MILVUS_HOST=172.16.2.125

# 启动后端服务（自动建表并创建默认管理员 admin/admin123456）
python run.py
```

> 说明：项目启动即自动执行 `db.create_all()` 建表并确保管理员账户存在，**无需**执行 `flask db init/migrate/upgrade` 迁移命令。

#### 2.1.4 前端环境

```bash
# 进入前端目录
cd frontend

# 安装依赖
npm install --registry=https://registry.npmmirror.com

# 启动开发服务器
npm run dev
```

### 2.2 Docker开发环境

```bash
# 一键启动所有服务
docker-compose -f docker-compose.dev.yml up -d

# 查看服务状态
docker-compose -f docker-compose.dev.yml ps

# 查看日志
docker-compose -f docker-compose.dev.yml logs -f

# 停止服务
docker-compose -f docker-compose.dev.yml down
```

### 4.1 生产环境配置

```yaml

    build:

      - CELERY_RESULT_BACKEND=redis://redis:6379/2
      - OPENAI_API_KEY=${OPENAI_API_KEY}
      - OPENAI_BASE_URL=${OPENAI_BASE_URL}
      - JWT_SECRET_KEY=${JWT_SECRET_KEY}
    depends_on:
      - mysql
      - redis
      - milvus
    networks:
      - prod-network
    restart: unless-stopped
    deploy:
      resources:
        limits:
          cpus: '2'
          memory: 2G

  celery-worker:
    build:
      context: ./backend
      dockerfile: Dockerfile
    command: celery -A app.celery_app worker --loglevel=info --concurrency=4
    environment:
      - DATABASE_URL=mysql+pymysql://wiki_user:${DB_PASSWORD}@mysql:3306/wiki
      - REDIS_URL=redis://redis:6379/0
      - CELERY_BROKER_URL=redis://redis:6379/1
      - CELERY_RESULT_BACKEND=redis://redis:6379/2
    depends_on:
      - redis
      - mysql
    networks:
      - prod-network
    restart: unless-stopped

  # MySQL主从
  mysql-master:
    image: mysql:8.0
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD}
      MYSQL_DATABASE: wiki
      MYSQL_USER: wiki_user
      MYSQL_PASSWORD: ${DB_PASSWORD}
    volumes:
      - mysql_master_data:/var/lib/mysql
      - ./mysql/master.cnf:/etc/mysql/conf.d/master.cnf
      - ./init.sql:/docker-entrypoint-initdb.d/init.sql

      - prod-network
    restart: unless-stopped
    command: --server-id=1 --log-bin=mysql-bin --binlog-do-db=wiki

    image: mysql:8.0

      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD}
    volumes:
      - mysql_slave_data:/var/lib/mysql
      - ./mysql/slave.cnf:/etc/mysql/conf.d/slave.cnf
    depends_on:
      - mysql-master
    networks:
      - prod-network

    image: redis:7-alpine

      - prod-network
```

### 4.2 Nginx配置

```nginx
# nginx/nginx.conf
user nginx;
worker_processes auto;
error_log /var/log/nginx/error.log warn;
pid /var/run/nginx.pid;

events {
    worker_connections 1024;
    use epoll;
    multi_accept on;
}

http {
    include /etc/nginx/mime.types;
    default_type application/octet-stream;

    # 日志格式
    log_format main '$remote_addr - $remote_user [$time_local] "$request" '
                    '$status $body_bytes_sent "$http_referer" '
                    '"$http_user_agent" "$http_x_forwarded_for"';

    access_log /var/log/nginx/access.log main;

    # 性能优化
    sendfile on;
    tcp_nopush on;
    tcp_nodelay on;
    keepalive_timeout 65;
    types_hash_max_size 2048;
    client_max_body_size 50m;

    # Gzip压缩
    gzip on;
    gzip_vary on;
    gzip_proxied any;
    gzip_comp_level 6;
    gzip_types text/plain text/css text/xml application/json application/javascript application/xml+rss application/atom+xml image/svg+xml;

    # 后端服务负载均衡
    upstream backend {
        least_conn;
        server backend-1:5000;
        server backend-2:5000;
        keepalive 32;
    }

    # HTTP重定向到HTTPS
    server {
        listen 80;
        server_name wiki.example.com;
        return 301 https://$server_name$request_uri;
    }

    # HTTPS服务器
    server {
        listen 443 ssl http2;
        server_name wiki.example.com;

        # SSL配置
        ssl_certificate /etc/nginx/ssl/cert.pem;
        ssl_certificate_key /etc/nginx/ssl/key.pem;
        ssl_protocols TLSv1.2 TLSv1.3;
        ssl_ciphers ECDHE-RSA-AES128-GCM-SHA256:ECDHE-RSA-AES256-GCM-SHA384;
        ssl_prefer_server_ciphers off;

        # 安全头
        add_header X-Frame-Options "SAMEORIGIN" always;
        add_header X-Content-Type-Options "nosniff" always;
        add_header X-XSS-Protection "1; mode=block" always;
        add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;

        # 前端静态文件
        location / {
            root /usr/share/nginx/html;
            index index.html;
            try_files $uri $uri/ /index.html;
            
            # 静态资源缓存
            location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg)$ {
                expires 1y;
                add_header Cache-Control "public, immutable";
            }
        }

        # API代理
        location /api/ {
            proxy_pass http://backend;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;
            
            # 超时设置
            proxy_connect_timeout 60s;
            proxy_send_timeout 60s;
            proxy_read_timeout 60s;
            
            # 缓冲设置
            proxy_buffering on;
            proxy_buffer_size 4k;
            proxy_buffers 8 4k;
        }

        # WebSocket代理
        location /ws/ {
            proxy_pass http://backend;
            proxy_http_version 1.1;
            proxy_set_header Upgrade $http_upgrade;
            proxy_set_header Connection "upgrade";
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_read_timeout 86400;
        }

        # 健康检查
        location /health {
            proxy_pass http://backend;
            access_log off;
        }
    }
}
```

## 5. 部署脚本

### 5.1 一键部署脚本

```bash
#!/bin/bash
# deploy.sh

set -e

echo "开始部署LLM Wiki知识管理平台..."

# 检查Docker是否安装
if ! command -v docker &> /dev/null; then
    echo "错误: 请先安装Docker"
    exit 1
fi

if ! command -v docker-compose &> /dev/null; then
    echo "错误: 请先安装Docker Compose"
    exit 1
fi

# 加载环境变量
if [ -f .env.production ]; then
    export $(cat .env.production | grep -v '^#' | xargs)
fi

# 构建镜像
echo "构建Docker镜像..."
docker-compose -f docker-compose.prod.yml build

# 停止旧容器
echo "停止旧容器..."
docker-compose -f docker-compose.prod.yml down

# 启动新容器
echo "启动新容器..."
docker-compose -f docker-compose.prod.yml up -d

# 等待服务启动
echo "等待服务启动..."
sleep 30

# 健康检查
echo "执行健康检查..."
if curl -f http://localhost/health; then
    echo "部署成功！"
else
    echo "警告: 健康检查失败，请检查日志"
    docker-compose -f docker-compose.prod.yml logs
fi

echo "部署完成！"
```

## 7. 备份和恢复

### 7.1 数据库备份脚本

```bash
#!/bin/bash
# backup.sh

BACKUP_DIR="/backup"
DATE=$(date +%Y%m%d_%H%M%S)

# MySQL备份
echo "备份MySQL数据库..."
mysqldump -u root -p$MYSQL_ROOT_PASSWORD --all-databases | gzip > $BACKUP_DIR/mysql_$DATE.sql.gz

# Redis备份
echo "备份Redis数据..."
docker exec redis-master redis-cli -a $REDIS_PASSWORD BGSAVE
docker cp redis-master:/data/dump.rdb $BACKUP_DIR/redis_$DATE.rdb

# Milvus备份
echo "备份Milvus数据..."
docker cp milvus-standalone:/var/lib/milvus $BACKUP_DIR/milvus_$DATE

# 保留最近30天的备份
find $BACKUP_DIR -name "*.gz" -mtime +30 -delete
find $BACKUP_DIR -name "*.rdb" -mtime +30 -delete

echo "备份完成: $BACKUP_DIR"
```

### 7.2 数据恢复脚本

```bash
#!/bin/bash
# restore.sh

BACKUP_FILE=$1

if [ -z "$BACKUP_FILE" ]; then
    echo "用法: $0 <backup_file>"
    exit 1
fi

echo "开始恢复数据..."

# MySQL恢复
echo "恢复MySQL数据库..."
gunzip < $BACKUP_FILE/mysql_*.sql.gz | mysql -u root -p$MYSQL_ROOT_PASSWORD

# Redis恢复
echo "恢复Redis数据..."
docker cp $BACKUP_FILE/redis_*.rdb redis-master:/data/dump.rdb
docker restart redis-master

echo "恢复完成！"
```
