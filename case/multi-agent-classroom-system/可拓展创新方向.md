# EduAgentX 可拓展创新方向

## 一、项目定位与现有能力

EduAgentX 是"多智能体互动智能课堂"：用户输入学习主题或上传资料，系统自动规划并生成含幻灯片、讲稿、随堂测验的完整课堂，由 AI 教师（沈老师）语音授课、多位 AI 同学（林晓、陈默、苏雨）实时提问讨论，支持举手发言、白板板书与 PPTX/HTML/PDF 导出。项目当前处于"设计方案定稿 + 高保真原型完成"阶段：`设计方案.md` 已给出分层架构（Next.js 应用层 / LangGraph 编排引擎 / 能力抽象层 / 课程 DSL）、核心数据模型（课程文档、会话状态、资产库、用户进度）与三阶段实施路线；`产品原型/` 已实现 4 个 TDesign 风格页面（index 首页生成器、workbench 生成工作台、classroom 课堂播放器、settings 设置中心），仓库已引入 pptxgenjs 依赖；`项目源码/` 目录尚空，各方向按"原型已锁定交互、设计已锁定架构"的接续开发场景提出，均可在 2~4 周内产出可演示 MVP。

现有原型可复用能力：标准/研讨两种生成模式、生成任务步骤卡（解析需求→大纲→分页写作→测验→语音）、大纲树页状态（完成/编辑中/生成中/待生成）、页面属性编辑（标题/讲稿/音色/互动开关）、播放器（字幕、倍速、教具、大纲跳转）、讨论区消息操作（引用/划重点/生成笔记/+1）、举手、白板工具条、导出弹层、多模型 Provider 配置（DeepSeek 默认，OpenAI/Qwen/Kimi/自定义兼容）、语音角色与生成参数滑杆。

## 三、功能增强

### 方向 1：随堂测验即时反馈与学情总览（易 · 1~2 周）

**背景与痛点**：settings「生成参数」已有"每章结束自动生成随堂测验"开关、原型大纲第四章含"随堂测验"页，但播放器只有"讲解+讨论"，测验落地后学生答完即忘、教师端看不到任何学情，与设计文档中"用户进度"数据模型的差距最大。

**创新点**：把测验做成课堂时间线上的"暂停节点"：AI 教师抛出题目→学生作答→当场判定并触发三种分支（答对快速带过 / 答错由 AI 同学陈默补充讲解 / 多错则插入一页复习）；课堂结束生成按章掌握度报告，展示在首页"最近课堂"卡片上。

**方案设计**：① DSL 增加 `quiz` 页类型：`{nodeId, question, options, answer, conceptTag, hintScript}`，生成 Skill 在每章末自动产出；② 播放器 runtime 增加 `QUIZ_START/QUIZ_SUBMIT/QUIZ_RESULT` 事件，交卷即调教师讲解分支；③ 新增表 `quiz_attempts(courseId, pageNo, userId, nodeId, option, correct, ts)` 与视图 `chapter_mastery`；④ 新增"学情总览"接口 `GET /api/courses/{id}/report`，首页卡片角标显示掌握度。

**落地步骤**：第 1 周做 DSL 节点、单题作答交互与即时反馈文案；第 2 周做答题入库、章级掌握度聚合与首页展示。

**实用价值**：自学者得到"被提问"的反馈回路而非单向听讲；培训讲师拿到每章正确率，能决定下节课重讲哪节——这是传统录播课给不了的，是"愿意用"的直接理由。

**风险与备选**：分支讲解依赖生成质量，可能答非所问——备选：先做"答题+参考答案回显"无分支版本再迭代；多选题与题干含图留到二期。

### 方向 2：可书写白板与板书时间线回放（中 · 2 周）

**背景与痛点**：classroom 白板 Tab 目前是整块静态 SVG（曲线+要点回顾+思考题），工具条（画笔/文本/图形/橡皮/同步给全班）全部是 `toast` 假动作。真实课堂里 AI 教师"边讲边写"是最有教学感的部分，原型里恰恰是空的。

**创新点**：白板数据化为笔画事件流，与讲解 timeline 绑定：播放到第 3 页 07:32 时自动重放"画出梯度下降曲线"的板书全过程；学生可跟画、可回看任意页板书；课末板书按页导出为图片/PDF。

**方案设计**：① 用 Pointer Events + SVG/canvas 实现 `WhiteboardEngine`，输出 `Stroke{boardId, tool, color, points[], pageNo, t}`；② 表 `boards` + `strokes`（含 `createdBy: teacher|student|me`），教师端生成管线可预先写入（由编排引擎在讲稿旁产出板书规划：每页 1~3 条要点笔迹）；③ 回放器按 `t` 对齐播放进度并驱动重绘，学生落笔存本地、课后可"查看教师板书"；④ 板书快照经 canvas.toDataURL 并入导出管线。

**落地步骤**：第 1 周完成笔画采集/重绘/清除与教师预设板书回放；第 2 周做板书库、按页快照导出与讨论区"引用板书"按钮。

**实用价值**：数理类内容（原型主题"机器学习入门"）极度依赖推导过程，可回放的板书把"听一遍就过"变成"随时倒带看推导"，适合需要反复理解的学生。

**风险与备选**：AI 预生成"板书笔迹"质量不可控——备选 MVP 仅支持"教师端真笔书写并同步"，AI 自动板书作为方向 4/5 的后续；多端同步见方向 10。

### 方向 3：个人学习笔记簿（易 · 1 周）

**背景与痛点**：讨论区每条消息下已有"引用 / 划重点 / 生成笔记"操作，点击却毫无反应；学习"机器学习入门"这类概念密集课程，用户亟需沉淀，而不是上完即忘。

**创新点**：三按钮打通一个本地优先的笔记库：点"划重点"收藏该消息文本并自动附上所在页号与概念标签；点"生成笔记"把本章已划重点+测验错题聚合为结构化笔记（按章小节的标题/要点/疑问），可导出 Markdown 或 PDF 讲义补充页。

**方案设计**：① 笔记库用 localStorage（原型定位单机）存 `notes/courseId/{pageNo}`，字段：文本、消息角色、conceptTag、type(highlight|qa|error)、ts；② "生成笔记"调用一个轻量组装接口（无大模型也行：按页序拼接 + 错题标注），有模型时由 AI 教师润色成"本章回顾"；③ classroom 新增"我的笔记"Tab，笔记项点击可跳回原页原消息（复用现有 `msg__quote` 跳页能力）；④ 导出复用方向 8 的 PDF 讲义渲染器。

**落地步骤**：第 1 周完成三按钮落库、笔记 Tab、跳回定位与 Markdown 导出；第 2 周（可选）接入错题聚合与润色。

**实用价值**：任何真学习场景都需要笔记；与课程页绑定的笔记比通用笔记软件少了"复制粘贴上下文"这一步，导出后可长期复习，是留存率抓手。

**风险与备选**：localStorage 易丢——备选：设计 `notes` 表接口先行、Web 端落 localStorage 缓存，后端接入时无缝切换；无需大模型依赖，稳。

## 四、智能升级

### 方向 4：页级生成状态机与版本回滚（中 · 2~3 周）

**背景与痛点**：工作台大纲树已画出"完成/编辑中/生成中/待生成"四种页状态，但全是写死的 treeData；"AI 重写此页"按钮只弹 toast。真实生成中一页失败或重写后变差，用户没有任何手段对比与找回。

**创新点**：把每页当作独立可重跑的任务单元（呼应设计文档"并行/串行生成各场景"）：任一页失败只重试该页；每次"AI 重写此页"生成版本快照，大纲树新增版本图标，展开可见新旧页 JSON 的 diff（标题/要点/讲稿/互动开关），一键回滚；修改指令可带引用定位（"把第 7 页的示例换成代码演示"）。

**方案设计**：① 分页任务由编排引擎按页产出，页状态经 SSE 推给前端（done/current/writing/wait 即现有 UI 四态）；② 新增表 `course_pages(id, courseId, chapterNo, pageNo, dsl_json, status, rev)` 与 `course_page_versions(id, pageId, rev, dsl_json, reason, model, cost, ts)`；③ 重写接口 `POST /api/pages/{id}/rewrite`：读当前 dsl_json + 用户指令 + 同章上下文（避免重写后风格跳变），输出新版本并返回结构化 diff（标题/要点数组级 diff 即可，不需文本级）；④ "发布课程"前强制版本确认列表。

**落地步骤**：第 1 周：分页任务与状态推送打通，大纲树显示真实状态；第 2 周：rewrite 接口与版本表；第 3 周：diff 视图与回滚、发布前确认。

**实用价值**：面向认真做课的人（教师、UP 主、培训师）——可控、可后悔、可对比的生成才是可用的生成；这也是后续"逐页精修"商业化工作流的地基。

**风险与备选**：diff 展示语义复杂——备选：先做"整页 JSON 新旧对照"折叠视图；重写上下文窗口成本高——仅携带同章页面摘要而非全文。

### 方向 5：材料溯源测验生成（中 · 2~3 周）

**背景与痛点**：首页"上传资料"入口与设计文档"材料解析+向量检索增强"已规划，但测验仍靠模型自由发挥——对着 PDF 讲完后出的题可能在材料之外，学员找答案时对不上号，教师不敢直接用。

**创新点**：测验生成以"材料先行"：先生成课纲、再让测验 Skill 只基于材料分块出题，每题携带 `source{fileId, chunkId, page, quote}`；题目在讨论区展示时右下角有"出处：讲义第 12 页"回链，学生点开即看原文段落。

**方案设计**：① 解析层先用免费库（PyMuPDF/pdfjs 或 textract 思路）：切块存 `material_chunks(fileId, chunkNo, page, text)`；② MVP 检索不引向量库，先做中文分词（jieba）+ BM25 关键词打分（免费、可解释、结果稳定），`material_chunks` 加倒排索引表 `chunk_keywords`；③ 测验 Skill 的 prompt 强制约束：题干必须命中 ≥2 个取自某 chunk 的考点实体，输出必带 source 字段，后端校验 source 存在否则拒收重生成；④ classroom 题目卡渲染出处徽标并支持点击跳材料预览（新抽屉页，复用上传解析器）。

**落地步骤**：第 1 周：上传/解析/分块入库与预览；第 2 周：BM25 检索与"考点抽取→组题→出处校验"链路；第 3 周：出处徽标 UI 与材料跳转抽屉。

**实用价值**：培训师拿着自家手册就能生成"讲原手册、考原手册"的课——企业内训最典型场景；教师可快速人工复核题目来源，信任门槛大幅下降。

**风险与备选**：材料 PDF 表格/公式切块效果差——备选：先支持 .md/.txt/.docx，PDF 标注为二期；材料过长时按章检索，超出预算返回"此材料太散"引导拆分。

### 方向 6：AI 同学人设库与研讨辩论（中 · 3 周）

**背景与痛点**：林晓（好问）、陈默（爱补充直觉）、苏雨（慢半拍思考）的差异目前只是三句写死的聊天记录；首页"研讨模式"提示语是"更多同学辩论与分组讨论"，但没有任何机制支撑；settings 已有"AI 同学数量/讨论激烈程度"滑杆，形同虚设。

**创新点**：同学角色人设结构化并开放配置：每个角色 = `{persona 卡(性格标签、专长学科、提问倾向、反驳概率、知识储备等级、音色、头像色)}`，用户可在设置页增删改、换人组队；"研讨模式"真正跑一个辩论子编排：从课纲抽辩题→正反立场分配→每人按人设开题→规定轮次内互驳（激烈程度滑杆映射轮次 1~4）→AI 教师仲裁总结落回讲稿笔记。

**方案设计**：① 新增 `personas` 表与 `course_agents(courseId, role, personaId, 出场章节)`；② 编排层新增 seminar 子图：`topic_select → stance_assign → debate_round(N) → arbiter_summary`，每个同学的发言前注入人设卡+立场+已发言摘要（防复读）；③ 辩论产出转成课堂段落：正反方观点合并为该章"延伸讨论"页（DSL 新 `debate` 页类型）；④ 讨论区渲染立场徽标（支持/反对/中立），沿用现有消息组件。

**落地步骤**：第 1 周：人设 schema、设置页管理 UI 与角色加入课堂；第 2 周：研讨子图与轮次控制；第 3 周：辩论总结落页、立场徽标。

**实用价值**：翻转课堂/读书会需要"有人吵起来"，教师把辩题丢给系统就能拿到一页立场充分的辩论实录作为课前材料；性格化同学也让自学用户有陪伴感而非答题机器。

**风险与备选**：辩论跑偏或互相复读——备选：限制轮次+仲裁必产出结论；人设开放可能被玩坏——加"班级默认人设集"一键复原。

### 方向 7：学习者画像与自适应节奏（难 · 4 周）

**背景与痛点**：播放器已支持倍速（1.0~2.0）、暂停、章节跳转，但这些信号用过即弃；学生"这页没懂"只有自己知道，系统不会因此放慢或复讲，学完也没有复习指引。

**创新点**：把课堂运行时行为埋点成画像，用规则引擎（不上模型）做自适应：某页回看 ≥2 次、该章测验错 ≥2 题、提问主题命中同页 → 该知识点记 `weak`；画像触发三类动作：自动建议语速档、在讲稿中插入一句"上一页的 X 我们再快速过一遍"、课后生成"我的薄弱点复习清单"（对应页链接+错题）。

**方案设计**：① 埋点事件 `page_view(pageNo, t, replayCount)/speed_change/quiz_submit/pause_replay` 入表 `behavior_events`；② 画像表 `learner_profile(userId, courseId, conceptTag, mastery, trend)`，conceptTag 复用方向 1 测验的 conceptTag 与大纲页标题（大纲即知识点结构）；③ 规则引擎为纯函数 `rules.ts`（阈值可配），输出 `adaptation{action, targetPage}`；④ 播放器监听 adaptation 建议，复习清单页聚合展示；⑤ 方向 3 笔记、方向 1 测验作为画像数据源，形成自有数据回路。

**落地步骤**：第 1 周：行为埋点与落库；第 2 周：画像聚合与阈值规则、复习清单页；第 3 周：播放器自适应动作（语速建议+插句复讲）；第 4 周：与笔记/测验数据打通与效果自测。

**实用价值**：自学者最大的痛是"不知道自己哪里没懂、学完就忘"；画像+复习清单把"感觉没懂"变成可执行的复习任务，直接对标付费学习 App 的核心留存功能。

**风险与备选**：规则误判（回看≠不懂）——备选：显式"没听懂"按钮作为高权重信号，规则默认保守；行为数据隐私——MVP 仅存本地（沿用 localStorage 模式），接口形态预留。

## 五、架构工程化

### 方向 8：统一导出管线（中 · 2~3 周）

**背景与痛点**：classroom 导出弹层承诺 PPTX/HTML/PDF 三种产物，仓库已装 pptxgenjs（`package.json` 依赖）却只用于生成项目说明 PPT；若三种导出各写一套"遍历 DSL"代码，必然三处漂移、bug 三倍。

**创新点**：定义中间表示 IR（页类型无关的树：title/body/source/asset/notes），生成侧只产出 DSL，导出侧 DSL→IR→三渲染器（PPTX 用 pptxgenjs、离线 HTML 自包含单文件、PDF 讲义=讲稿+要点+板书快照+讨论精选），任何新页类型只需补 IR 映射一次，三格式自动可用。

**方案设计**：① `export/ir.ts` 定义 IR schema；`export/dsl2ir.ts` 逐页类型映射（cover/points/figure/quiz/debate…）；② 三渲染器 `renderPptx/renderHtml/renderPdf`：HTML 产物为零外部 CDN 依赖（图标内联 SVG），双击即离线可学；PDF 走免费方案（浏览器打印服务端化：html→pdf 用 puppeteer 或 wkhtmltopdf 二选一，或先做"导出打印版 HTML 由用户 Ctrl+P"）；③ 导出任务入队并做产物尺寸与时间统计；④ 分享链接复用导出产物做静态托管。

**落地步骤**：第 1 周：IR 与 dsl2ir（cover/points/figure 三型先行）；第 2 周：PPTX 渲染器并逐页对照原型样式；第 3 周：离线 HTML + PDF 讲义，导出弹层四个入口全部接通。

**实用价值**：教师要把 AI 生成课件带进自己班级（PPTX 二次编辑）、学生要离线回看（HTML）、讲师要打印讲义（PDF）——三种真实使用场景，是课堂从"演示品"变成"可用资料"的最后一步。

**风险与备选**：PPTX 公式/复杂版式降级——备选：PPTX 输出保底为"标题+要点+图片"可靠子集；PDF 渲染引擎安装重——先交付打印版 HTML 顶替。

### 方向 9：生成流水线可观测与断点续跑（中 · 3 周）

**背景与痛点**：workbench 任务卡展示了 6 个步骤与"总进度 58%"，设计文档也强调会话可中断恢复，但无任何实现；一次 12 页的生成动辄几分钟，中途断网/超时只能从头再来，token 花费也无从核对。

**创新点**：任务卡步骤实时化并沉淀为可续跑的 job：步骤状态（done/running/waiting）来自真实事件流；每步展示耗时、token 消耗与失败重试按钮；页面刷新后重进工作台可"从第 7 页继续生成"而非重来。

**方案设计**：① 表 `gen_jobs(id, sessionId, status)` + `gen_steps(id, jobId, type, status, detail, costTokens, durationMs)`，页任务与步骤通过 jobId 关联（呼应设计文档"会话状态持久化"）；② 编排引擎每步发事件，后端经 SSE 推送到 workbench 任务卡（步骤组件即现有 `task-card` 结构）；③ 断点续跑：引擎每完成一页即持久化该页 dsl_json，恢复时按页状态机（方向 4 的表）从首个 waiting 页续跑；④ 课程会话页展示本次生成总 token/耗时，可选阈值告警（对接方向 11 成本预算）。

**落地步骤**：第 1 周：job/steps 落库与 SSE 推送，任务卡接真实状态；第 2 周：步骤级重试与失败原因回显；第 3 周：断点续跑与 token/耗时统计。

**实用价值**：对长期创作者是实打实的成本与耐心保护——几分钟的长任务可中断恢复是"真能用"的门槛；token 透明化也为后面的机构计费（方向 11）打好地基。

**风险与备选**：SSE 断连重放逻辑复杂——备选：MVP 用前端 3s 轮询 `GET /jobs/{id}`，事件表按 seq 增量拉取即可。

## 六、落地商业化

### 方向 10：同步共学房间（中 · 3 周）

**背景与痛点**：生成的课堂目前只有一人能"看"，classroom 顶栏"在线 5"是假象；而真实小班场景（老师带 5~10 个学生线上自习、考研小组共学）需要所有人同频：同一页、同一条字幕、能举手提问，而不是各自开一个课堂。

**创新点**：课堂可"开播"成房间：房主（AI 教师扮演者，或主讲教师）进入播放器点"开播"，获得房间号/分享链接；加入者浏览器同步当前页、字幕、板书回放与讨论消息；提问走"举手→点名"队列（复用原型举手按钮），AI 教师或真人房主点名后发言广播全房间。

**方案设计**：① 表 `rooms(id, courseId, ownerId, state{pageNo, playing, t}, createdAt)`；② 同步协议：房主端把播放器状态事件（换页/播放暂停/倍速/板书 strokes）写入 `room_events` 表，客端轮询增量（3s，周期内无事件则轻量心跳），MVP 不引入 WebSocket 也可跑通，二期换 WS；③ 举手入队 `raise_queue(roomId, userId, ts)`，点名由房主/AI 教师触发，发言作为普通课堂消息广播（复用讨论区组件）；④ 加入房间鉴权先用 6 位房间码（本地部署无账号体系前够用）。

**落地步骤**：第 1 周：rooms 建表、开播/加入与翻页/播放状态同步；第 2 周：举手点名队列与发言广播；第 3 周：字幕/板书同步、房间码与离开清理，压测 10 人内延迟。

**实用价值**：培训讲师可直接用 AI 生成的课堂"上课"，学生端零安装进浏览器即可，省去讲师重新做 PPT 的时间；自习小组获得"有人陪我一起学"的共学场——原型本就有的"举手/点名/在线数"此时才真正活起来。

**风险与备选**：AI 语音在客端播放与字幕不同步——备选：MVP 客端只同步字幕文本（TTS 播放放二期，或仅房主出声）；真人房主缺席时由 AI 教师自动点名，规则同方向 7。

### 方向 11：机构侧部署与合规管理端（难 · 4 周+）

**背景与痛点**：设计文档已承诺站点访问码、SSRF 防护、沙箱、审计日志与 Docker 部署，但离"学校/企业采购"还差两层：管理员看不到谁在跑什么课、花了多少 token；机构对生成内容有红线（课程材料不允许出现的内容需要兜底过滤）。

**创新点**：交付一个面向机构管理员的管理端：站点访问码+成员课堂配额、token 成本看板（复用方向 9 统计）与月度预算告警、课堂模板库（管理员预审通过的优秀课堂全校复用）、生成内容合规过滤（自定义敏感词表 + 对教师/学员可见性开关），全部本地部署（复用 settings 的自定义 OpenAI 兼容接口即可接 ollama 等本地模型，成本为零）。

**方案设计**：① 表 `org_members(userId, role, quota)`、`templates(courseId, orgId, status=approved)`、`audit_logs`、`cost_budgets(orgId, period, limitTokens)`；② 管理端为独立路由 `/admin`（沿用 TDesign 风格与 header 导航），页签=成员/成本/模板/过滤词；③ 合规过滤做成生成链路的可插拔中间件：输出文本过敏感词与模型内容策略，命中即整段重生成并记 `audit_logs`（重生成比后置打码保真）；④ 部署文档补 `docker-compose.admin.yml`。

**落地步骤**：第 1 周：访问码与成员角色（管理员/教师/学员）、配额与登录拦截；第 2 周：成本看板与预算告警（复用 gen_jobs 的 token 统计）；第 3 周：模板库审批流 + 管理端预审通过课堂可在首页"官方课堂"区展示；第 4 周：过滤中间件与审计日志、Docker 编排与部署文档。

**实用价值**：高校教育技术中心/企业培训部采购 AI 课堂工具的第一问题是"预算与内容可控"，此方向把个人玩具变成可立项系统；模板库让先做好课的教师变成全校的内容提供者，形成可持续供给。

**风险与备选**：合规需求因机构而异——备选：过滤词表与策略全部做成配置且默认关闭只留审计；管理端工作量超 MVP 时，先砍模板审批流，保访问码+成本看板+审计三项。

## 七、组合建议

- 最短路径（2~3 周出彩 Demo）：方向 1 + 方向 3 + 方向 2，全部落在播放器体验上，改动面小、演示冲击力强。
- 主线深化（推荐做 6~8 周主线）：方向 4 → 方向 5 → 方向 6 依次打通"生成可控→材料可信→互动可辩"，与设计方案三阶段路线衔接最顺。
- 商业化叙事（有机构/学校资源时）：方向 9 → 方向 10 → 方向 11，按"成本透明→多人使用→可采购"递进。
