> 版本：v1.0 ｜ 日期：2026-09-12 ｜ 状态：设计定稿

## 1. 项目一句话

EduAgentX 是**多智能体互动智能课堂**：用户输入一个学习主题或上传一份资料，系统自动规划并生成含幻灯片、讲稿、随堂测验的完整课堂；进入课堂后由 AI 教师（沈老师）语音授课、多位 AI 同学（林晓、陈默、苏雨）实时提问讨论，支持举手发言、白板板书，并可一键导出 PPTX / HTML / PDF。

**当前状态**：设计方案定稿 + 高保真原型完成（`产品原型/` 4 个页面）；**P0（工程基座）与 P1（课程生成内核）已交付** ——
首页输入主题 → 工作台六步任务卡实时跑完 → 12 页课程（大纲 / 讲稿 / 测验）落库，P0 验收 11/11、P1 验收 32 通过 / 0 不通过 / 3 跳过（离线桩）。
下一步是 P2（语音能力接入）。

## 2. 技术栈定稿

| 层次 | 选型 | 说明 |
|------|------|------|
| 前端 | **Vue 3 (SFC + `<script setup>`) + Vite + TypeScript + Pinia + Vue Router** | 4 个原型页面的直译实现 |
| UI 组件 | **TDesign Vue Next**（全局注册） | 原型已是 TDesign 风格，保持视觉一致 |
| 后端 | **Flask 3.x + Flask-SQLAlchemy + Flask-Migrate** | 应用工厂模式 + 蓝图分模块 |
| 实时通道 | **SSE**（生成进度，单向）+ **Flask-SocketIO**（课堂互动，双向） | 生成用 SSE 更简单；课堂必须双向 |
| 数据库 | **SQLite**（WAL 模式） | 单机/小班部署；ORM 隔离，后续可切 PostgreSQL |
| 语音（主） | **火山引擎 · 豆包端到端实时语音大模型**（Realtime Voice Model） | 用户选定，见 `技术实现方案.md` §5 |
| 语音（辅） | 火山引擎大模型 TTS 2.0（**双向流式 WS**）/ ASR（流式），浏览器 Web Speech API 兜底 | 降级链路；三套语音能力鉴权口径已统一为单头 `X-Api-Key` |
| 文本大模型 | **OpenAI 兼容适配器**：火山方舟 / DeepSeek / OpenAI / Qwen / Kimi / 自定义 | 默认 DeepSeek，设置页可切换 |
| 检索 | jieba 分词 + BM25（SQLite 倒排表） | 不引入向量库，可解释、零外部依赖 |
| PPTX 导出 | **pptxgenjs**（Node 侧）或 **python-pptx**（推荐，随服务一起跑） | 二选一，见 P5 |
| 部署 | Docker Compose + 单容器（Flask 同时托管 Vue 构建产物） | 见 P5 |

> ⚠️ `设计方案.md` 中标称的 Next.js / FastAPI / PostgreSQL 已被本表取代，以本表为准；架构分层思想不变。

### 2.1 一组关键数字（贯穿所有阶段的验收基线）

| 指标 | 目标 |
|------|------|
| 生成 12 页课程总耗时 | ≤ 120s（P95），单页重写 ≤ 15s |
| 课堂首次语音响应 | ≤ 2.0s（从学生提问结束到听见回答） |
| TTS 首帧延迟 | ≤ 1.5s |
| 打断响应 | ≤ 300ms（教师停止发声） |
| SSE / WebSocket 消息端到端延迟 | ≤ 500ms（局域网） |
| 并发课堂 | ≥ 20 路同时在线（单机 SQLite） |
| 首屏可交互 | ≤ 1.5s（本地） |
| 材料检索 P95 | ≤ 200ms（万级 chunk） |

## 3. 里程碑总览

```
P0 基座         → P1 生成内核    → P2 语音能力    → P3 课堂运行时
（骨架+Provider）  （三段式生成）    （TTS/ASR/实时语音） （多智能体编排+互动）
                                        │
                                        ├→ P4 工作台与材料（上传/解析/检索/会话）
                                        ├→ P5 导出与工程化（PPTX/HTML/PDF/成本/部署）
                                        └→ P6 扩展（测验学情/笔记/人设辩论/画像/共学房间）
```

| 阶段 | 名称 | 交付物一句话 | 预估 | 前置 | 状态 |
|------|------|-------------|------|------|------|
| **P0** | 工程基座与能力抽象 | 前后端跑通、数据库建好、Provider 抽象层可切换并自检 | 1 周 | — | ✅ 已交付 |
| **P1** | 课程生成内核 | 输入主题 → 12 页课程（大纲/内容/讲稿/测验）+ 实时进度 | 2 周 | P0 | ✅ 已交付 |
| **P2** | 语音能力接入 | 火山豆包实时语音 + TTS/ASR 可听可说、可打断、有兜底 | 1.5 周 | P1 |
| **P3** | 多智能体课堂运行时 | 教师授课 + AI 同学讨论 + 举手/白板/字幕/课堂记录 | 2.5 周 | P2 |
| **P4** | 工作台与材料处理 | 上传解析 → BM25 检索 → 溯源生成 → 会话可回退 | 2 周 | P1 |
| **P5** | 导出与工程化交付 | PPTX/HTML/PDF 导出 + 成本可观测 + 断点续跑 + Docker | 2 周 | P1,P3 |
| **P6** | 扩展能力（选做） | 测验学情、笔记、人设辩论、学习画像、共学房间（分 6.1~6.6 子项） | 2~6 周 | P3,P4,P5 |

**MVP 定义**：P0 + P1 + P2 + P3 完成即可演示「一键生成课堂 → AI 教师语音授课 → AI 同学讨论 → 学生举手提问」的完整闭环，约 7 周。

**可演示里程碑**：
- M1 = P0 完成（能跑起来，能看到页面）—— ✅ 已达成
- M2 = P1 完成（能生成真课程，进度是真的）—— ✅ 已达成（`python scripts/accept_p1.py`；无 Key 也可用离线桩演示）
- M3 = P3 完成（**核心演示版**，完整课堂体验）
- M4 = P5 完成（可交付版，能导出、能部署、成本透明）

## 5. 全局术语表

| 术语 | 含义 |
|------|------|
| **DSL** | 课程文档的内部描述格式（JSON），页面/元素/讲稿/测验/时间线的唯一事实来源 |
| **Page / 页** | 课堂的一页（= 一张幻灯片 + 一段讲稿 + 可选互动），DSL 的最小生成单元 |
| **Chapter / 章** | 若干页的集合，用于大纲树与掌握度聚合 |
| **Provider** | 外部能力的统一抽象（LLM / TTS / ASR / 检索 / 导出），可插拔替换 |
| **Job / Step** | 一次生成任务的作业与步骤记录，用于进度推送、成本统计、断点续跑 |
| **Session** | 课堂运行时实例（一次「上课」），承载时间线、发言队列、白板、消息 |
| **Persona** | AI 角色人设卡（教师或同学），驱动说话风格与音色 |
| **Beat** | 讲稿的一次发言单元（一句话或一段），语音合成与字幕对齐的基本单位 |
| **Stroke** | 白板的一笔（工具/颜色/点集/时间戳），板书回放的数据单元 |
| **念稿 / narration** | AI 教师口述内容，与幻灯片展示内容分离存放 |

## 6. 全局验收口径（所有阶段通用）

每个阶段的《验收条件》按以下 7 类书写，编号形如 `P1-A3`：

| 类别 | 代号 | 含义 | 判定方式 |
|------|------|------|---------|
| 功能 | `A` | 该阶段承诺的功能是否可用 | 手动走查 + 脚本 |
| 接口 | `B` | API/事件契约是否与文档一致 | 契约测试（pytest + httpx） |
| 数据 | `C` | 落库是否正确、可恢复 | 直查 SQLite 断言 |
| 性能 | `D` | 是否满足 §2.1 基线 | 计时/压测脚本 |
| 质量 | `E` | 生成内容质量下限 | 抽样人工评分（1~5 分） |
| 安全 | `F` | 鉴权、SSRF、沙箱、密钥 | 手工渗透清单 |
| 回归 | `G` | 不破坏既有功能 | `make test` 全绿 |

**验收执行规则**（强制）：
1. **每条验收条件必须可复现**：写明前置条件、操作步骤、期望结果；禁止「体验流畅」这类不可判定描述。
2. **验收人 ≠ 实现人**：每阶段结束由他人按文档逐条打勾，未通过项进入缺陷清单，不阻塞下一阶段但必须记录。
3. **阶段准入**：上一阶段的 `A/B/C/G` 四类必须 100% 通过才开下一阶段；`D/E/F` 允许 ≤2 项带条件通过（列明偿还计划）。
4. **Demo 即验收**：每阶段产出一段 ≤3 分钟的录屏或可跑脚本 `scripts/accept_p{n}.py`，一条命令回放全部 A 类验收。

## 7. 全局风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 火山引擎实时语音协议复杂（事件多/保活/优雅关闭） | P2 延期 | P0 先做 Provider 抽象与 Mock；P2 首日先跑通 `材料/python3.7_duplex_demo/` 再接入；TTS 念稿作为保底链路。协议细节已核对，见 `技术实现方案.md` §5.3-A/B |
| 讲稿含 Markdown / LaTeX 被照念 | 课堂质量事故（念出"星星"） | TTS `additions.disable_markdown_filter` **默认参数强制开启**，调用方无法关闭；数理化课另开 `latex_parser: v2`。验收 P2-A19 |
| **三条语音链路的线上编码互不相同**（TTS/ASR 二进制帧 vs 实时语音 JSON+Base64） | 误把编解码器当成通用件，重构时"顺手抽公共基类" | 每套编解码器独立封装在各自 Provider 内；TTS 的 payload 区比 ASR **多一层 `session_id` 长度前缀**，照抄必错。验收 P2-A21 / P2-A22 |
| **TTS 客户端上行帧的事件号未定**（规范只给了服务端响应侧） | 只能收不能发 | 按帧框架同源推断为 `0b0001`+flags`0b0100`+4 字节事件号，**不可照抄 ASR 号段**；P2 第 1 天抓包确认。见 `技术实现方案.md` §12 第 3i 条 |
| **实时语音会话超 10 分钟无交互被服务端释放**（错误码 `45000003`） | 学生提问突然无响应 | `volc_realtime.py` 内实现在线重建会话（WS 连接可复用）；验收 P2-A17 必须通过 |
| 端到端实时语音成本高 | 长期不可用 | 默认走「TTS 朗读讲稿」低功耗路径，实时语音仅用于学生提问对话（P2 三路径，见 `P2-语音能力接入.md` §2.1） |
| 生成内容质量不稳定 | 演示翻车 | 每类页面写死 JSON Schema + 输出校验，不合格自动重试 1 次；预置 3 门「官方示例课」兜底演示 |
| 长任务中断 | 用户流失 | P5 断点续跑；P1 起每页完成即落库 |
| SQLite 并发写锁 | 多人课堂卡顿 | WAL 模式 + 写操作串行化队列 + 读多写少设计；预留 PostgreSQL 迁移路径 |
| 版权/合规 | 不可交付 | P5 关键词过滤中间件；导出产物带「AI 生成」水印开关 |
