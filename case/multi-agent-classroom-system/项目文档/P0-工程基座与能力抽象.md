# P0 · 工程基座与能力抽象

> 前置阶段：无 ｜ 预估：1 周 ｜ 里程碑：**M1（能跑起来）**
> 目标：把前后端骨架、数据库、配置体系与 Provider 抽象层搭起来，让后续每个阶段只需「填肉」不需「改骨架」。

---

## 1. 阶段目标

一句话：**`make dev` 一条命令启动前后端，浏览器打开首页与设置页与原型一致，设置页能对每个 Provider 点「测试连接」并拿到真实结果。**

本阶段不产生任何 AI 能力，但决定后面所有阶段的开发效率。核心是两件事：
- **骨架**：Flask 应用工厂 + 蓝图 + SQLAlchemy + Alembic 迁移 + Vue3/Vite + TDesign + Pinia + Router。
- **抽象**：`providers/` 目录下的能力接口（LLM / TTS / ASR / 检索 / 导出）与注册表，业务代码只依赖接口，不依赖厂商 SDK。

## 4. 接口设计（P0 需实现）

### 4.1 健康与自检

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/health` | 返回 `{status, version, db, providers:{llm:'ready',tts:'unconfigured',...}}` |
| GET | `/api/capabilities` | 返回当前可用能力清单与所属 Provider，供前端禁用不可用入口 |

### 4.2 设置

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/settings/providers` | 服务商卡片列表（含 `configured`、`enabled`、`maskedKey`、`latencyMs`） |
| PUT | `/api/settings/providers/{id}` | 保存 API Key / Base URL / 默认模型（Key 加密落库） |
| POST | `/api/settings/providers/{id}/test` | **测试连接**：发一次 1-token 的探活请求，返回 `{ok, latencyMs, error}` |
| POST | `/api/settings/providers/{id}/enable` | 设为当前启用服务商（全局唯一） |
| GET / PUT | `/api/settings/voice` | 音色列表与当前选择、语速、起伏、ASR 开关 |
| GET / PUT | `/api/settings/generation` | 生成参数（页数 8~20 / 同学数 0~5 / 激烈度 / 讲稿详细度 / 配图 / 测验 / 白板） |
| GET | `/api/agents/roles` | 内置角色：沈老师(teacher) + 林晓、陈默、苏雨、周野、顾棠(同学，给满 5 位) |

契约示例：

```jsonc
// POST /api/settings/providers/deepseek/test  →
{ "code": 0, "message": "ok", "data": { "ok": true, "latencyMs": 320, "model": "deepseek-chat" }, "requestId": "..." }

// 未配置 Key 时
{ "code": 40201, "message": "未配置 API Key", "data": { "ok": false, "error": "missing_api_key" }, "requestId": "..." }
```

**错误码段位（全项目统一）**：`0` 成功；`4xxxx` 客户端错误（40001 参数、40101 未授权、40401 不存在、42901 限流）；`5xxxx` 服务端错误（50001 内部、50201 上游 Provider 失败、50401 上游超时）。

## 5. 数据模型（P0 建表）

P0 只建**基础表**，其余表在对应阶段以迁移方式追加。

```
users(id, name, role[teacher|student|admin], created_at)

settings_kv(key, value_json, updated_at)          # 全局设置（当前服务商、生成参数、ASR 开关）

providers(id, name, kind[llm|tts|asr], base_url, api_key_enc, default_model,
          enabled, configured, extra_json, updated_at)

voice_profiles(id, name, provider, voice_type, gender, style, sample_url, builtin)

agent_roles(id, code, name, role[teacher|student], avatar_color,
            persona_json, voice_profile_id, builtin)

courses(id, title, topic, cover_json, status[draft|generating|ready|failed],
        page_count, duration_min, owner_id, dsl_json, created_at, updated_at)

course_pages(id, course_id, chapter_no, page_no, kind, title, status,
             dsl_json, rev, created_at, updated_at)
```

约束与索引：
- `courses.owner_id → users.id`；`course_pages.course_id → courses.id`（`ON DELETE CASCADE`）。
- 唯一索引：`courses(title, owner_id)` 非强制；`course_pages(course_id, page_no)` 唯一。
- 所有表含 `created_at/updated_at`，时间统一存 UTC ISO8601 字符串。
- SQLite 开启 `PRAGMA journal_mode=WAL`、`foreign_keys=ON`、`busy_timeout=5000`。

## 6. Provider 抽象层设计

```python
# providers/base.py（示意）
class LLMProvider(ABC):
    name: str
    @abstractmethod
    def chat(self, messages: list[dict], *, model=None, temperature=0.7,
             stream: bool = False, json_schema: dict | None = None) -> LLMResult: ...
    @abstractmethod
    def test(self) -> ProbeResult: ...        # 探活，返回延迟与错误

class TTSProvider(ABC):
    @abstractmethod
    def synthesize(self, text: str, *, voice: str, speed: float = 1.0,
                   fmt: str = "mp3") -> TTSResult: ...
    @abstractmethod
    def stream(self, text: str, *, voice: str, **kw) -> Iterator[bytes]: ...
    @abstractmethod
    def list_voices(self) -> list[Voice]: ...

class ASRProvider(ABC):
    @abstractmethod
    def transcribe(self, audio: bytes, *, fmt="wav", lang="zh") -> ASRResult: ...
    @abstractmethod
    def stream(self, audio_iter, *, lang="zh") -> Iterator[ASRSegment]: ...
```

`registry.py` 提供 `get_llm(name)` / `current_llm()` / `get_tts(name)`，按 `settings_kv` 中当前启用项解析实例。**业务代码禁止直接 import 厂商 SDK**，一律走 registry（用 ruff 自定义规则或 code review 保证）。

P0 阶段 LLM 只需实现 `openai_compatible.py` 一个实现类即可覆盖 DeepSeek / OpenAI / Qwen / Kimi / 火山方舟 / 自定义（差异只在 `base_url` 与模型名）。

## 7. 前端设计要点

- **设计令牌**：把原型配色固化为 CSS 变量，并覆盖 TDesign 主题：`--brand: #B98A5A`（主棕）、`--brand-2: #6E8F5E`（绿）、`--brand-3: #8A7BB0`（紫）、`--bg: #FBF7EE`（米白）、`--card: #F4EDE0`、`--ink: #3D3730`、`--sub: #6B6457`、`--line: #D9CCB9`。
- **Pinia store**：`settingsStore`（服务商/音色/生成参数）、`userStore`（当前用户，P0 用固定本地用户）。
- **api/client.ts**：axios 实例，统一注入 `X-Request-Id`、统一解包 `{code,message,data}`、`code!==0` 时抛业务异常并 toast。
- **设置页交互**：
  - 服务商卡片点击「配置」→ 抽屉表单 → 保存后卡片状态与「延迟 xxx ms」刷新。
  - 「测试连接」请求中显示 loading，成功后显示 `✓ 已连接 · 320ms`，失败显示红色原因（如 `401 invalid api key`）。
  - 滑杆拖动实时显示数值；「保存设置」批量提交，成功 toast「设置已保存」。
- **占位页**：工作台/课堂演示页 P0 只渲染空状态与「待 P1/P3 实现」说明，保证路由与导航可用。

## 9. 风险与对策

| 风险 | 对策 |
|------|------|
| TDesign 主题覆盖与原型配色不一致 | 先用令牌覆盖关键组件（Button/Card/Slider/Tag），跑一次 4 页面视觉走查再进 P1 |
| 五家 Provider 接口差异（如 Qwen 的 `dashscope`） | 统一走 OpenAI 兼容协议，差异只在 `base_url`；个别不兼容处用子类覆写 |
| SQLite 在 P3 多路课堂下写锁 | P0 起就开启 WAL + 写队列封装（`db_write(fn)`），避免 P3 返工 |
| 过早引入 WebSocket 复杂度 | P0 只装 `Flask-SocketIO` 依赖不启用，P3 才启用 |
