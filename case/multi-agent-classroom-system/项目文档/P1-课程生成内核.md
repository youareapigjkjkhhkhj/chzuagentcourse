# P1 · 课程生成内核

> 前置阶段：P0 ｜ 预估：2 周 ｜ 里程碑：**M2（能生成真课程）**
> 目标：把「输入一个主题」变成「一门结构完整、内容真实、进度可见的课程」，并落库可复用。

---

## 1. 阶段目标

一句话：**在首页输入主题 → 工作台看到真实的六步任务卡逐步完成 → 12 页课程带大纲、讲稿、测验写入数据库 → 刷新页面课程仍在。**

本阶段是产品的价值内核（生成），也是后面所有阶段的输入。质量与稳定性优先于速度：宁可慢 30 秒，也不要生成半门课。

## 3. 生成管线（核心设计）

### 3.1 三段式

```
主题/材料 ─┬─► S1 需求解析（受众、难度、时长、章节数、风格）
           │        └─► audience_profile JSON
           ├─► S2 课程大纲（章 → 页标题列表）        ← 可暂停等用户确认
           │        └─► outline JSON（含每页 kind 预分配）
           └─► S3 分页内容（逐页/并按章并行）
                    ├─ 页内容 + 讲稿（必须）
                    ├─ 测验题（章末，开关控制）
                    └─ 讨论问题（章末，开关控制）
```

- **为什么大纲先行**：一次性生成 12 页质量会显著下降，且无法干预；先大纲后分页让「生成可控」这件事从 P1 就成立。
- **并发度**：每页一次 LLM 调用，按章分组，默认并发 3（`GEN_CONCURRENCY`），避免触发上游限流。
- **上下文控制**：每页生成时携带：受众画像 + 完整大纲（仅标题）+ 前一页要点摘要（防重复）+ 本章已生成页摘要。**不带全文**，控制 token。
- **幂等**：每个 `(course_id, page_no)` 生成前先查是否已有成功版本，有则跳过（断点续跑基础）。
- **图示与公式靠提示词教，不靠后处理猜**（2026-09-13）：S3 的提示词里带一页
  `_VISUAL_SPEC_GUIDE` —— 三种图的 `spec` 怎么写、表达式白名单
  （`sin cos exp log sqrt …` 与 `pi e`）、`params` 滑块怎么给、LaTeX 认哪一小撮。
  模型给的是**结构化 spec**，渲染是服务端的事；顺着这条线，模型写不出「画个漂亮的图」
  这种没法兑现的需求（`schema._visual` 拿到不认识的 spec 时退回文字描述，不留空框）。

### 3.2 页面类型（DSL `kind`）

| kind | 用途 | 生成要求 |
|------|------|---------|
| `cover` | 封面 | 标题、副标题、讲师角色、时长 |
| `outline` | 课程大纲页 | 章节列表 |
| `concept` | 概念讲解（主力页型） | 标题、副标题、3~5 要点、讲稿、视觉描述 |
| `figure` | 图示/示意图 | 图类型描述 + **结构化的图示规格**（`visual.spec`：节点网格 + 箭头），后端据此确定性渲染成 SVG 存进 `visual.svg`；画不出来就只剩描述 |
| `example` | 案例/例题 | 场景、步骤、结论 |
| `code` | 代码演示 | 语言、代码块、逐行讲解 |
| `quiz` | 随堂测验 | 题干、选项、答案、解析、概念标签 |
| `summary` | 章节小结 | 要点回顾 + 思考题 |
| `debate` | 研讨页（研讨模式） | 辩题、正反观点（P6.4 完整化，P1 只出静态文案） |

### 3.3 DSL 结构（课程文档 = 唯一事实来源）

```jsonc
{
  "version": "1.0",
  "meta": { "title": "机器学习入门", "topic": "…", "audience": "…",
            "durationMin": 25, "mode": "standard", "cover": { "…" } },
  "chapters": [
    { "no": 1, "title": "绪论", "pages": [7, 12] }
  ],
  "pages": [
    {
      "pageNo": 7, "chapterNo": 3, "kind": "concept",
      "title": "3.2 梯度下降法",
      "subtitle": "GRADIENT DESCENT — 如何找到最低点",
      "bullets": [
        { "text": "梯度方向是最陡上升方向，取负即下降", "emphasis": ["梯度方向"] },
        {
          "text": "记住结论 $w_{t+1} = w_t - \\eta \\nabla L$ ，再看它是怎么来的",
          "pieces": [
            { "kind": "text", "text": "记住结论 " },
            { "kind": "math", "text": "w_{t+1} = w_t - \\eta \\nabla L", "svg": "<svg …>" },
            { "kind": "text", "text": " ，再看它是怎么来的" }
          ]
        }
      ],
      "narration": [
        { "beatId": "p7-b1", "text": "我们先看一个直觉……", "estSec": 12 },
        { "beatId": "p7-b2", "text": "学习率决定了每一步走多远", "estSec": 8 }
      ],
      "visual": {
        "type": "plot",
        "desc": "学习率不同，收敛的快慢不一样",
        "spec": {
          "kind": "plot",
          "title": "损失随迭代下降", "xlabel": "迭代步", "ylabel": "损失",
          "xrange": [0, 20], "yrange": [0, 1.2],
          "curves": [{ "expr": "exp(-k * x)", "label": "损失", "color": "#2F6BE4" }],
          "params": { "name": "k", "label": "学习率", "values": [0.1, 0.3, 0.6, 1.0] }
        },
        "svg": "<svg …>（后端按 spec 渲染，前端与三份导出直接用）</svg>",
        "frames": [
          { "value": 0.1, "svg": "<svg …>" }, { "value": 0.3, "svg": "<svg …>" },
          { "value": 0.6, "svg": "<svg …>" }, { "value": 1.0, "svg": "<svg …>" }
        ],
        "params": { "name": "k", "label": "学习率", "values": [0.1, 0.3, 0.6, 1.0] }
      },
      "interaction": { "askAtEnd": true, "allowFreeChat": true },
      "quiz": null,
      "boardPlan": [{ "tool": "curve", "desc": "画出损失曲线", "atBeat": "p7-b2" }],
      "meta": { "model": "deepseek-chat", "tokens": 1832, "generatedAt": "…" }
    }
  ]
}
```

- `narration` 按 **beat** 切分（一句话一个 beat），因为 P2 语音、P3 字幕、白板时间线都以 beat 为最小对齐单位。
- `estSec` 用于估算课时总长与播放进度。
- **`visual` 三种图共用一个结构**（流程图 `diagram` / 曲线图 `plot` / 公式 `formula`，`kind` 认不出来时按 `curves`、`tex` 这些字段猜）：`spec` 是模型给的结构，`svg` 是服务端按 `spec` **确定性渲染**出来的那一张。前端不画图，只显示 —— 这样工作台预览、课堂舞台与三份导出拿的是同一份字节，「同一门课两个样子」在结构上就不可能发生（见 §3.4）。
- `frames` / `params` 只有**带可调参数的曲线图**才有：`params.values` 的每个取值预渲染一帧，前端拖滑块只是换一张已经画好的图，浏览器里没有求值器（不把 `plot` 的表达式语义抄第二份）。
- `pieces` 只有**带行内公式的要点**才有：`$…$` 里的 LaTeX 在生成时就排好成 SVG 落库，前端按块贴进那一行。拼起来等于 `text`（排不出来的式子退回原文）—— 前端按 `pieces` 渲染、不按 `text`，否则屏幕上会带着美元号。
- **`chapterNo = 0` 是开篇与收尾**：封面/大纲页与章末小结都挂 0 章，大纲树按 `FRONT_KINDS`（cover/outline）把它们分成 `front` 与 `back` 两段返回 —— 两者在工作台左列一上一下，混成一段就渲染不出「开篇在上、小结在下」的顺序（`store.outline_tree`）。
- **`meta.durationMin` 是「这节课排多长」**（受众画像给的，也就是课程卡上那个数），课程行的 `duration_min` 取它；讲稿秒数回答的是另一个问题（「照念一遍要多久」），单独记在 `dsl.meta.narrationSec`，P2 的语音合成按它排时长。没有封面页时（生成到一半、或大纲里没排它）才退回讲稿值 —— 卡片上写「0 分钟」比写「4 分钟」更像坏了（`store._duration_min`）。

### 3.4 图示与课堂交互（2026-09-13）

一页的图有三种，都由**服务端渲染**（`services/generation/`）：

| 类型 | 模块 | 交互 |
|------|------|------|
| `diagram` 流程图 | `diagram.py` | **逐拍揭示**：节点与边都带 `data-beat`，讲稿讲到第几拍就亮到第几层 |
| `plot` 曲线图 | `plot.py` | **可调参数**：带 `params` 时预渲染每一帧，页面上出滑块 + 播放 |
| `formula` 公式 | `formula.py` | 主图整页居中；行内 `$…$` 贴进要点那一行 |

三条纪律，都是为了让「交互」和「导出」不打架：

1. **交互不进 SVG。** `ir._svg_of` 拒收带 `script` / `on*=` / `javascript:` 的 SVG，图上挂不了脚本；滑块与揭示都由 Vue 层挂在容器上（`PageSlide.vue`），`data-beat` 只是个属性，过得了那道闸。所以同一份 `svg` 既能内联进网页，又能栅格化进 PDF、当图片进 PPTX。
2. **不在浏览器里重算。** 每一帧、每一截行内公式都是生成时排好的。前端要是自己求值，就得把 `plot` 的表达式语义、`formula` 的排版规则各抄第二份，网页和产物早晚分叉。
3. **导出取静态帧。** PDF / PPTX / 导出的 HTML 用的都是 `visual.svg`（参数取默认值那一帧）。交互只活在页面里 —— 课件是给人回去看的，不是给人拖的。

行内公式的**字号是同一个常量**（`formula.INLINE_SIZE`）：生成时写进 DSL 用这个数，导出 HTML 排 `<img>` 也用这个数，各写各的迟早对不上。

逐拍揭示对不上层数时**兜底全显示**：`data-beat` 是图自己的层号（第几行），不一定等于这一页的拍数；讲到最后一拍一律整张亮出来，比拍数多的那几层不会永远藏着（`PageSlide.shownUpTo`）。

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/courses/generate` | 创建生成任务，body：`{topic, mode, pageCount, options}` → 返回 `{courseId, jobId}` |
| GET | `/api/courses/generate/{jobId}/stream` | **SSE** 推送进度事件（见 §4.1） |
| GET | `/api/jobs/{jobId}` | 轮询兜底：当前步骤、进度、各步耗时与错误 |

| POST | `/api/jobs/{jobId}/steps/{stepId}/retry` | 重试失败步骤 |

| GET | `/api/courses/{id}` | 课程详情：meta + chapters + pages（分页可选 `?withPages=1`） |
| GET | `/api/courses/{id}/outline` | 大纲树（工作台左侧） |
| POST | `/api/courses/{id}/outline` | 用户确认/修改大纲后提交，触发 S3 |
| GET | `/api/courses/{id}/pages/{pageNo}` | 单页详情（工作台右侧编辑区） |
| PUT | `/api/courses/{id}/pages/{pageNo}` | 人工编辑页面字段（标题/讲稿/开关） |
| POST | `/api/courses/{id}/pages/{pageNo}/rewrite` | AI 重写：`{instruction}` → 新 `rev` |
| GET | `/api/courses/{id}/pages/{pageNo}/versions` | 版本列表（为 P6.4 版本回滚预留数据结构） |
| DELETE | `/api/courses/{id}` | 删除课程（**软删**：置 `deleted_at`，列表与详情立刻看不见，页面行与版本都还在，误删可撤回） |

> **删干净是另一件事**：接口只管标记，真正连页面、版本、任务与事件一起删的是
> `store.purge_course()`（P1-C3 验的是它）。分成两条路是有意的 —— 用户在界面上
> 点「删除」时不该没有回头路，而「清库」是部署方/测试的诉求，不该挂在 HTTP 上。

### 4.1 SSE 事件契约

```
event: job.start      data: {"jobId":"j_01H…","steps":[{id,type,title}...]}
event: step.start     data: {"stepId":"s2","type":"outline","title":"生成课程大纲（4 章）"}
event: step.progress  data: {"stepId":"s3","done":7,"total":12,"pageNo":7,"pageTitle":"3.2 梯度下降法"}
event: step.done      data: {"stepId":"s3","durationMs":38000,"tokens":5120}
event: step.failed    data: {"stepId":"s3","pageNo":9,"error":"schema_invalid","retryable":true}
event: page.ready     data: {"pageNo":7,"title":"3.2 梯度下降法","kind":"concept"}
event: job.done       data: {"courseId":"c_01H…","totalMs":96000,"totalTokens":18320}
event: job.failed     data: {"error":"upstream_timeout","step":"s3"}
```

- 每个事件带单调递增 `seq`，前端断线后可用 `Last-Event-Id` 续传（P1 可先简单重连全量刷新，P5 做续传）。
- SSE 心跳每 15s 一次 `: ping`，防止代理超时断开。

```
gen_jobs(id, course_id, owner_id, status[queued|running|paused|done|failed|canceled],
         progress, total_ms, total_tokens, options_json, error, created_at, updated_at)

gen_steps(id, job_id, seq, type[parse|outline|write|quiz|tts|assemble],

          detail_json, duration_ms, tokens, error, started_at, finished_at)

                     instruction, model, tokens, created_at)
```

索引：`gen_events(job_id, seq)` 唯一；`gen_steps(job_id, seq)` 唯一；`course_page_versions(page_id, rev)` 唯一。

> `reason` 多出的第四个取值 `seed` 是 P1-7 的两门官方示例课：它们是手写素材，记成
> `generate`（没调过模型）或 `manual`（不是用户改的）都会让版本表说谎。示例课与
> 生成课**同形**是同一条底线：页面正文走同一个 `validate_page`，`dsl_json` 走同一个
> `rebuild_dsl`，落库走同一个 `store.save_page(reason="seed")` —— 前端因此不需要为
> 「两种课」各写一套渲染。

## 6. 前端设计要点

- **首页**：主题输入框回车即生成；示例主题标签点击即填入；「生成中」的课程卡片显示进度环（订阅 `/api/courses` 列表里的 `status` 与 `progress`）。从这里开出去的课都带 `confirmOutline: true`，第一个停点是工作台的大纲确认（F1-3）—— 首页是界面上唯一的生成入口，这个开关不在这儿带上，「大纲先行」就没有第二次机会。
- **工作台布局**：两列 + 一个浮框 —— 左 = 课程大纲（增删改序 + 确认），中 = 页面编辑区（预览 + **可收缩的**页面属性面板），右下 = 可折叠的「生成任务 / 对话 / 材料」弹框。任务卡与对话从原型的左栏挪进了这个浮框：大纲是要一直看着的，任务进度和对话是「有事才看」的，两类东西不该抢同一块 380px。材料抽屉（P4-G3）原先单独占一个 340px 的右栏，把中间那格挤到幻灯片只剩 840px 宽（16:9 的课件在这个尺寸上看不清），现在也并进这个浮框当第三个页签，工作台回到两列。预览宽度**吃满中栏**（`flex: 1`，`PageSlide.page-slide`）：它不封宽度，是因为幻灯片高度由宽度算出（16:9），宽度是这一列唯一能自己长的量 —— 给死值（如 960）会在编辑区更宽时于 PPT（连同它下面的讲稿、出处）右侧留一条空白。只按剩余高度封顶（`(100vh - 300px) × 16/9`）防矮屏把讲稿顶出可视区。注意 `.wb-main__body` **不要**加 `justify-content: space-between`：上限生效时它会把属性栏推到最右，中间空出一块，正是要避免的那个观感。
- **大纲树**：`完成/编辑中/生成中/待生成` 四态由 SSE 的 `step.progress` 驱动，禁止前端写死。折叠、增章、增页、拖动调序都在这一层完成，**改动只落本地草稿**，点「确认大纲」才整棵提交（页号与状态由服务端重排）。开篇与收尾两组是系统页，不给任何编辑入口 —— 提交时它们会被服务端摘掉再补一遍（`intake.clean_outline`），在它们身上做的编辑都会石沉大海。
- **总进度**：`Σ(已完成步骤权重) / Σ权重`，权重按步骤预估耗时分配（parse 5 / outline 10 / write 60 / quiz 15 / **tts 5** / assemble 5，合计 100）。`tts` 在 P1 是 `skipped`，跳过与完成一样计入 —— 否则开了语音的课永远到不了 100%。进度必须单调递增，禁止回退（`pipeline.WEIGHTS`）。
- **页面编辑**：右侧面板绑定 `dsl_json`，改完点「保存」调 PUT；点「AI 重写此页」弹指令输入框（提供 3 个快捷指令：更通俗 / 更深入 / 换个例子）。
- **发布课程**：P1 **没有「发布」这个接口** —— 状态由管线自己走完：建课时就是 `generating`（用户刷新页面要看得见它，而不是一个只活在内存里的任务），`assemble` 步写完 `dsl_json` 时按「有没有 ready 页」定 `ready` / `failed`，用户取消则回 `draft`（没坏，只是还没写完，可以接着生成）。用户看到的就是这些步骤的结果，不需要再点一次「发布」把课程从别的状态搬过来。工作台右上角的「预览课堂」进课堂演示页：按页放映服务端已经写好的幻灯片，字幕条放这一页的讲稿，左侧大纲可跳页、翻过的打勾 —— **只读，没有语音，也没有课堂运行时**（那两件分别是 P2 与 P3 的事，页面上照实写着）。

### 10.1 原型走查：这一轮补的账（2026-09-12）

拿 `产品原型/` 的四张页面与实现对了一遍，差异按三档处理：**A 真缺陷**（功能对不上）、
**B 看着像坏了**（点得动没反应，或摆着一个永远点不动的按钮）、**C 版式细节**。
A 与 B 这一轮修完，C 有意保留（10.2 逐条记着）。

| 位置 | 原来 | 现在 |
|------|------|------|
| 课堂演示页 | 顶栏、大纲页签都在，舞台永远是空的 —— 生成好的 12 页一页也看不到 | 接上 `GET /courses/{id}?withPages` 与 `/outline`：逐页放映幻灯片，字幕条放这一页的讲稿，大纲点一下跳页、翻过的打勾。页数用服务端那份（12），不是「拉下来几页就是几页」 |
| 工作台大纲树 | 只能删页：章标题点不动、加不了页、调不了序 | 跟原型看齐：章的折叠、`+ 章节` / `+ 页`（先问标题，标题会进写页的提示词）、正文页拖动调序；改动只落本地草稿，点「确认大纲」才整棵提交 |
| 设置页 | 「模型服务」「关于」两屏也摆着「保存设置」，永远点不动 | 保存栏只出现在有草稿的两屏（语音服务 / 生成参数） |
| 首页 | hero 徽章挂着「环境 development · v0.1.0」 | 徽章换回原型那句「开源 · 多智能体 · 一键生成互动课堂」；环境与版本挪到页脚 |
| 幻灯片 | 图示类型直接印模型写的英文词（`diagram`） | 走 `utils/labels.ts` 的中文表；**表里没有的词原样显示**，不拿白名单卡自由文本，页面上不会因此空一块 |
| 首页生成入口 | —（原型是静态页，不体现） | 请求带上 `confirmOutline: true`：开出去的课先停在大纲确认点，工作台那棵树的编辑入口才有得开。原来是后端默认的 `false`（一路写完），于是确认点只活在 API 与验收脚本里；想要一路写完，现在得走 API 显式传 `confirmOutline: false`（F1-3 的「可配置自动继续」就是这个开关） |

两条实现上的取舍，写下来免得下次又绕回去：

- **编辑入口只在「大纲确认点」开着**（`tree.confirmable`，即任务 `paused`）。生成跑起来
  之后服务端一律 409（`ensure_confirmable`：「这次生成已经结束，大纲不能再改」），
  那时候还能删页就是个陷阱 —— 删了没处提交。所以拖柄、`+ 页`、`×` 都跟着这个开关走，
  而不是跟着「有没有选中一页」走。这也意味着**这个确认点必须真的走得到**：首页入口
  带上 `confirmOutline` 就是为了这件事（见上表最后一行）。
- **加了章必须自带一页**：`parse_outline` 会把没有正文页的章整章丢掉，加个空章等于没加。
  弹窗因此在加章时同时问章名与第一页的标题。同一件事的另一个面：一个章只剩测验页时，
  提交后那章也会消失（测验页是系统页，会被摘掉）—— 前端不在本地预演这条规则，
  提交后重问一次大纲，让屏幕上显示的与库里的一致。规则只有服务端一份。

### 10.2 与原型的有意差异（C 类，保留）

版式与文案级的差异，逐条记着，免得下次走查再翻一遍：

| 差异 | 原型 | 我们 | 为什么保留 |
|------|------|------|-----------|
| 课时估算 | 「约 25 分钟」（写死的样例） | 页数 × 2 分钟（12 页 → 约 24 分钟） | 数字跟着内容走才对，写死的那个数和这门课没有关系 |
