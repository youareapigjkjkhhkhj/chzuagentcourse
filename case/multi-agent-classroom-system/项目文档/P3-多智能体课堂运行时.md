# P3 · 多智能体课堂运行时

> 前置阶段：P2 ｜ 预估：2.5 周 ｜ 里程碑：**M3（核心演示版）**
> 目标：把「一门课」变成「一堂课」——AI 教师按时间线授课，AI 同学随时插话讨论，学生可举手提问、可看板书，一切实时同步。

**P3 是项目的演示核心。** 完成后即可完整演示：一键生成 → 有声课堂 → 多智能体讨论 → 举手互动 → 课堂记录回看。

---

## 1. 阶段目标

一句话：**进入课堂演示页点「开始上课」，AI 教师逐页讲解（语音+字幕+板书），林晓/陈默/苏雨在合适时机插话提问与补充，学生按空格举手提问得到回答，全程进度可暂停/跳转/回看。**

## 2. 运行时模型（核心设计）

### 2.1 课堂状态机

```
        ┌───────────────────────────────────────────────┐
        │                                               │
  idle ──► lecture ──(章末)──► quiz_wait ──► lecture     │
             │  ▲                  │                    │
             │  │                  └──► discussing      │
             │  │                                        │
             │  └────────── discussing ◄──── (同学插话/学生提问)
             │                    │
             ▼                    ▼
         board_show ──────────► paused ──► lecture
             │
             └──► ended
```

| 状态 | 行为 | 进入条件 | 退出条件 |
|------|------|---------|---------|
| `idle` | 等待开始 | 页面进入 | 用户点「开始上课」 |
| `lecture` | 教师按 beat 念讲稿，字幕推进，按 `boardPlan` 触发板书 | 自动 | beat 播完 / 章末 / 被打断 |
| `discussing` | AI 同学按人设发言，教师应答；受「讨论激烈程度」控制轮次 | 章末有 discussion 点 / 学生举手 / 教师 `askAtEnd` | 轮次用尽 / 超时（默认 90s）/ 用户点「继续讲课」 |
| `quiz_wait` | 弹出测验题，等待作答 | 遇到 `kind=quiz` 页 | 提交答案 / 跳过 |
| `board_show` | 白板回放板书笔画 | `boardPlan` 触发 | 笔画播完 |
| `paused` | 冻结时间线 | 用户暂停 / 窗口失焦（可配） | 用户继续 |
| `ended` | 课堂结束，产出课堂记录 | 最后一页结束 | — |

**单写者原则**：同一时刻只能有一个说话者（教师或某位同学）。所有发言必须经过 `SpeechScheduler`（发言队列）排队，**禁止并发发声**——这是避免音频重叠与逻辑混乱的根本约束。

### 2.2 发言调度器（SpeechScheduler）

```python
class SpeechScheduler:
    """串行发言队列：同一时刻只有一个 active speaker。"""
    def enqueue(self, turn: Turn) -> None: ...      # Turn{speakerRole, text|beats, kind, priority, ttlSec}
    def interrupt(self, reason: str) -> None: ...   # 学生举手/打断：清空低优先级队列
    def next(self) -> Turn | None: ...
```

- **优先级**：`学生提问(barge) > 教师答疑 > 同学插话(高) > 同学讨论 > 教师讲授`
- **抢占**：学生提问可抢占除 `教师答疑` 外的所有发言；被抢占的 Turn 丢弃（不补播，避免课堂拖沓）。
- **TTL**：任何 Turn 排队超过 20s 未播即丢弃，防止恢复播放后一次性蹦出 5 条过期发言。
- **两拍之间留一口气**（`CLASSROOM_BEAT_GAP`，默认 0.6s；翻页后是 `CLASSROOM_PAGE_GAP`，
  默认 1.5s）：上一拍说完了不立刻接下一句，换了幻灯片先让学生看一眼那张图。
  0 不是「快」是「赶」——两句话首尾相接，听着像念稿子而不是讲课。这个节奏由**服务端**
  定（`Turn.not_before`，`next()` 到点才放行），不是让每个客户端各播各的：刷新一下、
  换台机器进来，听到的课是同一个速度。
- **服务端的收尾计时是兜底，不是主路**：有音频的发言由客户端的 `ended` 收尾
  （它知道音频真的播完了），服务端按 `_speak_ms` 计的那一份要额外加上余量
  （`_audio_grace_ms` = `max(SPEAK_AUDIO_GRACE_MS 2.5s, 时长×25%)`：投递 + 缓冲 +
  解码 + 播放器启动，再加音频文件比清单时长长出的一截）。少了它，`speak_end`
  会先于学生的耳朵到达句尾、前端按它收声 —— **线上那堂课 47 条讲稿发言全是这么
  收尾的，一条也没等到客户端的 `ended`**，每条削掉 167~527ms。
  两个数都不是拍的：清单里的 `durationMs` 是「说到最后一个字」的时刻
  （`volc_tts._duration_ms` 取字级时间戳末位），实测 83 条音频比它长 189~941ms
  （占这一句的 4%~15%）；定值盖住短句与播放器启动，比例项盖住几十秒的答疑。
- **轮次控制**：`discussing` 状态下最大轮数 = 激烈程度映射 `{低:1, 适中:2, 高:3}`，另加一个**总时长上限**（60/90/120s 同映射）。
- **最后一句必须是老师说的**（P3-A4）：轮数用完**不是**立刻散场，老师还要再回应一次、
  收束讨论并把话头递回讲授。少了这一句，讨论会停在一个同学的话头上，下一页的讲稿接上来
  像是把话岔开了。到时长上限时不再等模型，直接收尾（讨论不能拖住课堂）。

### 2.3 插话决策（AI 同学什么时候说话）

不是随机插话，规则 + 一次轻量 LLM 判定：

1. **固定时机**：章末讨论点（P1 生成）必触发。
2. **规则触发**：页面 `kind=concept` 且本页 beat 播放过半 → 允许最多 1 位同学插话；每 3 页最多插话 1 次（防吵）。
3. **人设驱动**：由 `persona_json` 决定谁插话——林晓（好问，**提问倾向高**）、陈默（爱补充直觉，**补充倾向高**）、苏雨（慢半拍，**复述+反问**）。
4. **内容生成**：一次 LLM 调用输入 `{当前页要点 + 讲稿摘要 + 人设卡 + 最近 3 条发言}`，输出 `{speakerCode, text(≤80字), type[question|supplement|reflect], trigger}`；输出必须过敏感词与长度校验。

### 2.4 板书（boardPlan → 笔画）

- P1 生成的 `boardPlan[{tool, desc, atBeat}]` 在 P3 落地为真实笔画：由 LLM 将 `desc` 转成**简化笔画指令**（`polyline | curve | text | arrow` + 归一化坐标），存 `board_strokes`。
- 播放到 `atBeat` 时，`board_show` 状态按笔画时间轴重绘（每笔 `durMs` 默认 800ms）。
- **MVP 范围**：只做教师端预生成板书的回放 + 学生端查看；学生实时书写与同步见 P6.6。工具条（激光笔/聚光灯/画笔/橡皮）在 P3 **本地生效**：光点、光圈、笔迹都画在舞台的教具覆盖层上，不进幻灯片本体、不进 store、也不发 WS（笔迹按页存，翻页不串）。

## 4. 接口设计

### 4.1 HTTP

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/classroom/sessions` | 我正在上的课（`{items, limit}`，新的在前）—— 撞上每人上限时在这里关掉旧的 |
| POST | `/api/classroom/sessions` | 开始上课：`{courseId, mode}` → `{sessionId, wsToken, timeline}` |
| GET | `/api/classroom/sessions/{id}` | 会话状态（页号、beat 索引、状态、参与者） |
| POST | `/api/classroom/sessions/{id}/ticket` | 重签接入票据 → `{wsToken, ttlSec}`；已结束的课 40901 |
| POST | `/api/classroom/sessions/{id}/end` | 结束并生成课堂记录 |
| GET | `/api/classroom/sessions/{id}/record` | 课堂记录：字幕/消息/板书快照/测验作答 |
| GET | `/api/classroom/sessions/{id}/messages` | 消息分页（`?before=&size=`） |
| POST | `/api/classroom/sessions/{id}/raise-hand` | 举手入队 → 返回队列位置 |
| POST | `/api/classroom/sessions/{id}/quiz-submit` | 提交测验答案 → 判定与反馈 |
| GET | `/api/classroom/sessions/{id}/board/{pageNo}` | 该页板书笔画数据 |

**几条载荷口径**（HTTP 与 WS 共用同一份 service 函数，所以两边看到的是同一条事件流）：

- `POST /sessions` 返回 `{sessionId, wsToken, mode, status, timeline}`。`mode` 是
  **服务端实际用的那个**（`CLASSROOM_WS=false` 时 `auto` 会降级成 `manual`），
  前端据它决定要不要显示「手动翻页」提示；`wsToken` 只活 60 秒，拿到就建连。
- `POST /sessions/{id}/ticket` 是**同一条票据的另一张**（P3-A10/A11 的必需品）：
  票据一次性、60 秒有效，所以「刷新页面」与「断线重连」这两件事都必然要再签一张
  —— 前者手上那张随页面没了，后者那张在断开前已经核销掉了。少了这一条，前端只剩
  「重新 `POST /sessions` 开一堂新课」，而课上到一半的位置、板书、举手队列全留在
  旧会话里。**已结束的课返回 40901**（不是重开一堂课）：下课之后要接着看，走的是
  `GET /record`。
- `POST /raise-hand` 的 body 是 `{action: "raise" | "lower" | "call"}`，默认 `raise`；
  返回 `{hand, position}`（`position` 从 1 起，0 表示不在队里）。三条动作与 WS 上行的
  `hand` 是**同一批函数** —— 同一个班里有人只能走 HTTP 时（推送关掉、socket 刚断），
  两条路必须给出同一个位次。**课没开始（`idle`）时返回 40901**（P3-B4）。
- `POST /quiz-submit` 的 body 是 `{option, responseMs}`，`option` 是**整句选项文本**
  （题面 DSL 里 `answer` 就是其中一句话，判定即两句话相比），不是 `A`/`B` 键。
  返回 `quiz_result` 的载荷 `{pageNo, correct, option, answer, explain, branch,
  feedback}`（`feedback` 见 P6.1）；**答案与解析只在判完之后给** —— 下发题目时
  `quiz` 事件里没有这两个字段。**前端走的是 WS 上行 `quiz_answer`**（判定同上），
  走这条 HTTP 的是降级与脚本；两条路差的只是反馈那一句有没有声音（见 §10.2）。
- `GET /record` 读 `messages` / `board_strokes` / `quiz_attempts` 三张永不清理的表，
  **不读事件留档**（留档到顶会砍最老的十分之一，P3-C2）—— 否则一堂超过上限的课
  回看时会丢掉前半段字幕，而那正是最难重来的一段。还在上的课也能看，拿到的是「到此刻」。
- `GET /board/{pageNo}` 没有板书的页返回空数组，不是 404：「这页没有板书」与
  「这页不存在」是两件事，后者由会话可见性管。

### 4.2 WebSocket `/ws/classroom/{sessionId}`

**客户端 → 服务端**

```jsonc
{ "type": "hello",      "token": "…", "resumeFrom": {"pageNo": 7, "beatIdx": 3} }
{ "type": "play" }  { "type": "pause" }  { "type": "seek", "pageNo": 5 }
{ "type": "beat_done",  "beatId": "p7-b2" }        // 前端播放完一个 beat 上报，驱动时间线
// 服务端按 beatId 判陈旧：报的不是现在这一拍、而这个号在整条时间线上确实存在 → 丢掉
// （多标签各报一次不会让时间线多走一格）；没带 beatId 或认不出来的号一律照收 —— 宁可多走
// 一格，也不能因为一个格式把课堂卡死在某一拍上（§6、§10 第 2 条）
{ "type": "ask",        "text": "…", "mode": "voice|text" }
{ "type": "chat",       "text": "…", "target": "teacher|all" }
{ "type": "hand",       "action": "raise|lower|call" }
{ "type": "quiz_answer","option": "整句选项文本", "responseMs": 4200 }
// 与 HTTP 的 POST /quiz-submit **同一个判定**（服务端同一个 submit_quiz）。判完的
// 那条广播照走 quiz_result；差别只在 P6.1 的反馈那一句：WS 这条路有发言队列，
// 老师那句带过 / 同学那句补充讲解能带着说话人自己的嗓子里说出来，HTTP 那条够不着
// 队列，只能落一条静默消息（见 §10.2）。
// **不要再自己补一条 `beat_done`**：这一句说完（它的 `speak_end`）就是「接着往下讲」
// 的那一刻，客户端按它报一次 —— 提前报会把这句反馈当场掐断。这一档没有那句话时
// （`review`）服务端自己往下走。
{ "type": "board_sync", "pageNo": 7, "strokes": […] }
{ "type": "speed",      "value": 1.5 }
```

**服务端 → 客户端**

```jsonc
{ "type": "state",   "status": "lecture|discussing|quiz_wait|board_show|paused|ended",
                     "pageNo": 7, "beatIdx": 3, "elapsedMs": 452000, "totalMs": 1500000 }
{ "type": "speak",   "turnId": "t_…", "speaker": {"code":"teacher","name":"沈老师"},
                     "text": "…", "audioUrl": "…", "beats": ["p7-b2"], "priority": 10 }
{ "type": "speak_end","turnId": "t_…" }
{ "type": "subtitle","beatId": "p7-b2", "text": "…", "pageNo": 7 }
{ "type": "message", "msg": { "id":"…","speaker":"linxiao","type":"question","text":"…","ts":… } }
{ "type": "hand_queue", "queue": [{"userId":"u1","name":"我","ts":…}], "called": null }
{ "type": "board",   "pageNo": 7, "strokes": [{"tool":"curve","points":[…],"durMs":800}] }
{ "type": "quiz",    "pageNo": 9, "stem": "…", "options": ["…"], "conceptTag": "…" }
{ "type": "quiz_result", "pageNo": 9, "correct": true, "option": "…", "answer": "…",
                         "explain": "…", "branch": "pass|remedial" }
{ "type": "presence","online": 5, "members": [{"name":"我","role":"student"}],
                     "aiMembers": [{"code":"xiaoxiao","name":"林晓","color":"#00A870","role":"student"}] }
{ "type": "error",   "code": "…", "message": "…", "recoverable": true }
```

**契约要点**：
- 所有下行事件含单调 `seq`；客户端断线重连时带 `resumeFrom`，服务端补发缺失事件（事件留档在 `session_events`）。
- 客户端必须能处理乱序与重复（幂等：同 `seq` 丢弃）。
- 心跳 `ping/pong` 每 20s；60s 无响应则判定掉线并从在线数移除。
- **交付只有留档这一条路径**：会话逻辑只写事件（`publish`：分配 `seq`、落库），
  投递由连接层按 `seq` 增量扫留档完成（在线投递与断线补发扫的是同一份数据，
  不会出现「当场发出去的」与「存下来的」不一致）。因此 §4.1 的 HTTP 接口改了
  什么，WS 上的人自然会看到 —— 两边都只 `publish`，连接层不另建广播通道。
- `error` 是例外：它**只发给发信人**（别人的合规拦截、发言过快不该广播给全班），
  不落库、不带 `seq`。带了会坏事：客户端拿最后一个 `seq` 去重连，而一个不在
  留档里的号会让它此后一直对不上账。
- `quiz` 的题面是**平铺**的（`stem` / `options` / `conceptTag`，不套一层
  `question`）：它就是 P1 写进 `dsl.quiz` 的那几个键 + `pageNo`。**答案与解析
  不在里面**（下发前被摘掉）：把 `answer` 一起发下去，前端看一眼 network 就有答案了，
  而这道题的意义正是「学生先答，再看到解析」。两者只在 `quiz_result` 里给。
- **老师的追问走 `message` 事件的 `question` 类型，不新造事件**（2026-09-13）：
  一次答疑可能是两段式（先反问一层、学生接住再收束），追问就是讨论区里一条
  「老师提问」的消息，`quote_msg_id` 指向学生那个问题。前端不需要为它加分支 ——
  讨论区本来就按角色和类型渲染（§5.1）。

**入场与生命周期（P3-3 实现补充）**

- **两条入场路径**，二选一：
  - **URL 票据**（前端走这条）：`GET /ws/classroom/{id}?ticket=<wsToken>`。
    票据在 `accept()` **之前**核销 —— 核销不过给的是普通的错误信封（HTTP 401），
    浏览器连 101 都拿不到。
  - **`hello.token`**（协议里本来就有这个字段）：握手之后才认人，认不过先回一条
    私有 `error`，再 `close(4403)`。
  两条路都**不看请求头**：`X-Owner-Id` 谁都能改，拿它兜底等于把 P3-F1 要挡的
  那条路重新打开。
- **票据**：一次性、60s 有效、`scope = sessionId` —— **为 A 课签的票接不进 B 课**
  （用途对不上与票不对是同一句话、同一个 401，不告诉人哪一步错了）。
- **入场这道闸与「看得见这堂课吗」是两道，顺序是死的**：课号不存在 → **404**（还没走到
  票据）；票据核销不过 → **401**（票不对、过期、用过、跨课，都是这一句）；核销过了再看
  可见性 → **404**（与课堂记录页同一个口径，P3-F4）。**「票认得出来人、但这堂课不该给他看」
  这一层走 URL 这条路到不了**：签票本身就要求可见，看不见的人根本拿不到票（陌生人重签
  票据是 40401，见 P3-F1）。`hello.token` 那条路走得到 —— 握手之后才认人，认不过先回一条
  私有 `error` 再 `close(4403)`。验收钉的就是这个顺序（见 §10.2）。
- **关闭码**：`1000` 正常（下课、收摊）、`4403` 越权、`4408` 心跳判死、
  `4429` 这堂课的连接数到顶（`CLASSROOM_MAX_CONNECTIONS`）。
- **心跳是应用层的 `ping` 帧，不是 WebSocket 协议层的 ping**：协议层的 ping 由浏览器
  网络栈自动回，前端一行代码都不用写 —— 但它回答不了课堂要问的那个问题：**页面**
  还在不在（标签页被挂起时协议层照样有来有回）。前端必须回 `pong`；任何上行都刷新
  计时（`pong` 只是最常见的那一种）。`CLASSROOM_HEARTBEAT=20`、`CLASSROOM_TIMEOUT=60`。
- **`ping` 与 `error` 一样是每连接私有帧**：不广播、不落库、不带 `seq`。
- **「在线」数的是人**（P3-A12）：同一个人开两个标签页仍算在线 1；关掉一个不是掉线，
  关掉最后一个才是。连接层按「这堂课此刻还开着几条连接」对齐名单，所以不留幽灵
  在线（P3-B5）。
- **新连接不重放历史**：不带 `afterSeq` 的 `hello` 从**此刻**起收（整堂课的历史走
  §4.1 的 `GET /messages`）；带 `afterSeq` 的从断点之后接着补发，已收到过的同 `seq`
  不重发。`resumeFrom` 只用来对账，「现在讲到哪」以会话行为准。
- **下课先补完再关**：`state.status=ended`（以及最后那个 beat、`speak_end`）先发出去，
  然后才 `close(1000)`。顺序反了，前端最后看到的是「连接断了」，而不是「课下了」。
- `CLASSROOM_WS=false`：路由在握手之前就回 **HTTP 403 + 普通错误信封**
  （`code=40302`、失败原因原样放进 `data`）—— 与语音的 40201 同一个形状（P3-G3）：

  ```jsonc
  { "code": 40302, "message": "课堂推送通道已关闭（CLASSROOM_WS=false），本堂课按逐页手动翻页进行",
    "data": { "ok": false, "error": "ws_disabled", "fallback": "manual" }, "requestId": "…" }
  ```

  **不是平铺的 `{ok,error,fallback}`**（那是 40201 的 `data` 的形状，不是信封）：
  能被同一段前端代码处理的是 `code`，而 `code` 得在信封顶层才看得见。
  课堂本身照常能上，只是退到逐页手动翻页 + 文字消息。

## 5. 数据模型（P3 新增）

```
classroom_sessions(id, course_id, owner_id, mode, status, current_page_no, current_beat_idx,
                   elapsed_ms, total_ms, speed, started_at, ended_at, state_json)

session_participants(id, session_id, user_id, role[owner|member], online, joined_at, left_at)

session_events(id, session_id, seq, type, payload_json, created_at)     # 断线补发

messages(id, session_id, speaker_code, speaker_kind[teacher|student_ai|me|system],
         type[lecture|question|supplement|reflect|answer|comment|system],
         text, page_no, beat_id, audio_url, quote_msg_id, ts)

hand_queue(id, session_id, user_id, ts, called_at, status[waiting|called|done|canceled])

quiz_attempts(id, session_id, course_id, page_no, node_id,
              option[255], correct, response_ms, ts)                  # P6.1 学情聚合复用

board_strokes(id, session_id, course_id, page_no, stroke_no, tool, color,
              width, points_json, text, at_beat_id, dur_ms, author[teacher|me], created_at)
```

索引：`session_events(session_id, seq)` 唯一；`messages(session_id, ts)`；`hand_queue(session_id, status)`；`board_strokes(course_id, page_no, stroke_no)`。

**建表与后续修正的实现口径（P3-1 / P3-4，2026-09-13）**：

1. **`messages.ts` 必须严格递增，这是写入方的责任。** `utcnow_iso()` 不保证 ——
   本机 `datetime.now()` 粒度约 15.6ms，同一滴答里写的两条消息会拿到一模一样的
   ISO 串，`ORDER BY ts` 的先后就变成了「数据库碰巧怎么返回」。讲稿与字幕常是同一批
   写下来的，所以 recorder 写入前要比一下会话里上一条的 `ts`，不前进就 +1µs（P3-C1）。
2. **`board_strokes.tool` 除 §2.4 那四个（`polyline|curve|text|arrow`）外还收了
   `rect|ellipse`。** 笔画是**客户端也能发**的（`board_sync` 上行），前端教具条里有
   「图形」；少一个值不是严格，是把一次合法输入变成 CHECK 违约的 500。
3. **`board_strokes` 多一列 `text`。** §2.4 把 `text`（写字）列为四种笔画之一，
   但 §5 的表里没有一列放这个字符串。不加列，写字就只能塞进 `points_json`
   （比如约定「点的第三个元素是文字」），前端得靠猜。一列比一个约定便宜。
4. **另加四条索引**（`classroom_sessions(course_id, status)` / `(owner_id, started_at)`、
   `quiz_attempts(session_id, page_no)` / `(course_id, page_no)`）：前两条对应
   「这门课还有课在跑吗」「我最近开的课」，后两条是 P6.1 学情聚合的读路径。
   都是真实查询，不是预防性加的。
5. **`quiz_attempts.option` 存的是整句选项文本，不是 A/B 键，列宽 255。**
   题面 DSL 里 `quiz.options` 是四句话、`quiz.answer` 也是其中一句话，判定即两句话
   相比（技术实现方案 §161）。这一列最早按「选项键」想当然写成 `String(16)`，
   而示例课里最短的正确选项有 17 个字 —— 存不下，于是每道题都判错。
   P3-4 把它放宽到 255（`OPTION_MAX_CHARS`，迁移 `c3f81b0a5d7e`），
   `runtime.submit_quiz` 按这个宽度截断。**列宽不是随手写的数字，是判定能不能对上的前提。**

另：`classroom_sessions.state_json` 存状态机自己那点东西（讨论轮次、当前说话者），
**进程重启后「刷新可恢复」（P3-A10）成立与否取决于状态是否都在这一行里** ——
不许把会话状态放在 Python 对象的字段上。

### 5.1 苏格拉底式引导与思辨轨迹（2026-09-13）

一次答疑不必是「问 → 答」，可以是**两段式**：老师先反问一层，学生接住之后再收束给答案。
判据与轨迹折出来只有一份（`classroom/scaffold.py`）—— 课堂运行时（此刻该追问还是该给答案）
与课堂记录（这条链子怎么画）是两个读者，各写一份判据就会出现「课上追了两轮、记录里只画出一条」。

**不新增表、不新增消息类型、不动 CHECK 约束**，全部落在已有的 `messages` 上，只用
`quote_msg_id`（那一列本来就留着「引用上一条」的口子）：

```
学生问  ──引用──▶  老师追问  ──引用──▶  学生答  ──引用──▶  老师收束
question            question             comment             answer
speaker=我          speaker=老师          speaker=我          speaker=老师
```

于是「学生自己说了几句」这个数能从**已有数据**里数出来（`build_trails` / `stats_of`，
记录接口的 `trails` 与 `stats.thinkingTrails`）—— 不用模型打分、也不用学生填问卷。
这是「看得见的思辨行为」唯一诚实的口径：**AI 问得再漂亮也不算证据，学生说出来的才算。**

两条兜底，都好过「把学生困在问题里」：

1. **逃生阀** `wants_answer()`：学生说「直接告诉我」立刻给答案。学生要答案时被反问，
   读到的不是「老师在引导」，是「这东西坏了」。
2. **`MAX_ASKS = 1`**：只追一层，学生接住一轮就直接收束。

开关是设置页的「苏格拉底式引导」（`settings_service` 的 `socraticAnswer`，默认开）。
**读不出来按开着**：追问有逃生阀兜底，开着不会把人困住；反过来读不出来按关掉，
会让这个功能看着像没做（`roster.classmate_count()` 是相反的取法，理由见那里）。

## 6. 前端设计要点

- **单一课堂 Store**（Pinia `classroomStore`）：持有 `status / pageNo / beatIdx / messages / handQueue / board / quiz`，所有变更只能由 WS 事件驱动（**禁止本地伪造状态**，防止与后端不一致）。
- **播放器与时间线**：由后端 `state` 事件 + 前端 `beat_done` 上报构成闭环。前端不自行推进页号，只上报事实。
  服务端按上报里的 `beatId` **判陈旧**：报的不是现在这一拍、而这个号在整条时间线上确实存在 → 丢掉
  （多标签各自播完各报一次，不会让时间线多走一格）；没带 `beatId`（脚本与老客户端）或认不出来的号
  一律照收 —— 宁可多走一格，也不能因为一个新格式把课堂卡死在某一拍上（§4.2、§10 第 2 条）。
- **幻灯片上的交互**（2026-09-13，`PageSlide.vue`）：一页的图有两种玩法，都**跟着课堂的拍子走**，不是点着玩的。
  - **逐拍揭示**：讲稿讲到第几拍，图就亮到第几层。拍号从 `speak` 载荷的 `beats[0]` 来（一个 beat 一条 turn），在这一页的讲稿里查出位置 —— 前端不解析 `p3-b1` 这种串，编法是服务端的事。**只进不退**：一句讲完 `speaking` 就清空了，跟着回退的话老师一停图就缩回去一半；翻页归零重新长。
  - **可调参数**：带 `params` 的曲线图出滑块 + 播放（`frames` 是服务端预渲染的每一帧，拖动只是换图）。播放走到头就停、不循环 —— 是「演示一遍这个参数在干什么」，不是让它一直转。
  - 两条都**只在页面里**：导出的 PDF / PPTX / HTML 取的是静态帧。揭示与滑块都由 Vue 挂在容器上，不往图里塞脚本（`ir._svg_of` 也塞不进去，见 P1 §3.4）。
- **讨论区**：消息按角色渲染头像色（取自 `agent_roles.avatar_color`，我=灰），`type` 以徽标区分；「正在输入…」由 `speak` 事件前置 300ms 的 `typing` 事件驱动。名单条上真人一排、AI 同学一排（虚线框），后者就是讨论里会开口的那几位 —— 与顶栏「在线 N · AI M」同源。
- **举手**：举手后按钮变「已举手（第 2 位）」；被点名时弹出提问条并自动开始录音（走 P2 实时语音）。
- **板书**：SVG 渲染，笔画按 `points` 与 `durMs` 做路径动画；提供「回看本页板书」按钮重放。
  文字笔画（`tool=text`）**按行排**（`ClassroomBoard.vue` 的 `textBlock`）：模型给的
  文字本身是多行的（`目录\n1. …\n2. …`），而 `<text>` 不认 `\n` —— 不拆成 `<tspan>`
  就会挤成一行，起点靠右的那几笔（`[[0.78, 0.68]]`）于是只有开头几个字落在画布内，
  看着就是「白板上只有几个字」。拆行之后整块再夹回画布内，超宽的单行按估宽折行
  （中英混排按字数折不准：同样 10 个字，宽度能差一倍）。服务端那边 `clip_text`
  按行截断（`text[:80]` 会把最后一行劈成半句）。
- **断线重连**：WS 断开显示顶部灰条「连接中断，正在重连」，指数退避重试（1s/2s/4s/8s，上限 5 次），重连成功用 `resumeFrom` 恢复。
- **课堂记录页**：结束后跳转只读回顾页（字幕全文 + 消息 + 板书快照 + 我的作答），支持导出（P5）。
  页面里多一栏**「思辨轨迹」**（2026-09-13）：一次引导一条，`学生问 → 追问 → 学生答 → 收束`，
  标了收束没有（没收束的那条指出哪一页没讲清）。数据就是记录接口的 `trails`，**前端不自己折**
  —— 折法只有一份（§5.1），两边各折一次就会出现「课上追了两轮、页面上只画出一条」。

这一轮翻出来**四个真缺陷**，都不是桩的问题：

1. **多标签页状态互相看不见**（A13 一开始是红的）。每条连接有自己的运行时，而运行时手里
   那份 `ClassroomSession` 停在**入场那一刻** —— 一个标签页暂停之后，另一个标签页的
   `pause`/`speed` 还拿着旧状态去问 `require_live`，被挡成 40901，于是「暂停」按了没反应、
   倍速也不生效。修法是每条**上行**之前 `_sync()` 一次（`db.session.refresh`，只在上行做：
   连接层每 50ms 走一拍，挂节拍上就是每秒 20 次查询）。配了回归用例，并验过「把 `_sync()`
   拿掉，用例当场红（`课堂错误 code=40901`）」。
2. **多标签各报一次 `beat_done`，时间线多走一格**（A13 的同一个场景翻出来的）。两个标签
   各自播各自那一拍、谁先播完谁先报，而服务端**根本没看**上报里的 `beatId` —— 同一句被
   报两次就往前走两格，整堂课的进度会越来越快。修法是按 `beatId` 判陈旧：报的不是现在
   这一拍、且这个号在整条时间线上确实存在 → 丢掉；没带 `beatId`（脚本与老客户端）或认不
   出来的号一律照收 —— 宁可多走一格，也不能因为一个新格式把课堂卡死在某一拍上。
   前端本来有一道 `claimBeatReport`，但它只管得住**一个**标签页。
3. **章末讨论缺了老师的收尾**（A4）。§7 A4 要的形状是「同学提问 → 教师答 → 另一同学补充 →
   **教师收尾**」，而轮数一用完就散场了 —— 讨论停在一个同学的话头上，下一页的讲稿接上来
   像是把话岔开了。现在轮数用完老师再回应一次、收束讨论并把话头递回讲授（提示词里老师那
   一轮本来就是这么写的）；到时长上限时不再等模型，直接收尾。
4. **课堂票据落进了访问日志**（F1 一开始也是红的）。票据走 URL 查询串（§4.2），WSGI 服务器
   的访问日志把请求行原样记下来，而脱敏规则的关键词表里没有 `ticket`。它不是 Key，但它是
   **这堂课的钥匙**；一次性和 60 秒有效期不该变成「可以进日志」的理由。关键词表补上
   `ticket`，并加了一条喂**真实访问日志行**的单测。**没有**给票据上 `register_secret`：
   那是「已知原文」的精确替换表，按课堂数无界增长，还会让每条日志多一趟 O(n) 遍历。

脚本自己也踩了六个坑，记在这儿免得下次重踩：**请求行只能是 ASCII**（F1 拿中文课号去试，
`encode("ascii")` 当场炸掉整组检查 —— 现在按 RFC 3986 百分号编码，真浏览器也是这么发的）；
**`AuditLog.detail` 是描述符不是列**（`AuditLog.detail.like(...)` 会在子进程里抛，脚本静默
返回 0，看着像「产品漏了审计」，实际是脚本自己出错 —— 现在失败返回 -1，与「产品真的没有」
分开报）；**私有帧不在 `events` 里**（`wait("error")` 永远返回 None，得用 `pump` + `errors()`）；
**失败的现场默认会被删掉**（现在 `--keep` 与「有不通过」时会把每一条连接收发的原始事件
全量落到 `events.log`，`ClassClient.ALL` 让主线之外的临时连接也算数）；**`-q` 会跟 addopts
叠成 `-qq`**（`pyproject.toml` 的 addopts 里已经有一个 `-q`，脚本再传一个就安静过头 ——
`-qq` 的 pytest 把最后那句「N passed in x.xxs」整个省掉，于是详情里只剩一串进度点，
`_pytest_summary()` 找不着那一句、退回取末两行，正是它要躲开的东西；要更安静去改 addopts，
别在调用处加）；**pytest 会把「整文件」这个参数折掉**（`pytest f.py f.py::test_x` 只收
`test_x`，于是 B1 那个 24 条的 WS 契约文件被数成「2 条用例全通过」—— 2 是它下面另两张单条
的票，B4 的 21 条被数成 1；现在整文件与单条分两趟跑，`_NODE_CACHE` 以节点 id 为键，
同一条用例两趟都出现也只算一次）。

### 10.1 离线跑不到的九条，接上真 Key 之后怎么补

一份操作口径，照着做就行（前三条要真上游/真时长/真浏览器，后两条要人眼）：

1. **时延与资源（D1 的 20 连接 / D4 的 45 分钟 / D5 的 200ms 渲染）**：`LLM_PROVIDER` 与三个
   语音能力都接真上游，把 `CLASSROOM_MAX_CONNECTIONS` 调高、**开 20 个标签页**进同一堂课，

   200 笔画那一下的帧耗时。
2. **人眼评分（A3b / E1 / E1b / E3 / E3b）**：同一堂课上抽 5 条插话判人设（林晓=提问 /

   LLM —— 离线替身每个角色只有三句句式库，连说十几轮必然撞句，那是桩的局限。阈值不变（≤0.8）。

### 10.2 有意差异与已知缺口（保留）

| 条目 | 规格怎么写 | 我们怎么做 | 为什么 |
|------|-----------|-----------|--------|
| `board_show` 这个状态 | 讲到有 `boardPlan` 的页时进入 `board_show`，笔画播完回 `lecture`（§2.1） | **不进这个状态**：在 `lecture` 里推一条 `board` 帧，前端按 `durMs` 逐笔重绘。`board_show` 保留在枚举与转移表里 | 板书是**一页里的一段**而不是一整页：讲稿照常在念，笔画跟着 `atBeat` 出来（A8 量的就是这个）。真插一个状态，前端要多等一次 `state` 往返才敢画，反而慢半拍。它留在枚举与转移表里，与「学生实时书写」一起归 P6.6 |
| 心跳用应用层 `ping` 帧 | 「心跳 `ping/pong` 每 20s」 | 不用协议层 ping，用**应用层**的 `ping` 私有帧，且任何上行都刷新计时（`pong` 只是最常见的一种） | 协议层 ping 由浏览器网络栈自动回，前端一行都不用写 —— 但它回答不了课堂要问的那个问题：**页面**还在不在（标签页被挂起时协议层照样有来有回） |
| `error` / `ping` 是每连接私有帧 | 所有下行都带单调 `seq`、都落 `session_events` | 这两种例外：只发给发信人，不落库、不带 `seq` | 别人的合规拦截、发言过快不该广播给全班；更要紧的是**带了 `seq` 会坏事** —— 客户端拿最后一个 `seq` 去重连，而一个不在留档里的号会让它此后一直对不上账 |
| 运行时实例的生命周期 | 没说（只有「服务端权威」这一条） | **每条连接一个 `ClassroomRuntime`**（`channel._enter` 里新建）：一关连接，它那份调度器就跟着 `close()` 清掉，手上**说了一半的那一轮不留 `speak_end`** | 「这堂课现在是什么状态」是全局的（落在库里，每条上行 `_sync()` 拉一次，见下），而调度器、讨论上下文是「这条连接播到哪」的私有进度 —— 一个关掉的标签页不该把整班的进度带走。代价是断线那一轮没有收尾事件（A2 把这种轮次单独记一笔，不进「首尾相接」的统计），重连后由 `state` + `resumeFrom` 补发接上，A10 量的就是这个 |

| P3-A12 与 §4.2 的「在线」 | §4.2 写的是 `presence.online` = 在线人数 | 数的是**人**：一个人开 3 个标签仍是在线 1，关掉最后一个才摘名单 | 同一个人在教室里开三个标签，教室里还是一个人。验收脚本一开始按「连接数」读，读出来和产品口径冲突，改的是脚本 |
| 答疑音频 | 教师语音回答 | 走**试听缓存目录**合成（不进课程的讲稿清单），失败就退纯文字 | 答疑是当场合成的，一个词都不该混进「这堂课的 41 句讲稿」里；配不上音最坏也只是这一句没声音，答案本身绝不能丢 |
| 同学音频 | 只说「AI 同学插话/参与讨论」，没说有没有声音 | 也**当场合成**（同一条缓存目录），用**这位同学自己的音色档**（`AgentRole.voice_profile_id`，种子按 `voice` 配好了）；角色行没配音色时**不合成** | 讲稿有预合成音频、答疑有当场合成的音频，只有同学是哑的 —— 字幕条亮着、署名是林晓、几秒钟一声没有。**绝不退回老师那把嗓子**：那等于老师用自己的声音自问自答，比没声音更糟。共用同一个音色档的两位同学（林晓与苏雨都是顾老师）再按 persona 的 `speechRate` 拉开语速 |
| 语音提问 | 课堂里的语音提问 | 复用 `POST /api/voice/asr`（P2 那条路），**不为课堂另开一条 ASR** | 转码、格式白名单、时长上限、配额都只该在一处。课堂要做的只是把识别结果当成一次 `ask` |
| 测验反馈那两句（P6.1） | 「答对教师带过一句 / 答错同学补充讲解」 | **看作答从哪条路来**：WS 上行 `quiz_answer`（前端走这条）有发言队列，这一句进队**带说话人自己的嗓子说出来**（`kind="feedback"`，优先级夹在答疑与插话之间）；HTTP `POST /quiz-submit`（降级与脚本）够不着队列，落一条**静默发言**（只发 `message`，不发 `speak`）。两条路都进消息流 | 队列在**每条连接各自的 runtime** 里（见上一条），HTTP 这一侧够不着它 —— 硬发一条没有 `speak_end` 的 `speak`，前端会一直停在「正在说话」。而只把消息塞进 `quiz_feedback` 事件的话，课堂上根本没人看得见它（前端不认那个事件），要翻课后记录才冒出来 —— 「课堂收到的」与「记录里的」由此对不上账（P3-C1 / P3-A14 红过，两处都是这么修的）。**绝不能两边都落库**：静默那条与队列那条只能走一条，否则同一句话说两遍 |
| 答完题之后往前走的这一下 | 未规定（只说「位置不动，由客户端再报一次 `beat_done`」） | WS 这条：反馈那一句的 `speak_end` **就是**「接着往下讲」（客户端照它报一次 `beat_done`，报的是空 `beatId`）；`review` 那一档没有话要说，服务端在 `_on_quiz_answer` 里自己把这一拍报掉 | 「答完还要再报一次」这条规矩在 HTTP 那条路是天经地义的（接口不会替客户端推时间线），到了 WS 就变成一个坑：反馈那一句是有声音的，客户端一收到 `quiz_result` 就补报，正好把这句反馈**当场掐断**（`_on_beat_done` 的第一件事就是收掉正在说的那条）。于是这一下挪到「那句话说完」，而没人说话的那一档由服务端兜住 —— 两条都不会让课堂停在答完题的地方 |
| 反馈那一句的说话人 | 未规定 | 答对是老师一句带过；答错由**同学**补一句讲解（按已有消息数轮流选人，避免总是同一位） | 答错时最该听到的是同伴的「我这儿也卡过」，而不是老师再说一遍。嗓子照 §「同学音频」那条走：没配音色档就不出声，**不借老师那把** |
| 字级高亮 | 用 TTS 的字级时间戳驱动逐字高亮 | 前端按 `subtitle` 事件里的 `beatId` 去讲稿清单里对回整句，整句切换（与 P2 §10.2 同一处缺口） | 离线替身不给时间戳，≤150ms 那条要真上游才量得出来 |
| `typing` 这一帧 | §4.2 的下行里**没有它** | 多了一条：教师或 AI 同学要开口之前先推一条 `typing`，与 `speak` **同一拍**发出去（真人学生那条不发 —— 那句停顿是给 AI 留的） | 「AI 在组织语言」和「AI 卡住了」从界面上看是一样的，一条 `typing` 把这一段说清楚。它是个「马上要开口了」的提示，晚一拍就失去意义，所以不真按打字速度拖 |
| 教具条 | 画笔/文本/图形/橡皮齐备 | 激光笔 / 聚光灯 / 画笔 / 橡皮四条**已本地生效**（光点跟随、滚轮调光圈、笔迹可画可擦），跨端同步见 P6.6 | §2.4 的 MVP 范围就是这么划的：P3 只做「教师端预生成板书的回放 + 学生端查看」。本机那半边现在补齐了 —— 笔迹按页存在组件里、坐标归一化（与 `BoardStroke` 同一口径），P6.6 要做的只剩「发上去 + 收下来」 |
| 空格键 | 原型里是「按住说话」（P2） | **P3 的课堂上空格是举手** | 课堂里的提问是「举手 → 点名 → 提问」的队列，不是按住就打断老师。语音那条路仍在，在答疑环节用 |
| 课堂页右侧面板分几个 Tab | 原型是三个（讨论 / 课程大纲 / 白板），字幕是舞台下方的一条 + 一个开关 | **四个**：字幕 / 讨论 / 课程大纲 / 白板 | 原型那个字幕条只显示得下一行，而课堂页要的是「当前 beat 高亮 + 历史字幕滚动 + 点一条历史字幕跳回那一页」三件事，塞回舞台下面会把画面挤小（`ClassroomPanel.vue` 的头注释里记着同一句话） |
| 课堂记录页 | 原型里没有这一页 | 是 P3 新设计的：字幕、消息、板书、作答四块 + 与实时一致的六字段 | P3 的验收条件（A14/C3）要「结束后可回看」，原型只画了上课那一路 |
| 白板的 `instant` 档 | — | `ClassroomBoard` 支持一个 `instant` 快照档（一次画完，不走动画） | 记录页回看与断线重连**补发**时用：补发 200 笔还按 800ms 一笔演一遍，人得等两分半 |
| 参与者名字 | `presence.members` 里要有人名 | **现查 `users` 表**，不落进课堂表 | 名字改了、账号注销了，课堂里显示的还是那个人的名字；存一份快照就得设计「什么时候刷新」。代价是每次 `presence` 多一次 `IN` 查询（一次一批，不是一人一次） |
| AI 同学在不在名单上 | §4.2 只写了 `online` / `members` | 多一个 `aiMembers`：这堂课的角色（`code` / `name` / `color`），**人数取设置页的「AI 同学数量」**，与讨论里谁开口**同源**（`classroom/roster.py`） | 名单上列 3 位、讨论里冒出第 4 位，是同一件事的两种说法对不上。**不混进 `online`**：那个数是「几个人真的连进来了」，用来判断学生到齐没有 —— 混起来两个问题都答不了 |
| `speakerKind` 的「我」 | 前端要区分「老师 / 同学 / 我」 | 服务端在**真人学生**那条上写 `speakerKind="me"`（四种取值：`teacher` / `student_ai` / `me` / `system`），**不按收信人改写** | 「我」是*看的人*的属性，一条广播帧写不出所有人的「我」。P3 的课堂上真人只有**一个人**（一个课堂里能出现的连接都属于同一个 `X-Owner-Id`：旁听的人连 `require_visible` 都过不了，参与者行本来就是入场时才写的），所以 `me` 发出去对每个标签都对。多人课堂（P6）得按 `speaker`（真人那一栏存的就是他的 `userId`）各自判 |

### 10.3 还没做的（与 §10.2 的「有意差异」分开：这些是**要补**的）

- **弱网没测**：A10/A11 验的是「断 3 秒再回来」，丢包、抖动、断超过 60 秒（判死之后）这些
  要真网络，口径见 10.1。
- **多标签之间没有主从协商**：陈旧的上报会被丢掉（见上面第 2 条），但两个标签同时开着
  课堂时，两边都跟着服务端的 `speak` 放音，听起来是重的。「同一堂课只该有一个声音」要
  标签页之间选一个「主」，P3 不做（一个人不会同时听两个标签页）。
- **`board_show` 状态 / 教具条跨端同步 / 学生实时书写**：§2.4 划给了 P6.6。
- **课后小结**：记录页给的是**事实**（字幕 / 消息 / 板书 / 作答），小结是 P6.1 学情聚合
  读同一份数据做的事。
