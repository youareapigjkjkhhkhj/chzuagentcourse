# P3 · 多智能体课堂运行时

> 前置阶段：P2 ｜ 预估：2.5 周 ｜ 里程碑：**M3（核心演示版）**
> 目标：把「一门课」变成「一堂课」——AI 教师按时间线授课，AI 同学随时插话讨论，学生可举手提问、可看板书，一切实时同步。

**P3 是项目的演示核心。** 完成后即可完整演示：一键生成 → 有声课堂 → 多智能体讨论 → 举手互动 → 课堂记录回看。

---

## 1. 阶段目标

一句话：**进入课堂演示页点「开始上课」，AI 教师逐页讲解（语音+字幕+板书），林晓/陈默/苏雨在合适时机插话提问与补充，学生按空格举手提问得到回答，全程进度可暂停/跳转/回看。**

## 2. 运行时模型（核心设计）

### 2.1 课堂状态机

```
        ┌───────────────────────────────────────────────┐
        │                                               │
  idle ──► lecture ──(章末)──► quiz_wait ──► lecture     │
             │  ▲                  │                    │
             │  │                  └──► discussing      │
             │  │                                        │
             │  └────────── discussing ◄──── (同学插话/学生提问)
             │                    │
             ▼                    ▼
         board_show ──────────► paused ──► lecture
             │
             └──► ended
```

| 状态 | 行为 | 进入条件 | 退出条件 |
|------|------|---------|---------|
| `idle` | 等待开始 | 页面进入 | 用户点「开始上课」 |
| `lecture` | 教师按 beat 念讲稿，字幕推进，按 `boardPlan` 触发板书 | 自动 | beat 播完 / 章末 / 被打断 |
| `discussing` | AI 同学按人设发言，教师应答；受「讨论激烈程度」控制轮次 | 章末有 discussion 点 / 学生举手 / 教师 `askAtEnd` | 轮次用尽 / 超时（默认 90s）/ 用户点「继续讲课」 |
| `quiz_wait` | 弹出测验题，等待作答 | 遇到 `kind=quiz` 页 | 提交答案 / 跳过 |
| `board_show` | 白板回放板书笔画 | `boardPlan` 触发 | 笔画播完 |
| `paused` | 冻结时间线 | 用户暂停 / 窗口失焦（可配） | 用户继续 |
| `ended` | 课堂结束，产出课堂记录 | 最后一页结束 | — |

**单写者原则**：同一时刻只能有一个说话者（教师或某位同学）。所有发言必须经过 `SpeechScheduler`（发言队列）排队，**禁止并发发声**——这是避免音频重叠与逻辑混乱的根本约束。

### 2.2 发言调度器（SpeechScheduler）

```python
class SpeechScheduler:
    """串行发言队列：同一时刻只有一个 active speaker。"""
    def enqueue(self, turn: Turn) -> None: ...      # Turn{speakerRole, text|beats, kind, priority, ttlSec}
    def interrupt(self, reason: str) -> None: ...   # 学生举手/打断：清空低优先级队列
    def next(self) -> Turn | None: ...
```

- **优先级**：`学生提问(barge) > 教师答疑 > 同学插话(高) > 同学讨论 > 教师讲授`
- **抢占**：学生提问可抢占除 `教师答疑` 外的所有发言；被抢占的 Turn 丢弃（不补播，避免课堂拖沓）。
- **TTL**：任何 Turn 排队超过 20s 未播即丢弃，防止恢复播放后一次性蹦出 5 条过期发言。
- **轮次控制**：`discussing` 状态下最大轮数 = 激烈程度映射 `{低:1, 适中:2, 高:3}`，另加一个**总时长上限**（60/90/120s 同映射）。

### 2.3 插话决策（AI 同学什么时候说话）

不是随机插话，规则 + 一次轻量 LLM 判定：

1. **固定时机**：章末讨论点（P1 生成）必触发。
2. **规则触发**：页面 `kind=concept` 且本页 beat 播放过半 → 允许最多 1 位同学插话；每 3 页最多插话 1 次（防吵）。
3. **人设驱动**：由 `persona_json` 决定谁插话——林晓（好问，**提问倾向高**）、陈默（爱补充直觉，**补充倾向高**）、苏雨（慢半拍，**复述+反问**）。
4. **内容生成**：一次 LLM 调用输入 `{当前页要点 + 讲稿摘要 + 人设卡 + 最近 3 条发言}`，输出 `{speakerCode, text(≤80字), type[question|supplement|reflect], trigger}`；输出必须过敏感词与长度校验。

### 2.4 板书（boardPlan → 笔画）

- P1 生成的 `boardPlan[{tool, desc, atBeat}]` 在 P3 落地为真实笔画：由 LLM 将 `desc` 转成**简化笔画指令**（`polyline | curve | text | arrow` + 归一化坐标），存 `board_strokes`。
- 播放到 `atBeat` 时，`board_show` 状态按笔画时间轴重绘（每笔 `durMs` 默认 800ms）。
- **MVP 范围**：只做教师端预生成板书的回放 + 学生端查看；学生实时书写与同步见 P6.6。工具条（画笔/文本/图形/橡皮）在 P3 保持可用但对学生本地生效。

### 4.2 WebSocket `/ws/classroom/{sessionId}`

**客户端 → 服务端**

```jsonc
{ "type": "hello",      "token": "…", "resumeFrom": {"pageNo": 7, "beatIdx": 3} }
{ "type": "play" }  { "type": "pause" }  { "type": "seek", "pageNo": 5 }
{ "type": "beat_done",  "beatId": "p7-b2" }        // 前端播放完一个 beat 上报，驱动时间线
{ "type": "ask",        "text": "…", "mode": "voice|text" }
{ "type": "chat",       "text": "…", "target": "teacher|all" }
{ "type": "hand",       "action": "raise|lower|call" }
{ "type": "board_sync", "pageNo": 7, "strokes": […] }
{ "type": "speed",      "value": 1.5 }
```

**服务端 → 客户端**

```jsonc
{ "type": "state",   "status": "lecture|discussing|quiz_wait|board_show|paused|ended",
                     "pageNo": 7, "beatIdx": 3, "elapsedMs": 452000, "totalMs": 1500000 }
{ "type": "speak",   "turnId": "t_…", "speaker": {"code":"teacher","name":"沈老师"},
                     "text": "…", "audioUrl": "…", "beats": ["p7-b2"], "priority": 10 }
{ "type": "speak_end","turnId": "t_…" }
{ "type": "subtitle","beatId": "p7-b2", "text": "…", "pageNo": 7 }
{ "type": "message", "msg": { "id":"…","speaker":"linxiao","type":"question","text":"…","ts":… } }
{ "type": "hand_queue", "queue": [{"userId":"u1","name":"我","ts":…}], "called": null }
{ "type": "board",   "pageNo": 7, "strokes": [{"tool":"curve","points":[…],"durMs":800}] }
{ "type": "quiz",    "pageNo": 9, "question": {...} }
{ "type": "quiz_result", "correct": true, "explain": "…", "branch": "pass|remedial" }
{ "type": "presence","online": 5, "members": [{"name":"我","role":"student"}] }
{ "type": "error",   "code": "…", "message": "…", "recoverable": true }
```

**契约要点**：
- 所有下行事件含单调 `seq`；客户端断线重连时带 `resumeFrom`，服务端补发缺失事件（事件留档在 `session_events`）。
- 客户端必须能处理乱序与重复（幂等：同 `seq` 丢弃）。
- 心跳 `ping/pong` 每 20s；60s 无响应则判定掉线并从在线数移除。

## 6. 前端设计要点

- **单一课堂 Store**（Pinia `classroomStore`）：持有 `status / pageNo / beatIdx / messages / handQueue / board / quiz`，所有变更只能由 WS 事件驱动（**禁止本地伪造状态**，防止与后端不一致）。
- **播放器与时间线**：由后端 `state` 事件 + 前端 `beat_done` 上报构成闭环。前端不自行推进页号，只上报事实。
- **讨论区**：消息按角色渲染头像色（沈老师棕 / 林晓绿 / 陈默紫 / 苏雨蓝 / 我灰），`type` 以徽标区分；「正在输入…」由 `speak` 事件前置 300ms 的 `typing` 事件驱动。
- **举手**：举手后按钮变「已举手（第 2 位）」；被点名时弹出提问条并自动开始录音（走 P2 实时语音）。
- **板书**：SVG 渲染，笔画按 `points` 与 `durMs` 做路径动画；提供「回看本页板书」按钮重放。
- **断线重连**：WS 断开显示顶部灰条「连接中断，正在重连」，指数退避重试（1s/2s/4s/8s，上限 5 次），重连成功用 `resumeFrom` 恢复。
- **课堂记录页**：结束后跳转只读回顾页（字幕全文 + 消息 + 板书快照 + 我的作答），支持导出（P5）。

## 7. 验收条件

### A. 功能

| 编号 | 验收条件 | 判定步骤 |
|------|---------|---------|
| P3-A1 | 完整课堂闭环 | 开始上课 → 12 页讲完 → 教师语音与字幕推进正常 → 课堂记录页可查看全文，全程无卡死 |
| P3-A2 | 状态机正确 | 断点日志中观察到的状态转移符合 §2.1 图；不存在「同时两个说话者」（脚本断言 `speak` 事件区间不重叠） |
| P3-A3 | 同学插话符合规则 | 12 页课堂中插话次数在 3~5 次之间（每 3 页 ≤1 次）；每次插话含人设特征（林晓=提问、陈默=补充、苏雨=复述/反问），抽 5 条人工判定 ≥ 4 条符合 |

| P3-A7 | 测验暂停与判定 | 遇 quiz 页自动进入 `quiz_wait`；答对显示「回答正确」并继续；答错显示解析并可重答一次 |
| P3-A8 | 板书回放 | 播放到含 `boardPlan` 的页面时，白板自动按笔画顺序绘制；可点「回看本页板书」重放 |

| P3-A12 | 在线数真实 | 打开第二个标签页进入同课堂 → 两个标签都显示「在线 2」；关闭一个 → 20s 内变「在线 1」 |
| P3-A13 | 多标签可控 | 两个标签同时操作（一个翻页一个暂停）→ 最终状态一致，无互相覆盖导致的乱序 |
| P3-A14 | 结束后可回看 | 结束后 24h 内打开课堂记录页，内容完整（消息条数与实时一致） |

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 发言调度竞态（两个说话者同时出声） | 体验崩坏 | 单写者队列 + 服务端统一分配 `turnId`；前端严格按 `speak`/`speak_end` 播放；验收 P3-A2 用脚本断言 |

| WS 断线造成状态漂移 | 用户困惑 | 服务端为唯一状态源 + `seq` 补发 + 前端幂等；重连后以服务端状态覆盖本地 |
| 长时间课堂内存泄漏（前端音频对象/事件监听） | 卡顿崩溃 | 音频对象复用单一实例；WS 监听在组件卸载时统一解绑；P3-D4 用 45 分钟压测把关 |
| SQLite 写并发（消息高频写入） | 卡顿 | 消息批量提交（200ms 合并写）+ WAL；`session_events` 异步落库不阻塞推送 |
