# P5 · 导出与工程化交付

> 前置阶段：P1（导出可早于 P3 做）｜ 预估：2 周 ｜ 里程碑：**M4（可交付版）**
> 目标：让课堂产物**走出浏览器**（PPTX / HTML / PDF），让生成过程**成本透明、可续跑**，让系统**一条命令部署**。

---

## 1. 阶段目标

一句话：**点「导出 PPTX」得到可二次编辑的课件；点「导出 HTML」得到双击即看的离线课件；点「导出 PDF」得到打印讲义；工作台能看到本次生成的 token 与费用；服务重启后能从断点继续生成；`docker compose up` 一键部署。**

## 3. 导出管线设计（核心）

```
DSL (课程唯一事实来源)
   │  dsl2ir.ts / dsl2ir.py —— 每页 kind 映射一次
   ▼
IR (页类型无关的中间表示)
   Page → { title, subtitle, blocks: [Heading|Paragraph|Bullets|Image|Quiz|Code|Quote|Notes], notes, sources }
   │
   ├─► renderPptx   → .pptx（python-pptx / pptxgenjs）
   ├─► renderHtml   → 单文件 .html（自包含，含讲义模式与讲义打印样式）
   └─► renderPdf    → .pdf（HTML → 打印样式 → 无头浏览器打印，或 WeasyPrint）
```

**IR 设计要点**：
- IR 只描述**内容与结构**，不含样式细节；样式由各渲染器自带主题决定（保证三种产物观感一致：同一套色彩令牌）。
- IR 是导出与渲染的唯一解耦点，也是将来接「视频导出」「Word 导出」的扩展点。
- 讲稿（`narration`）在 PPTX 落「备注页」、在 PDF 落「讲义右侧栏」、在 HTML 落「字幕层」。
- **图示取静态帧，交互不进产物**（2026-09-13）：三格式拿的都是 `visual.svg`（参数取默认值那一帧）。
  页面上的滑块与逐拍揭示只活在网页里 —— 课件是给人回去看的，不是给人拖的（P1 §3.4）。
- **行内公式在 IR 里是 `Bullet.pieces`**：`$…$` 由 `formula.split` 切成「文字 / 公式」几截，
  HTML 与 PDF 把它排成 `<img>`（2 倍栅格化、框按 1 倍给 —— MuPDF 按图片自己的像素摆，
  不写死尺寸的公式在 PDF 里会大出一倍）、PPTX 用 `formula.plain()` 的 Unicode 近似。
  **三个渲染器共用同一个字号常量** `formula.INLINE_SIZE`。
- **课堂记录多一栏「思辨轨迹」**（`exports/record.py` 的 `_trails_page`）：一次答疑里
  「学生问 → 老师追问 → 学生答 → 老师收束」这条链子，材料来自记录接口的 `trails`
  （P3 §5.1）。它和「讨论区」那一栏的差别是**分了组**：讨论区是一整条流水，读的人得自己
  认出「哪三句其实是一场引导」；这里一次引导一条，还标了收束没有 —— 那条没收束的链子
  是最有信息量的一行，它指出**哪一页没讲清**。没有轨迹时出一页说明为什么没有
  （学生没提问，或者答疑是直接给答案的），不是一片空白。

**技术选型建议**：
- PPTX：**python-pptx**（与后端同进程，无需 Node 运行时；仓库现有 pp 依赖是 Node 侧，后端导出用 python 更省事）。若团队更熟 pptxgenjs，则加一个 Node 边车服务，二选一即可。
- PDF：优先 **Playwright（Chromium）打印** 同一份 HTML —— 一份 HTML 模板同时供离线 HTML 与 PDF，减少漂移。次选 WeasyPrint（纯 Python 但中文排版需额外字体配置）。
- 中文 PDF/PPTX 必须显式指定字体（如 `Source Han Sans` / `Microsoft YaHei`），并在镜像内置字体文件，否则会出方框。

## 4. 接口设计

### 4.1 导出

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/courses/{id}/exports` | 创建导出任务：`{format: pptx\|html\|pdf, scope: course\|record, options:{watermark, withNotes, withQuiz}}` → `{exportId}` |
| GET | `/api/exports/{exportId}` | 任务状态：`{status, progress, fileUrl, sizeBytes, error, expiresAt}` |
| GET | `/api/exports/{exportId}/download` | 下载（带一次性 token，链接 24h 过期） |
| GET | `/api/courses/{id}/exports` | 该课程的导出历史 |
| DELETE | `/api/exports/{exportId}` | 删除产物与文件 |

### 4.2 用量与预算

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/usage/summary` | `?from=&to=&groupBy=day\|course\|kind` → 聚合数据（tokens、字符、时长、估算费用） |
| GET | `/api/usage/courses/{id}` | 单课明细：每次 LLM/TTS/实时语音调用 |
| GET/PUT | `/api/settings/budget` | 单课 token 上限、日预算与告警阈值 |
| GET | `/api/usage/models` | 支持的模型与价格表（可在设置页维护） |

### 4.3 续跑与可观测

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/jobs/{jobId}/resume` | 从首个未完成页继续（幂等：已完成页跳过） |
| GET | `/api/jobs/{jobId}/timeline` | 每步耗时/重试/token/错误码的详情（工作台展开用） |

## 5. 数据模型（P5 新增）

```
exports(id, course_id, session_id, owner_id, format[pptx|html|pdf|md], scope[course|record],
        status[queued|running|done|failed], progress, file_path, size_bytes,
        options_json, error, expires_at, created_at, finished_at)

model_calls(id, kind[llm|tts|asr|realtime], provider, model, ref_type, ref_id,
            step_id, prompt_tokens, completion_tokens, total_tokens,
            units, unit_name, latency_ms, est_cost, ok, error_code, created_at)

daily_usage(id, date, owner_id, kind, total_tokens, total_units, est_cost)   # 聚合缓存

budgets(id, scope[global|course|day], ref_id, limit_tokens, limit_cost, alert_ratio, enabled)

audit_logs(id, actor_id, action, target_type, target_id, detail_json, ip, ua, created_at)
```

- `model_calls` 是所有成本与可观测的唯一数据源；P1 的 `gen_steps.tokens` 改为引用其聚合值。
- 价格表放 `settings_kv.pricing`（JSON），估算费用 = tokens/1000 × 单价，前端明示「估算值，以账单为准」。

## 6. 部署设计

```
docker-compose.yml
├─ app（Flask + gunicorn + gevent，托管 frontend/dist）
│    volumes: ./backend/data:/app/backend/data  （SQLite + 材料 + 音频 + 导出产物 + 备份）
│    healthcheck: GET /api/health
│    env_file: ./backend/.env
└─ （可选）nginx：TLS、静态缓存、SSE 关闭 buffering、WS 升级
```

> 卷这一行与本文档初稿（`./data:/app/data`）不同，**以实现为准**：容器里的工作目录是
> `/app/backend`，`DATABASE_URL` 与五个目录的缺省值全都落在 `backend/data/` 下 ——
> 挂成 `./backend/data:/app/backend/data` 就能让**零个环境变量覆盖**成立，
> 而且跟 `make dev` 用的是同一份数据（想隔离就改这一行）。见 §10。

关键点：
- **SSE 必须关代理缓冲**：`proxy_buffering off; X-Accel-Buffering: no`。
- **WebSocket 走 `gevent` 就够**：本仓库的 WS 由 `simple-websocket` 提供，它只认几种
  WSGI 服务器暴露的 socket，gevent 是其中之一 —— 因此 `worker_class = "gevent"`，
  **不需要** `geventwebsocket` 那个额外的 worker（也就没有多一个依赖）。
- **SQLite 备份**：走 SQLite 的在线备份 API（`Connection.backup()`，不是 `sqlite3 .backup` 那个
  shell，也不是 `cp` —— WAL 下 `cp` 出来的是「看着正常、其实少一截」的文件）；库 + 四类目录
  一起打成一份归档，`flask backup` / `flask restore` 两个 CLI，容器里由 entrypoint 起清理循环。
- **访问码**：`SITE_ACCESS_CODE` 环境变量，开启后所有页面与接口需携带（本地单机默认关闭）。
  `/api/health` 例外 —— 容器健康检查没有浏览器、没有 cookie。
- **SSRF 防护**：自定义 Provider 的 `base_url` 过协议白名单（只 http/https）与内网网段黑名单
  （127./10./172.16-31./192.168./169.254. 等），域名会真解析一遍。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 中文字体缺失导致 PDF/PPTX 乱码 | 产物不可用 | **已消除**：PDF 走 PyMuPDF 的 `Story`，字体用 PyMuPDF 自带的那份 `china-s`（无外部字体文件要装）；PPTX 的中文字体由打开它的 Office 出，导出侧只需写对字体名。验收脚本按「产物里能不能取回中文原文」判，不是按字体名判 |
| 三渲染器样式漂移 | 维护成本高 | 强制走 IR；HTML 与 PDF 共用同一模板（仅媒体查询不同）；PPTX 只保证结构等价、不追求像素一致 |
| 无头浏览器依赖重（Chromium 体积） | 镜像大 | **已规避**：三种产物一个都不需要 Chromium（PDF 见上一行）；镜像里没有 node、没有浏览器，代价是 PDF 的 CSS 只支持 PyMuPDF `Story` 的那个子集 |
| 示意图（`visual.svg`）在 PDF 里画不出来 | 图示页只剩描述 | **已探明并绕开**：`Story` 不认内联 `<svg>`，但认 `<img src="data:image/png;base64,…">`（实测中文与图形都正常）。所以 PDF 那份把 SVG 栅格化成 data URI，HTML 那份直接内联矢量（清晰且不膨胀），PPTX 那份用同一份栅格化结果 `add_picture`。栅格化只用 PyMuPDF，不引入新依赖；画不出来就退回原来的灰色占位行，不假装有图 |
| 成本看板数字与实际账单不符 | 信任问题 | 明示「估算」口径与价格表可编辑；提供导出台账 CSV |
| Docker 下 SQLite 卷并发 | 数据损坏 | 单实例部署（不用多副本）；WAL + 备份；文档明确「不要横向扩容 SQLite」 |

### 10.3 这轮走查里发现并修掉的问题

产品侧（都是真故障，改的是实现）：

| 现象 | 根因 | 修法 |
|------|------|------|
| 点了「继续生成」界面像没反应：接口返回的与紧接着查到的那一份都还是 `status: failed, resumable: true` | 把任务摆回 `queued` 的活干在**后台线程**里，而请求线程返回的是改之前的那份状态 | 拆出 `pipeline.prepare_resume()`（只摆状态、不跑），路由在**请求线程**里调它，之后才是 `submit_resume`；`resume_job` = prepare + run |
| 同一时刻连点两次「继续生成」，两个线程会去改同一批步骤行（页码与版本号会乱） | 「正在跑」这一判排在改状态**之后**，中间有时窗 | 先判 `active_jobs()` 再改状态，`submit_resume` 的返回值当第二道闸 |
| 账本里 TTS/ASR/实时语音那几行的 `model` 是空的 | 语音链路的「型号」不是一个统一的东西（合成认音色、实时认上游资源 ID），写账的地方没填 | `voice/usage.py:model_of()`：按「调用方给的 → 这一嗓子用的音色 → 适配器自报的版本 / 默认音色 → 适配器名」依次取；**七个写入点**（合成成功那条、合成失败那条、试听、三处 ASR、实时语音的结算）全部传进来 —— `model_calls` 里不该再出现一行「不知道是哪一档花的钱」 |
| 没配 `FERNET_KEY` 的部署上，改一次 Provider 只回「服务器内部错误」，看不出怎么补 | 密钥缺失抛的是裸异常，被全局兜底按未知故障处理 | `CryptoError` 继承 `AppError`（code 50002）并带上补法文案 —— 验收里那一行 `HTTP 500 code=50002` 就是它 |

脚本侧（**接口是对的，是脚本问错了格子**；改的是判据，不是实现）：

| 现象 | 脚本原来问的是 | 实际该问的 |
|------|--------------|-----------|
| 「按课程分组的 `<courseId>` 是 0，账本却有 31391」 | `item["courseId"]` | 分组的身份是 `item["key"]`，显示名是 `item["label"]`；改完顺手加了一条「label 要等于课程标题」 |
| 「没有合计（每步 token 与金额没法汇总）」 | `totals["tokens"]` | 合计在 `totals["calls"]["tokens"]`（与每个 `step["calls"]` 同一个形状），另有 `unattributed` 一格；改完同时跟「各步相加」对账 |
