# EduAgentX 部署文档

面向「把这套东西放到一台机器上、让别人能用」的场景。只想在本机点一点看效果的话，
README 的 [5 分钟上手](../README.md#5-分钟上手) 就够了，**不用看这份**。

两条路，选一条：

| 形态 | 什么时候用 | 入口 |
|------|-----------|------|
| **容器（推荐）** | 干净机器、要一键起、要跟着仓库升级 | `docker compose up -d --build` |
| 物理机 | 机器上已经有 Python/Node 生态、或不让装 Docker | venv + gunicorn + 前端产物（见 §3） |

两种形态的数据都在**同一棵树**里：`backend/data/`。它是这台机器的全部状态
（SQLite、材料原件、合成音频、导出产物、备份归档），库里只存相对路径 —— 所以
迁移/备份的最小单位就是这一个目录（§2.3）。

> 说明：本仓库的 CI 只做静态检查（compose 文件可解析、entrypoint `sh -n`、
> `gunicorn.conf.py` 能编译），**没有在 CI 里真构建过镜像**。第一次
> `docker compose up -d --build` 就是那次真构建，P5-A11 的验收口径是
> 「干净机器上 3 分钟内 http://host:5000 可用」。

## 1. 容器部署

### 1.1 前置

- Docker Engine 20.10+ 与 `docker compose` v2（`docker compose version` 能打出来即可）
- 2 核 4G 起（`npm run build` 那一步吃内存，机器小就多等一会儿）
- **出网**：构建阶段要拉 `node:20-alpine` / `python:3.11-slim` 与两边的依赖。
  内网机器见 §1.6。

### 1.2 三条命令

```bash
cd 项目源码/
cp backend/.env.example backend/.env     # 等价于 make env
#   打开 backend/.env 填 SECRET_KEY / FERNET_KEY（见下）
docker compose up -d --build
docker compose ps                        # 等 app 变成 healthy
```

然后开 `http://<这台机器的IP>:5000`。

`.env` 里**至少要填两个**（不填也能起来，但会少东西）：

| 变量 | 不填的后果 |
|------|-----------|
| `SECRET_KEY` | 访问码 cookie 的签名盐退化；重启后所有人要重输访问码 |
| `FERNET_KEY` | 设置页**存不了 API Key**（报「未配置 FERNET_KEY」），只能靠 `.env` 里那组兜底配置 |

生成方式：

```bash
python -c "import secrets; print(secrets.token_hex(32))"
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

`LLM_API_KEY` 也可以直接填在 `.env` 里（那就是「当前启用的服务商」的兜底配置）；
不填也能起 —— 走 Mock Provider，界面点得动，内容不是真的。想验证「装对了没有」，
这一步反而是最快的（见 §4 检查单）。

### 1.3 起来的过程中发生了什么

`docker/entrypoint.sh` 按顺序做四件事，任何一步失败都会让容器退出（`set -e`），
`docker compose logs app` 里能看到它停在哪：

1. **降权**：卷是宿主机的目录，属主往往是宿主机用户。以 root 进来 `chown` 一次
   `/app/backend/data`，然后 `gosu app` 降权 —— **跑起来的进程始终不是 root**（P5-F3）。
   属主已经是 `10001` 时跳过 `chown -R`（data 里可能有几千个音频文件，每次都修会在
   冷启动预算里白白吃掉几秒）。
2. **迁移**：`flask db upgrade`。每次启动都跑 —— 迁移是幂等的，而漏跑的代价是页面 500。
3. **种子**（可选）：只有 `SEED_ON_START=1` 才跑。它建 1 位主讲老师 + 3 位 AI 同学 +
   3 个音色 + 2 门示例课，幂等、不会覆盖你改过的行。
4. **产物清理循环**（可选）：默认每 3600s 调一次 `flask exports-cleanup`（P5-C1）。
   `EXPORT_CLEANUP_INTERVAL=0` 关掉它，改由宿主机 cron 调 `docker compose exec -T app flask exports-cleanup`。

最后 `exec gunicorn`，PID 1 交给它，`docker compose stop` 能干净地停下来。

### 1.4 关键配置

改 `.env` 后 **`docker compose up -d`（不加 `--build`）** 就会重建容器带上新配置 ——
`.env` 是运行时注入的，不需要重新构建镜像。

| 变量 | 默认 | 说明 |
|------|------|------|
| `APP_ENV` | 容器里固定 `production` | 关调试器与自动重载；缺凭据只警告不崩 |
| `DATABASE_URL` | `backend/data/eduagentx.db` | 换成别的绝对路径也行，但记得**它也要在卷里** |
| `FRONTEND_DIST` | `/app/frontend/dist` | 镜像里已经放好；指不到就只剩 API（日志里有一行提示） |
| `SITE_ACCESS_CODE` | 空（关闭） | 开了之后所有页面与接口都要先输访问码（§2） |
| `AUDIT_TRUST_PROXY` | 容器里写死 `"false"` | 只有**跑在 nginx 后面**时才改 `true`（§1.5） |
| `LOG_FILE` | 空（只出 stdout） | 容器里建议留空，让 `docker compose logs` 收；要落文件见运维手册 |
| `BACKUP_DIR` / `BACKUP_KEEP` | `data/backups` / `7` | 见运维手册「备份与恢复」 |
| `SITE_ACCESS_CODE` 相关的 `ACCESS_*` | 见 `.env.example` | 有效期 7 天、限流 10 次/60 秒 |

### 1.5 要 TLS / 域名：带上 nginx 档

```bash
mkdir -p docker/certs && cp 你的证书 docker/certs/server.crt && cp 你的私钥 docker/certs/server.key
docker compose --profile tls up -d          # 等价于 make up PROFILE=tls
```

`docker/nginx.conf` 里那三段（SSE 关缓冲 / WS 转发 Upgrade / 一次性下载不进访问日志）
**缺一段就会表现成「前端某个功能安静地不动」**，所以那份文件里每段都写了为什么，别删。

上了 nginx 要同时做两件事，否则审计日志里的 IP 全是 `127.0.0.1`：

```yaml
environment:
  AUDIT_TRUST_PROXY: "true"     # 后端才会去读 X-Forwarded-For
```

（nginx 那边已经在转发 `X-Forwarded-For` 了。）**直连暴露 5000 时千万别开**：
那个头是调用方自己填的，开了等于让写审计日志的人自己填 IP。

自签证书浏览器会拦一次，继续访问即可。

### 1.6 内网 / 离线机器

构建阶段要出网。离线机器上换个顺序：在有网的机器上构建好，再搬过去。

```bash
# 有网的机器
docker compose build
docker save eduagentx:latest -o eduagentx.tar

# 内网机器（把源码目录和 tar 一起拷过去）
docker load -i eduagentx.tar
docker compose up -d          # 注意：不加 --build
```

内网没有 npm/pip 源时，`--build` 一定失败 —— 所以镜像里**不包含** `node_modules`
与构建缓存，体积也是按「只带运行时」压的。

## 2. 站点访问码（P5-A13）

默认关闭（本地单机）。要放到局域网/公网上，**建议开着**：它挡的是「知道地址就能用」，
不是身份认证 —— 里面没有账号体系，所有人共用一个入口码。

```bash
# backend/.env
SITE_ACCESS_CODE=换成一串够长的随机串
```

重启后：

- 浏览器访问任何页面 → 302 到 `/access`，输对之后发一个 cookie（HttpOnly、
  SameSite=Lax、默认 7 天），跳回你原来要去的地方；`next` 只认本站路径，
  `//evil.com` 这种会被丢掉（防开放重定向）。
- `/api/*`、`/ws/*` 没带 cookie → `403` + 业务码 **40304**。前端拿到 40304 会整页跳
  校验页，而不是弹一个没人看得懂的报错。
- 校验页是**后端渲染**的（`app/templates/access.html`，内联 CSS、无 JS）：那一刻
  前端的 JS/CSS 正好被它自己挡着，用前端产物做这页会转不出来。
- `/api/health` **不走门禁** —— 容器健康检查没有浏览器、没有 cookie。

两件容易被问到的：

- **输错密码不会写审计库**，只写一行日志。审计表不是给爆破留的写放大器；
  成功通过才会记一条 `access.grant`。
- **限流是进程内的**（默认 10 次 / 60 秒 / 每个 IP）。它防的是脚本乱试，不是分布式爆破 ——
  真要放到公网，请在 nginx 上再加一层 `limit_req`。

访问码是**明文比对**（走 `hmac.compare_digest`，防时序侧信道），没有哈希存储那一层：
它就是一张门禁卡，不是账号密码。别和别处的密码复用。

## 3. 物理机部署（不用 Docker）

```bash
# 1. 后端
cd backend
python -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env            # 填 SECRET_KEY / FERNET_KEY / LLM_API_KEY

# 2. 前端产物（构建一次，之后由后端托管）
cd ../frontend && npm ci && npm run build

# 3. 建库 + 灌种子
cd ../backend
.venv/bin/python -m flask --app "app:create_app()" db upgrade
.venv/bin/python -m flask --app "app:create_app()" seed     # 可选

# 4. 起服务
.venv/bin/python -m gunicorn -c gunicorn.conf.py "app:create_app()"
```

`gunicorn.conf.py` 里有两件事**不要改**，理由写在文件开头：

- `worker_class = "gevent"`：SSE（生成进度流）与 WebSocket（语音、课堂）都是长连接，
  `sync` 的 worker 会被一条 SSE 占死；
- `workers = 1`：SQLite 是单写者，而课堂的在线名单在**进程内存**里 —— 两个 worker
  会看到两个不同的课堂。

物理机上要开机自启就交给 systemd：

```ini
# /etc/systemd/system/eduagentx.service
[Unit]
Description=EduAgentX
After=network.target

[Service]
User=eduagentx
WorkingDirectory=/srv/eduagentx/项目源码/backend
EnvironmentFile=/srv/eduagentx/项目源码/backend/.env
ExecStart=/srv/eduagentx/项目源码/backend/.venv/bin/python -m gunicorn -c gunicorn.conf.py "app:create_app()"
Restart=always
RestartSec=3
# 优雅停机：SSE/WS 连接有 30s 的收尾时间
KillSignal=SIGTERM
TimeoutStopSec=30

[Install]
WantedBy=multi-user.target
```

开机自启那台机器上，**产物清理**和**备份**要自己挂 cron（容器那档是 entrypoint 挂的）：

```cron
0 * * * *  cd /srv/eduagentx/项目源码 && make clean-exports
17 3 * * * cd /srv/eduagentx/项目源码 && make backup
```

## 4. 起完之后：检查单

按顺序过一遍，任何一步不对，后面都不用看：

```bash
curl -s http://127.0.0.1:5000/api/health          # {"code":0,...,"status":"ok"}
docker compose ps                                 # app (healthy)
docker compose logs app | head -30                # 有「访问码已开启」/「托管前端产物：…」
docker compose exec -T app id                     # uid=10001(app) —— 不是 root
docker compose exec -T app ls /app/backend/data   # eduagentx.db / uploads / … 都在
```

浏览器打开首页，再走一遍**功能面**（这几条各自串着一条完整链路，坏了立刻能定位）：

1. 首页输入主题 → 工作台六步任务卡实时跑完（**这一步验的是 SSE 没被缓冲/掐断**）；
2. 生成完的课程里点导出 → 产物落 `data/exports/`，下载链接点得动；
3. 进课堂演示页，让它出声（**验的是 WebSocket 与语音链路**）；
4. 设置页改个服务商，点**测试连接** —— 成功显示 `✓ 已连接 · xxxms`。

`.env` 里没填 `LLM_API_KEY` 时，第 1 步走的是离线桩（内容固定但结构完整），
照样能验通链路。

## 5. 升级与回滚

```bash
git pull
docker compose up -d --build      # 迁移会在 entrypoint 里自动跑
```

- **迁移是单向的**：`flask db upgrade` 能跑，降级（`db downgrade`）要手工确认。
  升级前先 `make backup` —— 回滚的可靠姿势是「换回旧镜像 + 恢复那份备份」，
  不是把迁移倒着跑一遍。
- 镜像带 tag 就更好回：`docker compose up -d --build` 之前先
  `docker tag eduagentx:latest eduagentx:2026-09-13`，出事
  `docker compose up -d` 换 `image:` 指回去。
- **别横向扩容**：`docker compose up -d --scale app=2` 一定会出问题（见 §3 的两条）。

## 6. 部署期常见问题

**端口 5000 被占**：改 `docker-compose.yml` 的 `ports: ["5001:5000"]`（容器里还是 5000）。

**`env_file` 报文件不存在**：`cp backend/.env.example backend/.env`。compose 在
`.env` 缺失时直接拒绝启动，而那句报错看着和「密钥没配」是两回事。

**页面 200 但一片空白**：看 `docker compose logs app` 有没有「托管前端产物」。
没有 = `/app/frontend/dist/index.html` 不在（构建阶段挂了，会在 build 日志里先报）。
开发机上从没跑过 `npm run build` 时，后端**只提供 API**，这是设计如此。

**改 `.env` 没生效**：`docker compose up -d`（重建容器）才会读新的 `env_file`。

**容器 unhealthy**：`docker compose exec -T app python -c "import urllib.request;
print(urllib.request.urlopen('http://127.0.0.1:5000/api/health', timeout=4).status)"`。
多半是迁移失败或 5000 没起来，`logs` 里能看到真实原因。

**生成到一半断流**：先确认有没有走 nginx —— SSE 那一段 `proxy_buffering off` 少一行，
表现就是「进度条永远不动、日志里事件其实一直在发」。

**审计日志里 IP 全是 127.0.0.1**：跑在 nginx 后面但没把 `AUDIT_TRUST_PROXY` 改成 `true`（§1.5）。

其余运维类问题（备份恢复、日志、磁盘、成本）见 [运维手册](运维手册.md)。
