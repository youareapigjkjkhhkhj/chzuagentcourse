# 02 · 项目目标 — 企业级大模型和 RAG 技术的智能数据分析系统

## 一、功能目标

| 编号 | 功能 | 验收标准 |
|------|------|----------|
| F1 | ChatBI 对话问数 | 自然语言提问 → SQL → 数据 → 图表 → 智能分析全链路（`apps/chat/task/llm.py` LLMService） |
| F2 | Text-to-SQL | 12 种数据库方言模板 + 基础模板（`apps/template/template.py:32`），按 `db_type` 加载 |
| F3 | RAG 语义召回 | 表/字段/术语 embedding + 相似度阈值，召回相关表结构供 SQL 生成（`table_embedding.py:13`） |
| F4 | 数据源接入 | 13 种类型：增删改查/连通性检查/选表/表结构/Excel 导入建表 |
| F5 | 模型管理 | 12+ 服务商（OpenAI 兼容/Azure/vLLM），默认模型、密钥加密存储、工作空间模型映射 |
| F6 | 术语库 | 术语增删改查、启用/停用、Excel 批量导入、embedding 检索 |
| F7 | SQL 示例校准 | 训练数据维护、Excel 导入、embedding 检索（越问越准） |
| F8 | 工作空间隔离 | 工作空间 CRUD + 用户绑定，资源按工作空间隔离 |
| F9 | 细粒度权限 | 行/列级数据权限 + 逻辑操作符白名单 + SQL 注入转义（CWE-89 防护） |
| F10 | 多端集成 | Web 嵌入、弹窗嵌入、MCP 服务（8001 端口：8 个 mcp_* 操作） |
| F11 | 智能增强 | 图表生成、数据预测、推荐问题、运行日志与 token 用量 |

## 二、非功能目标

| 维度 | 目标 |
|------|------|
| 可运行性 | Docker 一键部署（`部署参考/docker-compose.yaml`）；本地核心模块导入验证通过；2 个本地测试全绿 |
| 安全性 | JWT 认证 + 密钥加密存储（sqlbot-xpack）+ SQL 注入转义（`row_permission.py`）+ 元数据查询默认禁用（`config.py:118`） |
| 隔离性 | 工作空间级资源隔离 + 行/列数据权限（`xpack.permissions`） |
| 多语言 | OpenAPI 文档多语言（zh/en/ko/zh-TW，`apps/swagger/i18n.py`） |
| 可维护性 | 72 个 Alembic 迁移管理 schema 演进；模块化 apps 架构；mypy/ruff 规范 |
| 可观测性 | 统一日志（SQLBotLogUtil）+ 审计日志（`common/audit`）+ token 用量记录 |

## 五、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| `sqlbot-xpack` 为私有商业包 | 本地无法 import（密钥/权限/license） | 官方镜像内置；文档标注边界；本地用 stub 验证核心链路 |
| 依赖 PostgreSQL | 无 PG 无法启动主库 | Docker 部署（自动迁移）；测试用 mock |
| torch/sentence-transformers 体积大 | embedding 模块安装重 | 按需安装（pyproject optional）；本地验证跳过 |
| 12 种数据库驱动 | 依赖面广 | 按实际数据源按需安装（`pyproject.toml` 已分类） |
| 生产密钥管理 | SECRET_KEY 泄露 | `.env` 覆盖；生产用环境变量注入 |
