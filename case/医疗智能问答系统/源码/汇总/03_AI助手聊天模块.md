# AI助手聊天模块功能报告

## 一、模块概述与功能定位

### 1.1 模块概述
AI助手聊天模块是糖尿病视网膜病变诊断系统的智能交互模块，为用户提供基于大语言模型的智能问答服务。该模块支持与用户进行自然语言对话，结合知识库提供专业的医疗咨询，并能够根据用户需求生成诊断建议和健康指导。

### 1.2 功能定位
- 提供智能问答服务
- 支持多轮对话和上下文理解
- 集成知识库提供专业医疗建议
- 支持流式响应提升用户体验
- 管理聊天会话和历史记录
- 提供聊天统计和分析功能

## 二、核心功能说明

## 三、技术实现细节

### 3.1 数据模型

#### ChatSession（聊天会话表）
- `id`：主键，UUID
- `user_id`：用户ID，外键关联users表
- `title`：会话标题
- `model_id`：使用的模型ID，外键关联models表
- `knowledge_base_id`：使用的知识库ID，外键关联knowledge_bases表
- `created_at`：创建时间
- `updated_at`：更新时间
- `is_active`：是否活跃

#### ChatMessage（聊天消息表）
- `id`：主键，UUID
- `session_id`：会话ID，外键关联chat_sessions表
- `content`：消息内容
- `message_type`：消息类型（user/ai/system）
- `role`：角色（user/assistant/system）
- `timestamp`：时间戳
- `tokens`：消息token数量
- `model_response_time`：AI响应时间（秒）
- `from_knowledge_base`：是否来自知识库
- `sources`：知识库来源信息（JSON格式）

### 3.3 流式响应实现

#### SSE（Server-Sent Events）实现
使用Flask的流式响应功能实现SSE：

```python
def generate_stream(messages, model, knowledge_base):
    """生成流式响应"""
    try:
        # 构建消息历史
        chat_history = []
        for msg in messages:
            chat_history.append({
                'role': msg['role'],
                'content': msg['content']
            })
        
        # 调用模型生成响应
        response = model.generate_stream(chat_history, knowledge_base)
        
        for chunk in response:
            # 发送SSE格式的数据
            yield f"data: {json.dumps({'content': chunk})}\n\n"
        
        # 发送结束标记
        yield "data: [DONE]\n\n"
        
    except Exception as e:
        yield f"data: {json.dumps({'error': str(e)})}\n\n"
```

### 3.4 知识库集成

#### 知识检索流程
1. 接收用户问题
2. 对问题进行向量化
3. 在向量数据库中检索相关文档
4. 将检索结果作为上下文
5. 使用大语言模型生成回答
6. 标注信息来源

#### 向量检索实现
```python
def search_knowledge_base(query: str, top_k: int = 5) -> List[Dict]:
    """在知识库中搜索相关信息"""
    # 对查询进行向量化
    query_embedding = embedding_model.encode(query)
    
    # 在向量数据库中搜索
    results = vector_db.search(
        query_embedding,
        top_k=top_k,
        filter={'active': True}
    )
    
    # 格式化结果
    documents = []
    for result in results:
        documents.append({
            'id': result['id'],
            'content': result['content'],
            'metadata': result['metadata'],
            'score': result['score']
        })
    
    return documents
```

#### 对话历史构建
```python
def build_chat_history(session_id: str, max_history: int = 10) -> List[Dict]:
    """构建对话历史"""
    messages = ChatService.get_session_messages(session_id)
    
    # 限制历史消息数量
    recent_messages = messages[-max_history:]
    
    # 转换为模型需要的格式
    chat_history = []
    for msg in recent_messages:
        chat_history.append({
            'role': msg.role,
            'content': msg.content
        })
    
    return chat_history
```

### 3.6 统计分析实现

#### 用户聊天统计
```python
def get_user_chat_statistics(user_id: int) -> Dict[str, Any]:
    """获取用户聊天统计信息"""
    # 总会话数
    total_sessions = ChatSession.query.filter_by(user_id=user_id).count()
    
    # 总消息数
    total_messages = db.session.query(ChatMessage).join(ChatSession).filter(
        ChatSession.user_id == user_id
    ).count()
    
    # 总token数
    total_tokens = db.session.query(db.func.sum(ChatMessage.tokens)).join(ChatSession).filter(
        and_(ChatSession.user_id == user_id, ChatMessage.role == 'assistant')
    ).scalar() or 0
    
    # 平均响应时间
    avg_response_time = db.session.query(db.func.avg(ChatMessage.model_response_time)).join(ChatSession).filter(
        and_(ChatSession.user_id == user_id, ChatMessage.role == 'assistant')
    ).scalar() or 0
    
    # 知识库使用率
    kb_messages = db.session.query(ChatMessage).join(ChatSession).filter(
        and_(
            ChatSession.user_id == user_id,
            ChatMessage.role == 'assistant',
            ChatMessage.from_knowledge_base == True
        )
    ).count()
    
    ai_messages = db.session.query(ChatMessage).join(ChatSession).filter(
        and_(
            ChatSession.user_id == user_id,
            ChatMessage.role == 'assistant'
        )
    ).count()
    
    kb_usage_rate = (kb_messages / ai_messages * 100) if ai_messages > 0 else 0
    
    return {
        'totalSessions': total_sessions,
        'totalMessages': total_messages,
        'totalTokens': int(total_tokens),
        'avgResponseTime': round(avg_response_time, 2),
        'kbUsageRate': round(kb_usage_rate, 2)
    }
```

## 五、数据流程

### 5.1 聊天对话流程
1. 客户端发送用户消息
2. 服务器接收并验证用户身份
3. 服务器验证会话是否存在
4. 保存用户消息到数据库
5. 构建对话历史
6. 如果启用知识库，检索相关信息
7. 调用大语言模型生成响应
8. 流式返回AI响应
9. 保存AI响应到数据库
10. 更新会话最后更新时间

### 5.2 知识库检索流程
1. 接收用户问题
2. 对问题进行预处理
3. 使用嵌入模型生成向量
4. 在向量数据库中搜索相似文档
5. 对搜索结果进行排序和过滤
6. 将相关文档作为上下文
7. 生成带来源标注的回答

### 5.3 会话创建流程
1. 客户端请求创建会话
2. 服务器验证用户身份
3. 生成会话ID（UUID）
4. 创建会话记录
5. 保存到数据库
6. 返回会话信息

### 5.4 消息导出流程
1. 客户端请求导出会话
2. 服务器验证用户身份
3. 验证会话是否存在
4. 获取会话所有消息
5. 根据格式生成导出数据
6. 返回导出数据或文件

## 六、错误处理机制

### 6.1 错误码定义
| 错误码 | 说明 | HTTP状态码 |
|--------|------|-----------|
| SESSION_NOT_FOUND | 会话不存在 | 404 |
| MESSAGE_NOT_FOUND | 消息不存在 | 404 |
| INVALID_MESSAGE | 消息内容无效 | 400 |
| MODEL_NOT_AVAILABLE | 模型不可用 | 500 |
| KNOWLEDGE_BASE_ERROR | 知识库错误 | 500 |
| STREAM_ERROR | 流式响应错误 | 500 |
| UNAUTHORIZED | 未授权访问 | 401 |

### 6.2 错误响应格式
```json
{
  "success": false,
  "message": "错误描述",
  "error_code": "ERROR_CODE"
}
```

### 6.3 异常处理
- **会话不存在**：返回404错误，提示会话不存在或无权限
- **消息无效**：返回400错误，提示消息内容不能为空
- **模型错误**：记录日志并返回500错误
- **知识库错误**：降级处理，不使用知识库继续对话
- **流式响应错误**：发送错误消息到客户端

## 七、性能与安全考量

### 7.1 性能优化
- **流式响应**：使用SSE实现流式输出，减少首字延迟
- **上下文限制**：限制对话历史长度，控制Token使用
- **缓存机制**：缓存常见问题的答案
- **并发处理**：支持多用户并发对话
- **异步处理**：知识库检索采用异步处理

### 7.2 安全措施
- **身份验证**：所有接口需要登录验证
- **权限控制**：用户只能访问自己的会话和消息
- **内容过滤**：过滤敏感和不当内容
- **Token限制**：限制单次对话的Token使用量
- **频率限制**：防止滥用和攻击

### 7.3 数据隐私
- **数据加密**：传输数据使用HTTPS加密
- **访问控制**：严格的数据访问权限控制
- **日志记录**：记录所有对话操作
- **数据保留**：支持用户删除历史记录
