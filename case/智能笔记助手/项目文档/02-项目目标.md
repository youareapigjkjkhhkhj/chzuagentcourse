# 02 · 项目目标

本文档定义项目一「智能笔记助手」的**功能目标、非功能目标、设计原则、里程碑、验收标准与风险对策**，作为开发、评审与验收的统一基线。

## 2.1 功能目标（FR）

| 编号 | 功能 | 说明 | 对应实现 |
|------|------|------|----------|
| FR-1 | 笔记上传 | 支持 .md/.txt/.pdf 上传，安全文件名处理 | `POST /api/notes/upload` |
| FR-2 | 笔记列表/查看/删除 | 列出笔记元信息、查看原文、删除并失效索引 | `GET/DELETE /api/notes` |
| FR-3 | 知识库构建 | 全量重建 FAISS 索引，返回笔记数/分块数/向量数 | `POST /api/index/rebuild` |
| FR-4 | 索引状态查询 | 返回是否已构建、向量数量 | `GET /api/index/status` |
| FR-5 | 非流式问答 | 返回答案 + 来源笔记溯源 | `POST /api/qa` |
| FR-6 | 流式问答 | SSE 逐 token 输出，结束返回来源 | `POST /api/qa/stream` |
| FR-7 | 前端交互 | 笔记管理面板 + 对话面板，调用全部接口 | Vue3 `NotePanel`/`ChatPanel` |
| FR-8 | 同源访问 | 单进程同时托管 API 与前端，零额外反代 | `app.py` 静态托管 |

## 2.2 非功能目标（NFR，量化）

| 维度 | 目标 | 说明 |
|------|------|------|
| 性能 | 单笔记（<100KB）建库 < 10s | 受限于嵌入 API 速率 |
| 准确率 | 检索 top_k=4，答案可溯源到正确笔记 | 通过来源字段验证 |
| 可靠性 | 索引持久化，重启服务不丢 | FAISS 落盘到 `data/vector_store` |
| 可维护性 | 分层架构（api/service/rag），配置集中 | `src/config.py` 单一配置源 |
| 安全性 | 文件名净化、路径不越界、CORS 可控 | `note_service._safe_name` |
| 可移植性 | 纯 Python + 本地向量库，无外部中间件 | 仅依赖大模型代理 |
| 可测试性 | 端到端 + HTTP 自动化测试 | `tests/` 下两套脚本 |

## 2.3 设计原则

1. **配置与代码分离**：所有密钥、路径、超参集中于 `.env` + `src/config.py`，不硬编码。
2. **分层解耦**：路由层只做 HTTP 协议转换，业务编排在 `services`，算法细节在 `rag`。
3. **失败可观测**：统一异常捕获，API 返回结构化错误；日志打印请求与耗时。
4. **开箱即用**：内置示例笔记与 `.env`，克隆即可 `python app.py` 体验。
5. **兼容约束前置处理**：Windows 中文路径等环境坑在基础设施层（`vectorstore.py`）一次性解决，业务代码无感。

| 阶段 | 交付 | 状态 |

## 2.6 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 大模型代理频率限制（429） | 建库/问答失败 | 代码捕获并提示重试；测试脚本容忍限流；业务不崩溃 |
| Windows 中文路径导致 FAISS 写盘失败 | 索引无法持久化 | `vectorstore.py` 用 `os.chdir`+相对名规避，已内置 |
| 笔记量大时全量重建慢 | 体验下降 | 当前版本接受；后续可引入增量 `add()`（代码已预留） |
| 前端跨域 | 开发态无法联调 | Flask-CORS 已启用；生产由同源托管规避 |
| API Key 泄露 | 安全风险 | Key 仅存 `.env`，已加入 `.gitignore`（建议） |
