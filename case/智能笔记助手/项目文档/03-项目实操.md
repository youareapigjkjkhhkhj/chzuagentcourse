## 3.2 第一步：进入项目目录


## 3.3 第二步：后端环境搭建（venv + 清华源）

```bash
# 1. 创建虚拟环境

# 2. 激活（Git Bash）
source .venv/Scripts/activate
# 或 PowerShell：
# .venv\Scripts\Activate.ps1

# 3. 用清华源安装依赖
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

**依赖清单（requirements.txt）**
```

langchain-community
faiss-cpu
flask
flask-cors
python-dotenv
pypdf
tiktoken
```

> **若 `python -m venv` 创建后无 pip**（个别精简 Python 环境），用引导方式：
> ```bash

> .venv/Scripts/python.exe /tmp/get-pip.py

## 3.4 第三步：配置 `.env`

`.env` 已内置以下配置，通常**无需修改**即可运行：

```ini
OPENAI_API_KEY="sk-xxxx"
OPENAI_BASE_URL="https://api.chatanywhere.tech"
CHAT_MODEL="gpt-5-mini"
EMBEDDING_MODEL="text-embedding-3-small"
APP_HOST=0.0.0.0
APP_PORT=5000
LOG_LEVEL=INFO
```

| 变量 | 含义 | 默认 |
|------|------|------|
| `OPENAI_API_KEY` | 大模型代理 Key | 已填 |
| `OPENAI_BASE_URL` | 兼容 OpenAI 的代理地址 | 已填 |
| `CHAT_MODEL` | 对话模型 | `gpt-5-mini` |
| `EMBEDDING_MODEL` | 嵌入模型 | `text-embedding-3-small` |
| `CHUNK_SIZE` / `CHUNK_OVERLAP` / `TOP_K` | 切分与检索参数 | 800 / 120 / 4 |

> 路径（数据目录、向量目录）由代码基于项目根自动绝对化，**不建议在 `.env` 写相对路径**，以免工作目录依赖。

## 3.7 第六步：构建知识库

方式 A — 网页操作：
1. 打开 `http://127.0.0.1:5000`
2. 在「笔记管理」中上传 `.md/.txt/.pdf`（项目已内置 `快速开始示例.md`）
3. 点击「构建知识库」

方式 B — 命令行（curl 示例）：
```bash
# 上传
curl -F "file=@data/notes/快速开始示例.md" http://127.0.0.1:5000/api/notes/upload
# 构建索引
curl -X POST http://127.0.0.1:5000/api/index/rebuild
# 查询状态
curl http://127.0.0.1:5000/api/index/status
```

成功后返回类似：
```json
{"status":"built","note_count":1,"chunk_count":1,"vector_count":1}
```

## 3.10 常见问题与排查

### Q1. 启动报 `could not open ... faiss_index.faiss for writing`
**原因**：FAISS 底层 C++ 在 Windows 上无法写入含中文的**绝对路径**。
**已修复**：`src/rag/vectorstore.py` 的 `VectorStoreManager` 采用 `os.chdir` 进入向量目录、以相对文件名写盘（配线程锁），数据仍落在项目内 `data/vector_store`。**使用者无需任何操作**。若仍报错，检查该目录是否有写入权限。

### Q2. 建库/问答返回 429 或「频率限制」
**原因**：大模型代理有调用频率/额度限制。
**处理**：稍后重试（额度重置后）；该错误已被代码捕获并提示，不会导致进程崩溃。也可降低 `CHUNK_SIZE` 以减少分块数、降低嵌入调用频次。

### Q3. 前端页面空白 / 资源 404
**原因**：`frontend/dist` 未构建，或后端从错误目录启动。
**处理**：确保 `cd 源码/backend` 后启动 `python app.py`；若改过前端，执行 `npm run build` 重新生成 `dist`。

### Q4. 跨域错误（CORS）
**原因**：前端用独立 Vite 端口（5173）访问后端（5000）。
**处理**：生产由 Flask 同源托管，无此问题；开发态 `flask-cors` 已启用，正常放行。

### Q5. 上传中文名文件报错
**处理**：`note_service._safe_name` 已做文件名净化，仅替换 `\/:*?"<>|` 等危险字符，保留中文，正常落盘。

## 3.11 生产部署建议

- **进程管理**：用 `gunicorn` 替代 `app.run`（`pip install gunicorn -i 清华源`，`gunicorn -w 2 -b 0.0.0.0:5000 app:app`）。
- **反向代理**：前置 Nginx 做 HTTPS 与静态资源分离（将 `frontend/dist` 交由 Nginx 托管、`/api` 反代到 Flask）。
- **索引重建**：当前为全量重建；笔记量大时建议在 `note_service` 中改用 `VectorStoreManager().add()` 实现增量。
- **安全**：将 `.env` 加入 `.gitignore`；生产环境务必替换为自有 Key 并限制 CORS 来源。
