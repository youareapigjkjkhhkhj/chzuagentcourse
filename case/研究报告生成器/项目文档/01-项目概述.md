# 01 · 项目概述 — 研究报告生成器

## 一、项目背景

学术调研与研究报告撰写存在典型痛点：论文检索散落多源、PDF 阅读耗时、证据组织缺乏依据、写作门槛高。本项目构建一个 **Multi-Agent 研究报告生成器**：输入一个研究主题，系统自动完成「规划 → 多源检索 → PDF 阅读 → 本地混合 RAG 证据检索 → LLM 分析 → 结构化写作 → Markdown/PDF 导出」全链路。

## 二、项目定位

面向研究人员、工程师、学生与知识工作者的**研究工作台**，对标学术综述辅助工具。核心差异化：

1. **多智能体流水线**：6 类代理各司其职，进度全程可视化（8 阶段时间线）。
2. **零依赖本地 RAG**：哈希特征向量 + FAISS + BM25 的混合检索，**不依赖远程 embedding API**，离线可用、结果确定。
3. **多论文源**：arXiv / Semantic Scholar / Europe PMC / Crossref / 综合开放源，中文主题自动转英文检索词。
4. **始终可用**：未配置 API Key、断网、PDF 无法解析等异常均自动降级，绝不中断流程。

## 三、技术栈

| 层 | 技术 | 说明 |
|----|------|------|
| 后端 | Python 3.13 + FastAPI + Uvicorn | REST API + 后台线程异步任务 |
| 检索 | arxiv / requests（Semantic Scholar、Europe PMC、Crossref） | 4+1 论文源 |
| 向量 | faiss-cpu + numpy | 哈希特征向量 + IndexFlatIP 内积召回 |
| 词法 | 自实现 BM25 + 查询词覆盖率 | 与向量分融合排序 |
| PDF | pdfplumber | 逐页文本抽取 |
| LLM | openai SDK（OpenAI 兼容） | 多服务商（DeepSeek/OpenAI/自定义）+ 本地响应缓存 |
| 导出 | markdown + Playwright Chromium | Markdown → HTML → A4 PDF |
| 前端 | Vue 3.5 + Vite 6 + @lucide/vue | 单页工作台，构建产物由 FastAPI 同源托管 |

## 六、核心数据流

1. **检索阶段**：`search_agent` 生成检索词变体 → `search_papers` 命中论文（title/authors/abstract/pdf_url/…）。
2. **阅读阶段**：`reader_agent` 下载 PDF 抽取文本，追加 `text` 字段。
3. **证据阶段**：`rag_agent.chunk_papers` 切块（1200 字符/180 重叠）→ `ResearchVectorStore` 建索引 → `build_rag_context` 检索出 `[Evidence N]` 块与相关度标签。
4. **生成阶段**：`analyze` 总结证据 → `write_report` 生成 Markdown → 保存 `md` + `pdf`。
5. **消费阶段**：前端轮询任务详情，下载报告。
