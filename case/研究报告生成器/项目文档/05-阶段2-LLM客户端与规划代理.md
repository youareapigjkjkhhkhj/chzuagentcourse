# 05 · 阶段 2 — LLM 客户端与规划代理

> 本阶段目标：实现「多服务商 LLM 客户端」（API Key 解析、本地响应缓存、未配置兜底异常）与「规划代理」（把研究主题拆解为可执行任务列表），并编写后端 CLI 入口验证。

---

## 1. 目标

- 掌握 `agents/llm_client.py` 的多服务商（DeepSeek / OpenAI / 自定义）配置解析链路。
- 理解本地 LLM 响应缓存机制（相同请求直接复用，节省 API 调用）。
- 运行 `planner_agent.plan_task()`，把主题拆成 5 步研究任务。
- 运行 `main.py` CLI 入口，走通「规划→检索→阅读→RAG→分析→写作→保存」骨架。

## 2. 关键设计

### 2.1 服务商默认值表

`agents/llm_client.py:15-37` 定义 `PROVIDER_DEFAULTS`：

| provider | 默认 base_url | 默认 model | env_key | env_model |
|----------|---------------|------------|---------|-----------|
| deepseek | `https://api.deepseek.com` | `deepseek-chat` | `DEEPSEEK_API_KEY` | `DEEPSEEK_MODEL` |
| openai | `None`（用 `OPENAI_BASE_URL` 环境变量） | `gpt-5-mini` | `OPENAI_API_KEY` | `OPENAI_MODEL` |
| custom | `""` | `""` | `CUSTOM_LLM_API_KEY` | `CUSTOM_LLM_MODEL` |

### 2.2 配置解析优先级

`resolve_llm_settings()`（`llm_client.py:69-100`）优先级：**请求体 LLMConfig > `.env` 环境变量 > provider 内置默认**。

- API Key：请求体 `api_key` → `env_key` 环境变量 → 抛 `LLMNotConfiguredError`（`llm_client.py:79-83`）。
- 模型：请求体 `model` → `env_model` → provider 默认。
- Base URL：请求体 `base_url` → **`OPENAI_BASE_URL` 环境变量（`llm_client.py:94`）** → provider 默认。

### 2.3 本地响应缓存

`invoke_llm()`（`llm_client.py:104-136`）先查本地缓存再调 API：

- 缓存键：`_cache_key()`（`llm_client.py:139-150`）对 provider/base_url/model/system/temperature/prompt 做 SHA-256。
- 缓存目录：`_cache_dir()`（`llm_client.py:153-162`）默认 `backend/runtime_cache/llm/`，可用 `LLM_CACHE_DIR` 覆盖。
- 开关：`LLM_RESPONSE_CACHE=0` 关闭（`llm_client.py:165-171`）。

## 3. 实操步骤

### 3.1 验证配置解析（无 API 调用）

```bash
cd 源码/backend
.venv/Scripts/python.exe -c "
from agents.llm_client import resolve_llm_settings
s = resolve_llm_settings({'provider': 'openai'})
print('provider =', s['provider'])

"
# 期望：model=gpt-5-mini（来自 .env），base_url=https://api.chatanywhere.tech（来自 .env）
```

### 3.2 运行规划代理

```bash

from agents.planner_agent import plan_task
for i, t in enumerate(plan_task('量子计算'), 1):

```

`plan_task()`（`planner_agent.py:1-9`）输出固定 5 步：明确范围 → 检索论文 → 阅读抽取 → 构建检索上下文 → 结构化写作。

```bash

# 输入研究主题后，依次打印 Planning/Searching/Reading/... 并保存 md+pdf
```

`main.py:10-41` 的 `main()` 是后端全部代理的串行编排参考实现。

## 4. 可运行验证

| 验证项 | 命令 | 期望 |
|--------|------|------|
| 配置解析 | 见 3.1 | model=`gpt-5-mini`、base_url=`api.chatanywhere.tech` |
| 缓存开关 | `.env` 设 `LLM_RESPONSE_CACHE=0` 后重跑 3.1 | 仍正常（解析不依赖缓存） |

**Checkpoint 达成标准**：`resolve_llm_settings` 正确命中 `.env` 的代理配置；`plan_task` 返回 5 步任务。
