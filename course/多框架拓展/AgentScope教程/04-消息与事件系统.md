# 04 - 消息与事件系统

本篇目标：理解 2.0 的两大通信原语——**消息（Message）**与**事件（Event）**。所有智能体输入输出都基于此，也是流式 UI / 可观测的基础。

## 4.1 前置准备

```bash
pip install agentscope
export DASHSCOPE_API_KEY="sk-你的密钥"
```

## 4.2 消息 UserMsg

2.0 用 `UserMsg` 表示用户输入（**取代 1.0 的 `Msg`**）。`content` 为字符串即可。

```python
from agentscope.message import UserMsg

# 纯文本消息
msg = UserMsg(name="user", content="北京今天天气怎么样？")

# 多轮对话：把上一条回复作为新输入的一部分
reply = await agent.reply(msg)
next_msg = UserMsg(name="user", content="那适合穿什么？")  # 上下文由 Agent 自动维护
```

> 2.0 的事件系统原生支持**多模态**（text / image / audio）流式推送；多模态消息构造以官方文档 [docs.agentscope.io](https://docs.agentscope.io/) 的 `UserMsg` 字段说明为准。

## 4.3 运行智能体：reply 与 reply_stream

`Agent` 提供两种运行方式，均为 `async`：

| 方法 | 行为 | 适用 |
|------|------|------|
| `await agent.reply(msg)` | 跑完整个推理-行动循环，返回**最终**消息对象 | 脚本/批量调用 |
| `async for e in agent.reply_stream(msg)` | 逐项**流式**产出事件 | 聊天 UI / 实时日志 |

```python
import os
import asyncio

from agentscope.agent import Agent
from agentscope.credential import DashScopeCredential
from agentscope.message import UserMsg
from agentscope.model import DashScopeChatModel


async def main() -> None:
    agent = Agent(
        name="Friday",
        system_prompt="You are a helpful assistant.",
        model=DashScopeChatModel(
            credential=DashScopeCredential(api_key=os.environ["DASHSCOPE_API_KEY"]),
            model="qwen-plus",
        ),
    )
    user_msg = UserMsg(name="user", content="用一句话介绍 AgentScope。")

    # 等待最终回复
    final = await agent.reply(user_msg)
    print("最终回复：", final.content)

    # 流式事件
    async for event in agent.reply_stream(user_msg):
        print("事件类型：", event.type)


asyncio.run(main())
```

## 4.4 事件类型 EventType

`reply_stream` 产出统一的事件流，可用 `match event.type` 驱动 UI。常用枚举（完整列表见 `agentscope.event.EventType`）：

| EventType | 含义 |
|-----------|------|
| `REPLY_START` | 一次回复开始 |
| `MODEL_CALL_START` | 即将调用模型 |
| `TEXT_BLOCK_START` | 一段文本开始生成 |
| `TEXT_BLOCK_DELTA` | 文本增量片段（用 `event.delta`） |
| `TEXT_BLOCK_END` | 一段文本结束 |
| `TOOL_CALL_START` | 智能体即将调用工具（含 `event.tool_name`） |
| `TOOL_CALL_END` | 工具调用结束 |

**典型流式渲染**

```python
from agentscope.event import EventType

async for event in agent.reply_stream(user_msg):
    match event.type:
        case EventType.TEXT_BLOCK_DELTA:
            print(event.delta, end="")          # 实时打印文本
        case EventType.TOOL_CALL_START:
            print(f"\n[工具] {event.tool_name} 调用中…")
        case EventType.TOOL_CALL_END:
            print("\n[工具] 调用完成")
        case _:
            pass
```

## 4.5 上下文注入：observe

`observe(msgs)` 把消息**加入上下文但不触发推理**——适合在多轮对话中手动塞入历史或系统上下文。

```python
# 把一条历史消息注入上下文（不触发推理）
agent.observe([UserMsg(name="user", content="我偏好简洁的中文回答。")])
# 之后再 reply，智能体会"记得"这条上下文
reply = await agent.reply(UserMsg(name="user", content="你好"))
```

## 关键 API 速查

| API | 说明 |
|-----|------|
| `UserMsg(name, content)` | 构造用户输入 |
| `await agent.reply(msg)` | 运行循环，返回最终消息 |
| `async for e in agent.reply_stream(msg)` | 流式事件循环 |
| `agent.observe([msgs])` | 注入上下文（不推理） |
| `EventType.TEXT_BLOCK_DELTA` 等 | 事件枚举 |

## 2.0 注意事项

- 消息类型是 `UserMsg`，**不要**再用 1.0 的 `Msg(name=, role=, content=)`。
- `reply` / `reply_stream` 必须 `await` 或 `async for`。
- 多轮上下文由 `Agent` 自动维护，无需手动拼 `history`（对比 LangChain 的 `MessagesPlaceholder`，见 [Langchain教程](../Langchain教程/14-记忆与多轮对话Memory.md)）。
