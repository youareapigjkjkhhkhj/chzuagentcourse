# 04 - 消息与消息类型

本篇目标：读懂 AutoGen 的消息体系。所有 Agent/团队的输入输出都是**消息对象**，理解它们才能正确解析 `TaskResult`、做日志与 UI 渲染。

## 4.1 前置准备

```bash
pip install -U "autogen-agentchat" "autogen-ext[openai]"
```

## 4.2 两大基类

AutoGen 消息分两类（来自 `autogen_agentchat.messages`）：

| 基类 | 含义 | 特点 |
|------|------|------|
| `BaseChatMessage` | **对话消息**：会进入模型上下文（如 `TextMessage`） | 持久、参与上下文 |
| `BaseAgentEvent` | **事件消息**：运行过程的可观测事件（如 `ToolCallRequestEvent`） | 用于流式展示/日志，通常不全部进上下文 |

`run_stream()` 产出的序列就是这两类消息的混合，**最后一项**是 `TaskResult`。

## 4.3 常用消息类型

| 类型 | 场景 | 关键字段 |
|------|------|----------|
| `TextMessage` | 用户任务 / Agent 文本回复 | `source`、`content`、`models_usage` |
| `MultiModalMessage` | 文本 + 图片 | `content=["问题", Image(...)]` |
| `ToolCallRequestEvent` | 模型请求调用工具 | `content=[FunctionCall(id, name, arguments)]` |
| `ToolCallExecutionEvent` | 工具执行结果 | `content=[FunctionExecutionResult(content, call_id, is_error)]` |
| `ToolCallSummaryMessage` | 工具结果后的自然语言总结 | `source`、`content` |
| `HandoffMessage` | 多智能体交接（Swarm） | `source`、`target`、`content` |
| `StopMessage` | 终止信号 | `content`、`source` |
| `MemoryQueryEvent` | 记忆检索结果 | `content=[MemoryContent(...)]` |

## 4.4 看一次完整的消息流

```python
import asyncio

from autogen_agentchat.agents import AssistantAgent
from autogen_ext.models.openai import OpenAIChatCompletionClient


async def web_search(query: str) -> str:
    """Find information on the web"""
    return "AutoGen is a programming framework for building multi-agent applications."


async def main() -> None:
    model_client = OpenAIChatCompletionClient(model="gpt-4.1-nano")
    agent = AssistantAgent(
        name="assistant",
        model_client=model_client,
        tools=[web_search],
        system_message="Use tools to solve tasks.",
    )
    result = await agent.run(task="Find information on AutoGen")
    for msg in result.messages:
        print(type(msg).__name__, "|", msg.source, "|", str(msg.content)[:80])
    await model_client.close()


asyncio.run(main())
```

输出结构：

```text
TextMessage              | user      | Find information on AutoGen
ToolCallRequestEvent     | assistant | [FunctionCall(id='call_703i...', arguments='{"query":"AutoGen"}', name='web_search')]
ToolCallExecutionEvent   | assistant | [FunctionExecutionResult(content='AutoGen is a programming...', name='web_search', call_id='call_703i...', is_error=False)]
ToolCallSummaryMessage   | assistant | AutoGen is a programming framework for building multi-agent applications.
```

## 4.5 在流式循环中区分消息与结果

```python
from autogen_agentchat.base import TaskResult

async for message in agent.run_stream(task="Find information on AutoGen"):
    if isinstance(message, TaskResult):
        print("Stop Reason:", message.stop_reason)
    else:
        print(type(message).__name__, message)
```

这是**官方推荐**的流式消费写法：末项是 `TaskResult`，其前都是消息/事件。

## 4.6 TaskResult

| 属性 | 说明 |
|------|------|
| `messages` | 本次运行产生的全部消息（含事件） |
| `stop_reason` | 停止原因字符串（如 `"Text 'APPROVE' mentioned"`） |

判断停止原因常用于：是否达成交接、是否被外部终止、是否触发了终止条件。

## 4.7 多模态消息

```python
from io import BytesIO

import PIL
import requests
from autogen_agentchat.messages import MultiModalMessage
from autogen_core import Image

pil_image = PIL.Image.open(BytesIO(requests.get("https://picsum.photos/300/200").content))
img = Image(pil_image)

message = MultiModalMessage(
    content=["Can you describe the content of this image?", img],
    source="user",
)

result = await agent.run(task=message)
```

## 4.8 交接消息（Swarm 专用）

```text
HandoffMessage(
    source='planner',
    models_usage=None,
    target='financial_analyst',
    content='Transferred to financial_analyst, adopting the role of financial_analyst immediately.',
    type='HandoffMessage'
)
```

`target` 决定**下一个发言者**；`target="user"` 表示交还人类（详见 [11-多智能体模式Swarm.md](11-多智能体模式Swarm.md)）。

## 关键 API 速查

| API | 说明 |
|-----|------|
| `autogen_agentchat.messages` | 全部消息类型所在模块 |
| `TaskResult.messages` / `.stop_reason` | 运行产物与停止原因 |
| `isinstance(message, TaskResult)` | 流式循环中识别终态 |
| `MultiModalMessage(content=[text, Image], source=)` | 图文混合输入 |

## 注意事项

- **不要**把 `BaseAgentEvent`（如工具调用事件）当成"对话历史"保存——它们主要用于过程观测。
- Agent 是有状态的：`run()` 会追加消息到内部上下文；需要全新开始时重建 Agent 或处理状态（见 [14-状态管理与序列化.md](14-状态管理与序列化.md)）。
- `models_usage` 记录 token 消耗，是做成本统计与 `TokenUsageTermination` 的基础。
