# 14 - 状态管理与序列化

本篇目标：理解 AutoGen 的"有状态"设计——如何延续对话、如何重置、如何把组件序列化成配置。

## 14.1 前置准备

```bash
pip install -U "autogen-agentchat" "autogen-ext[openai]"
```

## 14.2 有状态是默认行为

AgentChat 的设计约定（官方文档）：

> Agents are expected to be stateful and `run()` is expected to be called with **new messages, not complete history**.

即：

- `run(task=...)` 传入的是**增量消息**
- Agent/团队内部维护完整历史
- 终止条件在每次 `run()` 结束后**自动 reset**，所以可反复运行

## 14.3 延续对话（不重置）

```python
# 第一轮
await Console(team.run_stream(task="Write a short poem about the fall season."))

# 第二轮：直接带新任务继续（共享上文）
await Console(team.run_stream(task="将这首诗用中文唐诗风格写一遍。"))

# 不带 task：从上次中断处继续
await Console(team.run_stream())
```

`RoundRobinGroupChat` 会从**上次最后发言者的下一个**继续轮叫，历史上下文保留在成员 Agent 中。

## 14.4 重置 reset()

```python
await team.reset()   # 清空团队状态，并调用每个 Agent 的 on_reset()
```

- **不相关的新任务**：先 `reset()` 再运行。
- **相关的后续任务**：直接继续，不要 reset。

自定义 Agent 必须实现 `on_reset()`（见 [13-自定义Agent.md](13-自定义Agent.md)），否则状态会残留。

## 14.5 保存与加载状态

AgentChat 组件（Agent、Team、Memory、终止条件等）提供**状态保存/加载**能力，用于在进程间恢复会话。典型 API 形态：

```python
# 保存
state = await agent.save_state()      # 或 team.save_state()

# 恢复（在同一构造好的 agent/team 上）
await agent.load_state(state)
```

> 具体方法签名与可序列化范围以官方 **Managing State** 指南为准：
> <https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/tutorial/state.html>

实践建议：把 `state` 与 `session_id` 一起存入数据库/Redis，用户下次进入时 `load_state` 恢复上下文。

## 14.6 组件序列化（配置导出）

很多组件（如 `ChromaDBVectorMemory`、`Mem0Memory`）支持把**配置**导出为 JSON，便于保存和重建：

```python
config_json = chroma_user_memory.dump_component().model_dump_json()
print(config_json)
```

输出示例：

```json
{"provider":"autogen_ext.memory.chromadb.ChromaDBVectorMemory","component_type":"memory","version":1,
 "component_version":1,"description":"Store and retrieve memory using vector similarity search powered by ChromaDB.",
 "label":"ChromaDBVectorMemory","config":{"client_type":"persistent","collection_name":"preferences",
 "distance_metric":"cosine","k":2,"score_threshold":0.4,"allow_reset":false,"tenant":"default_tenant",
 "database":"default_database","persistence_path":"/Users/.../.chromadb_autogen"}}
```

官方序列化指南：<https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/serialize-components.html>

## 14.7 状态与记忆的区别

| 机制 | 存什么 | 生命周期 |
|------|--------|----------|
| Agent/Team 状态 | 对话历史、内部变量 | 会话级（可 save/load） |
| Memory（ListMemory/向量库） | 用户偏好、知识库 | 跨会话长期（持久化存储） |
| 终止条件状态 | 是否已触发 | 每次 run 结束自动 reset |

## 关键 API 速查

| API | 说明 |
|-----|------|
| `await team.reset()` | 清空团队与成员状态 |
| `team.run_stream()`（无 task） | 从中断处恢复 |
| `team.run_stream(task=新任务)` | 带上文继续 |
| `await agent.save_state()` / `load_state(state)` | 状态持久化（以官方指南为准） |
| `component.dump_component().model_dump_json()` | 导出组件配置 |

## 注意事项

- 状态保存在**进程内存**中，进程重启即丢失——需要持久化时用 save/load 或外部存储。
- 不要手动把历史消息拼进 `system_message`：框架已维护上下文。
- 团队与成员的状态是联动的：`team.reset()` 会调用每个成员的 `on_reset()`。
