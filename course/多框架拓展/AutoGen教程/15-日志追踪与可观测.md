# 15 - 日志追踪与可观测

本篇目标：把多智能体运行过程"看得见"——控制台流式输出、Python logging 记录内部消息、OpenTelemetry 分布式追踪。

## 15.1 前置准备

```bash
pip install -U "autogen-agentchat" "autogen-ext[openai]"
```

## 15.2 第一层：Console 流式输出（开发调试）

```python
from autogen_agentchat.ui import Console

await Console(team.run_stream(task="..."))
```

输出包含每个发言块（`---------- source ----------`）与结束摘要：

```text
---------- Summary ----------
Number of messages: 27
Finish reason: Text 'TERMINATE' mentioned
Total prompt tokens: 4130
Total completion tokens: 1102
Duration: 17.74 seconds
```

其中 `Finish reason` 即 `TaskResult.stop_reason`，`token` 统计来自各消息的 `models_usage`。

## 15.3 第二层：Python logging（记录内部消息）

AutoGen 使用标准库 `logging` 输出内部消息与追踪信息，可通过常规方式接入：

```python
import logging

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s - %(name)s - %(levelname)s - %(message)s",
)

# 只关心 AutoGen 相关日志，可单独设置 logger 级别
logging.getLogger("autogen").setLevel(logging.DEBUG)
```

实践建议：

| 场景 | 做法 |
|------|------|
| 只看对话结果 | `Console` 即可 |
| 排查模型调用/消息流转 | 开启 AutoGen logger 的 DEBUG |
| 生产环境 | 输出到文件/集中式日志（ELK、Loki），避免打印敏感内容 |

官方 Logging 指南：<https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/logging.html>

## 15.4 第三层：OpenTelemetry 追踪（生产可观测）

AutoGen 提供 **Tracing and Observability** 能力，可把 Agent 运行链路以 span 形式上报给 OpenTelemetry 兼容后端（Jaeger、Grafana Tempo、Langfuse、Application Insights 等）。

典型接入思路：

1. 安装 OTel SDK 与 exporter（如 `opentelemetry-sdk`、`opentelemetry-exporter-otlp`）。
2. 在应用启动时初始化 tracer provider，并指向 collector 端点。
3. AutoGen 的 tracing 集成会把 Agent/Tool/Model 调用自动织入 span。

> 具体的集成类名与环境变量以官方 **Tracing and Observability** 指南为准：
> <https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/tracing.html>

## 15.5 从消息流里提取指标

即使不接 OTel，也能从 `TaskResult` 直接统计：

```python
from autogen_agentchat.base import TaskResult

result: TaskResult = await team.run(task="...")

total_prompt = 0
total_completion = 0
for msg in result.messages:
    if getattr(msg, "models_usage", None):
        total_prompt += msg.models_usage.prompt_tokens
        total_completion += msg.models_usage.completion_tokens

print("messages:", len(result.messages))
print("stop_reason:", result.stop_reason)
print("tokens:", total_prompt, "/", total_completion)
```

结合 `TokenUsageTermination` 还能在超预算时自动停止（见 [10-终止条件Termination.md](10-终止条件Termination.md)）。

## 15.6 可观测清单

| 维度 | 数据来源 |
|------|----------|
| 谁说了什么 | `TaskResult.messages` / `Console` |
| 为什么停 | `TaskResult.stop_reason` |
| token 成本 | 各消息 `models_usage` |
| 工具调用 | `ToolCallRequestEvent` / `ToolCallExecutionEvent` |
| 记忆检索 | `MemoryQueryEvent` |
| 交接路径 | `HandoffMessage`（source → target） |
| 结构化链路 | OpenTelemetry tracing |

## 关键 API 速查

| API | 说明 |
|-----|------|
| `Console(run_stream(...))` | 格式化输出 + 摘要 |
| `TaskResult.messages` / `.stop_reason` | 事后分析 |
| `msg.models_usage` | token 统计 |
| `logging.getLogger(...)` | 控制日志级别 |
| `TokenUsageTermination` | 按 token 预算终止 |

## 注意事项

- 日志中可能包含用户输入与模型输出，生产环境注意脱敏与合规。
- token 统计依赖 Agent 上报 usage；自定义 Agent 需自行携带 `models_usage`。
- 追踪采样率与日志级别要按环境区分（开发 DEBUG / 生产 INFO）。
