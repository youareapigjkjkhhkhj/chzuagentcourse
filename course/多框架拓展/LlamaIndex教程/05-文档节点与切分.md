# 05 - 文档、节点与切分

本篇目标：理解 `Document` → `Node` 的转换过程，掌握文本切分（chunking）的关键参数与调优方向。

## 5.1 前置准备

```bash
pip install llama-index
```

## 5.2 Document 与 Node（官方定义）

| 概念 | 定义 |
|------|------|
| **Document** | 任意数据源的容器——一个 PDF、一次 API 输出、一次数据库查询结果 |
| **Node** | LlamaIndex 的**原子数据单位**，代表源 Document 的一个"块（chunk）"，带有关联文档与其他节点的元数据 |

简单说：**Document 是整体，Node 是被切分后的片段**。检索与生成的实际操作对象是 Node。

```python
from llama_index.core import Document
from llama_index.core.node_parser import SentenceSplitter
from llama_index.core.schema import TextNode

doc = Document(
    text="LlamaIndex 是面向自有数据的 LLM 应用框架。它负责接入、索引、检索与生成。",
    metadata={"author": "team", "source": "manual"},
)

splitter = SentenceSplitter(chunk_size=64, chunk_overlap=8)
nodes = splitter.get_nodes_from_documents([doc])

for node in nodes:
    print(type(node).__name__, "| id:", node.node_id[:8], "|", node.text[:40])
```

## 5.3 为什么要切分

- LLM 上下文窗口有限，不能把整库塞进去
- 检索粒度越小，相关性越精确；但过小会破坏语义完整
- 官方/社区共识：**切分质量直接决定检索质量**

| 切分问题 | 后果 |
|----------|------|
| 过度切分（over-chunking） | 破坏上下文，答案断章取义 |
| 切分不足（under-chunking） | 检索噪声大，长文本稀释相关性 |

## 5.4 SentenceSplitter（默认解析器）

```python
from llama_index.core.node_parser import SentenceSplitter

splitter = SentenceSplitter(
    chunk_size=1024,     # 每个 chunk 的目标大小（token 计）
    chunk_overlap=20,    # 相邻 chunk 的重叠，缓解切断语义
)
nodes = splitter.get_nodes_from_documents(documents)
```

| 参数 | 建议 |
|------|------|
| `chunk_size` | 中文/长文档常用 512–1024；短问答可 256–512 |
| `chunk_overlap` | 通常为 `chunk_size` 的 10%–20% |

## 5.5 全局配置切分参数

通过 `Settings` 一次性生效（见 [06-模型配置Settings.md](06-模型配置Settings.md)）：

```python
from llama_index.core import Settings

Settings.chunk_size = 512
Settings.chunk_overlap = 50
```

之后 `VectorStoreIndex.from_documents(docs)` 会自动使用这些参数。

## 5.6 其他解析器

| 解析器 | 用途 |
|--------|------|
| `SentenceSplitter` | 默认，按句子边界切分（推荐起点） |
| `TokenTextSplitter` | 纯 token 窗口切分 |
| `SentenceWindowNodeParser` | 每个节点带"句子窗口"上下文，检索用小窗口、生成时替换为大窗口 |
| `HierarchicalNodeParser` | 层次节点（父子结构），配合递归检索 |
| `MarkdownNodeParser` | 按 Markdown 标题结构切分 |
| `CodeSplitter` | 按代码语法切分 |
| `SemanticSplitterNodeParser` | 基于 embedding 相似度的语义切分（需 embedding 模型） |

```python
from llama_index.core.node_parser import MarkdownNodeParser

parser = MarkdownNodeParser()
nodes = parser.get_nodes_from_documents(documents)
```

## 5.7 元数据与关系

Node 会继承 Document 的 `metadata`，并带有：

| 字段 | 说明 |
|------|------|
| `node_id` | 节点唯一 ID |
| `text` | 节点文本 |
| `metadata` | 元数据（文件名、页码、自定义字段…） |
| `relationships` | 与其他节点/源文档的关系（PREVIOUS / NEXT / PARENT / SOURCE） |

元数据是**过滤与引用**的基础：

```python
node.metadata["file_name"]      # 来源文件名
node.metadata["page_label"]     # PDF 页码（PDF 解析时）
```

自定义元数据（在 Document 上设置，节点会继承）：

```python
doc = Document(text="...", metadata={"department": "finance", "year": 2025})
```

## 5.8 手工构造节点

需要完全控制粒度时，直接造 `TextNode`：

```python
from llama_index.core.schema import TextNode
from llama_index.core import VectorStoreIndex

nodes = [
    TextNode(text="第一节：产品定位", metadata={"chapter": 1}),
    TextNode(text="第二节：技术架构", metadata={"chapter": 2}),
]

index = VectorStoreIndex(nodes)
```

## 5.9 调优清单

| 症状 | 可能原因 | 调整方向 |
|------|----------|----------|
| 答案断章取义 | chunk 太小 | 增大 `chunk_size` |
| 检索总召回无关片段 | chunk 太大、噪声多 | 减小 `chunk_size` |
| 跨段语义丢失 | 无重叠 | 增大 `chunk_overlap` |
| 答案无法溯源到具体章节 | 元数据不足 | 补充 metadata / 用 MarkdownNodeParser 保留标题 |

## 关键 API 速查

| API | 说明 |
|-----|------|
| `Document(text=, metadata=)` | 构造文档 |
| `TextNode(text=, metadata=)` | 手工构造节点 |
| `SentenceSplitter(chunk_size=, chunk_overlap=)` | 默认切分器 |
| `splitter.get_nodes_from_documents(docs)` | 文档 → 节点 |
| `Settings.chunk_size` / `Settings.chunk_overlap` | 全局切分参数 |
| `node.node_id` / `node.metadata` / `node.relationships` | 节点关键字段 |

## 注意事项

- 更换切分策略意味着**必须重建索引**（embedding 与 chunk 一一对应）。
- 元数据要提前设计（部门、年份、文档类型…），否则后期无法按条件过滤。
- 层次/句子窗口类解析器要配合对应的检索器与后处理器使用才能发挥效果。
