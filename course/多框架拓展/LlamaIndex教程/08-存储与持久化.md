# 08 - 存储与持久化

本篇目标：把索引与元数据存下来（RAG 五阶段的 **Storing**），避免重复索引；并接入专业向量数据库。

## 8.1 前置准备

```bash
pip install llama-index
```

## 8.2 为什么要存储（官方定义）

> 一旦数据被索引，你几乎总是希望**存储索引以及其他元数据**，以避免重新索引。

重复索引的代价：重复的 embedding 费用 + 每次启动的等待时间。

## 8.3 默认持久化（本地磁盘）

```python
from llama_index.core import (
    VectorStoreIndex,
    SimpleDirectoryReader,
    StorageContext,
    load_index_from_storage,
)

PERSIST_DIR = "./storage"

# 第一次：构建并落盘
documents = SimpleDirectoryReader("data").load_data()
index = VectorStoreIndex.from_documents(documents)
index.storage_context.persist(persist_dir=PERSIST_DIR)

# 之后：直接加载（不再调用 embedding）
storage_context = StorageContext.from_defaults(persist_dir=PERSIST_DIR)
index = load_index_from_storage(storage_context)
print(index.as_query_engine().query("文档讲了什么？"))
```

落盘内容通常包括：

| 文件 | 内容 |
|------|------|
| `docstore.json` | 文档/节点文本与元数据 |
| `index_store.json` | 索引结构信息 |
| `vector_store.json` | 向量数据（默认 SimpleVectorStore） |
| `graph_store.json` | 图存储（若使用图索引） |

## 8.4 StorageContext

`StorageContext` 是存储组件的容器，可自定义各子存储：

```python
from llama_index.core import StorageContext
from llama_index.core.storage.docstore import SimpleDocumentStore
from llama_index.core.storage.index_store import SimpleIndexStore
from llama_index.core.vector_stores import SimpleVectorStore

storage_context = StorageContext.from_defaults(
    docstore=SimpleDocumentStore(),
    vector_store=SimpleVectorStore(),
    index_store=SimpleIndexStore(),
)
index = VectorStoreIndex.from_documents(documents, storage_context=storage_context)
```

## 8.5 接入向量数据库

换向量库只需两步：装包 + 构造 vector store 并传给 `StorageContext`。

```bash
pip install llama-index-vector-stores-chroma        # Chroma
pip install llama-index-vector-stores-qdrant        # Qdrant
pip install llama-index-vector-stores-postgres      # PostgreSQL + pgvector
pip install llama-index-vector-stores-faiss         # FAISS（本项目一/二/三用过）
```

示例（Chroma）：

```python
import chromadb
from llama_index.core import VectorStoreIndex, StorageContext
from llama_index.vector_stores.chroma import ChromaVectorStore

db = chromadb.PersistentClient(path="./chroma_db")
chroma_collection = db.get_or_create_collection("quickstart")

vector_store = ChromaVectorStore(chroma_collection=chroma_collection)
storage_context = StorageContext.from_defaults(vector_store=vector_store)

index = VectorStoreIndex.from_documents(documents, storage_context=storage_context)
```

示例（FAISS，轻量本地方案）：

```python
import faiss
from llama_index.core import StorageContext, VectorStoreIndex
from llama_index.vector_stores.faiss import FaissVectorStore

d = 1536                                  # 需与 embedding 维度一致
faiss_index = faiss.IndexFlatL2(d)

vector_store = FaissVectorStore(faiss_index=faiss_index)
storage_context = StorageContext.from_defaults(vector_store=vector_store)
index = VectorStoreIndex.from_documents(documents, storage_context=storage_context)
```

> FAISS 需自行持久化：`faiss.write_index(faiss_index, "faiss.index")`，加载用 `faiss.read_index(...)`。

### 从已有向量库加载索引

```python
index = VectorStoreIndex.from_vector_store(vector_store)
```

## 8.6 常见向量存储选型

| 方案 | 特点 | 适用 |
|------|------|------|
| `SimpleVectorStore`（默认） | 零依赖、内存/落盘 JSON | 演示、小规模 |
| FAISS | 本地高性能、无服务 | 单机、离线、中文项目常见 |
| Chroma | 轻量嵌入式/服务化 | 本地开发到小规模生产 |
| Qdrant | 过滤能力强、性能好 | 生产 |
| PostgreSQL + pgvector | 复用现有关系库、支持 SQL 混合 | 已有 PG 的团队 |
| Pinecone / Weaviate / Milvus | 托管或分布式、大规模 | 大规模生产 |

## 8.7 与 LlamaCloud 托管索引

若不想自建管线，LlamaCloud 提供端到端托管：连接数据源（Sharepoint / Google Drive / S3）与向量库，自动处理文档处理与同步（见 [17-评估与部署.md](17-评估与部署.md)）。

## 关键 API 速查

| API | 说明 |
|-----|------|
| `index.storage_context.persist(persist_dir=...)` | 持久化索引 |
| `StorageContext.from_defaults(persist_dir=...)` | 从磁盘构造存储上下文 |
| `load_index_from_storage(storage_context)` | 加载已有索引 |
| `StorageContext.from_defaults(vector_store=...)` | 指定向量库 |
| `VectorStoreIndex.from_vector_store(vs)` | 从向量库加载 |
| `faiss.write_index` / `read_index` | FAISS 自身持久化 |

## 注意事项

- 加载索引时不再需要重新 embedding，但**查询仍需要 LLM**。
- 换 embedding 模型 → 旧向量失效 → 必须重建索引。
- 生产环境不要把向量存在应用容器内部目录（重启丢失），应挂卷或使用外部数据库。
- 向量库的连接配置（URL、密钥）用环境变量管理。
