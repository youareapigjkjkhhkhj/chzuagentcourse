## 17.2 为什么评估（官方定义）

> A critical step in any flow is checking how effective it is relative to other strategies, or when you make changes. Evaluation provides **objective measures of how accurate, faithful and fast** your responses to queries are.

没有评估，调整 chunk_size、top_k、rerank 都只能"凭感觉"。

## 17.3 两类评估

| 类别 | 评估对象 | 指标 |
|------|----------|------|
| **检索评估** | Retriever 召回的节点 | MRR、命中率（Hit Rate）、NDCG |
| **响应评估** | 最终答案质量 | 忠实度（Faithfulness）、相关性（Relevancy）、正确性（Correctness） |

## 17.4 响应评估（LLM-as-judge）

```python
from llama_index.core.evaluation import (
    FaithfulnessEvaluator,
    RelevancyEvaluator,
    CorrectnessEvaluator,
)

faithfulness = FaithfulnessEvaluator(llm=Settings.llm)
relevancy = RelevancyEvaluator(llm=Settings.llm)
correctness = CorrectnessEvaluator(llm=Settings.llm)

query_engine = index.as_query_engine(similarity_top_k=5)

queries = [
    "2025 年 Q3 的定价策略是什么？",
    "文档提到哪些限制条件？",
]

for q in queries:
    response = query_engine.query(q)

    f = faithfulness.evaluate_response(response=response)
    r = relevancy.evaluate_response(query=q, response=response)

    print(f"Q: {q}")
    print(f"  faithfulness : {f.passing}  ({f.feedback[:80]})")
    print(f"  relevancy    : {r.passing}  ({r.feedback[:80]})")
```

| Evaluator | 问的问题 |
|-----------|----------|
| `FaithfulnessEvaluator` | 答案是否**只**来自检索到的上下文（有无幻觉） |
| `RelevancyEvaluator` | 答案与上下文是否**与问题相关** |
| `CorrectnessEvaluator` | 与**参考答案**相比是否正确（需提供 ground truth） |
| `GuidelineEvaluator` | 是否满足自定义准则（如"必须使用简体中文"） |
| `PairwiseComparisonEvaluator` | 两个答案哪个更好 |

## 17.5 检索评估

```python
from llama_index.core.evaluation import RetrieverEvaluator

retriever = index.as_retriever(similarity_top_k=5)
retriever_evaluator = RetrieverEvaluator.from_metric_names(
    ["mrr", "hit_rate"],
    retriever=retriever,
)

# expected_ids：人工标注的"应该召回"的节点 ID
result = retriever_evaluator.evaluate(
    query="Q3 定价策略",
    expected_ids=["node-id-1", "node-id-3"],
)
print(result.metric_vals_dict)
```

## 17.6 批量评估

```python
from llama_index.core.evaluation import BatchEvalRunner

runner = BatchEvalRunner(
    {"faithfulness": faithfulness, "relevancy": relevancy},
    workers=4,
)

results = await runner.aevaluate_queries(
    query_engine,
    queries=queries,
)
```

## 17.7 建立回归集

最佳实践：

1. 准备 **30–100 条**真实问题 + 参考答案/应召回节点
2. 每次调整（切分、top_k、rerank、提示词）后跑一遍
3. 记录指标变化，用数据决定改动是否保留

| 改动 | 关注指标 |
|------|----------|
| 调 chunk_size / overlap | 检索命中率、忠实度 |
| 加 rerank | 命中率、相关性 |
| 改提示词 | 忠实度、正确性 |
| 换 embedding | 命中率、MRR |

## 17.9 部署形态

| 形态 | 说明 | 适用 |
|------|------|------|
| **应用内嵌** | 把索引与查询引擎直接写进你的 Python/TS 服务 | 单体、内部工具 |
| **FastAPI 服务** | 用 API 包装 RAG（含流式） | 前后端分离 |
| **llama_deploy** | 官方项目：把 agentic workflows 部署为**生产微服务** | 多 agent、需要独立伸缩 |
| **Workflow 部署** | 官方 Workflows 文档提供部署指南 | 事件驱动长流程 |

FastAPI 包装示例：

```python
from fastapi import FastAPI
from fastapi.responses import StreamingResponse

app = FastAPI()


@app.post("/ask")
async def ask(question: str):
    async def gen():
        resp = query_engine.query(question)
        for chunk in str(resp):
            yield chunk

    return StreamingResponse(gen(), media_type="text/plain")
```

官方 Workflow 部署指南：<https://developers.llamaindex.ai/python/workflows/deployment/>

## 17.11 生产检查清单

| 项 | 建议 |
|----|------|
| 索引 | 持久化到外部向量库；换 embedding 必须重建 |
| 密钥 | 环境变量 / 密钥管理，绝不入库 |
| 成本 | 缓存解析与 embedding 结果；控制 top_k 与输出长度 |
| 延迟 | rerank 与多步查询会放大延迟，必要时异步化 |
| 质量 | 固定回归集 + 自动评估，改动前后对比 |
| 可观测 | 记录 query、召回节点、token、耗时，便于复盘 |
| 安全 | 元数据过滤做权限隔离；Text-to-SQL 用只读账号 |
| 可扩展 | 用 Workflow 编排确定性流程，Agent 负责开放式任务 |

## 关键 API 速查

| API | 说明 |
|-----|------|
| `FaithfulnessEvaluator / RelevancyEvaluator / CorrectnessEvaluator` | 响应评估 |
| `RetrieverEvaluator.from_metric_names(["mrr","hit_rate"])` | 检索评估 |
| `BatchEvalRunner({...}, workers=)` | 批量评估 |
| `LlamaParse(result_type="markdown")` | 云端解析 |
| `llama_deploy` | Workflow 微服务部署 |
| `npx create-llama@latest` | 项目脚手架 |

## 注意事项

- LLM-as-judge 本身有偏差，用于**相对比较**（A/B）比绝对评分更可靠。
- 检索评估需要人工标注"应该召回哪些节点"，成本较高但价值最大。
- 评估要用固定模型与固定数据，否则结果不可比。
- LlamaCloud 免费额度有限，生产用量需评估计费。
